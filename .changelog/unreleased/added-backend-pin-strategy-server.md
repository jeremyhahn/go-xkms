- **xkmsd resolves the PKCS#11 backend PIN under `backend_pin.strategy`.** At start-up the server resolves and persists the strategy (`auto`, `tpm2`, `sealed`). It refuses to start when the strategy cannot be met, falls below `backend_pin.minimum`, or does not match where the PIN is stored: `sealed` needs `credentials.seal_strategy: barrier`. `auto` selects `tpm2` whenever a TPM 2.0 is present; `tpm2` needs no `credentials.seal_strategy: tpm2`, as the server seals a PIN stored under the barrier to the TPM after unseal and fails closed if the TPM cannot seal it, and an `rng.pkcs11.pin` under the default `rng.mode` is held to the same policy. Under `sealed` the PKCS#11 backend starts after unseal with the released PIN. Shutdown zeroizes the held PIN, and `GET /api/v1/credentials/strategy` reports the strategy as `backend_pin_strategy` (#2262).
- **`backend_pin.strategy: manual` is not available yet.** `manual` (strategy, minimum or a persisted record) stops start-up with `ErrBackendPINManualUnavailable`. It stays refused until the unseal request can carry the backend PIN (#2262).
- **gRPC `GetCredentialStrategy` RPC.** gRPC clients read the credential strategy and `backend_pin_strategy`, as REST does; the gRPC transport no longer returns "not supported" for it (#2262).
- **A Raft transport key on the PKCS#11 token needs the `tpm2` backend PIN strategy.** With `cluster.raft_enrollment.key_backend: pkcs11`, `xkmsd` resolves the backend PIN strategy before the token opens; `sealed`, `auto` resolving to `sealed` and a weaker minimum stop start-up with `ErrBackendPINNodeKeyBeforeUnseal` before the token opens or a record is written (#2262).
