- **xkmsd resolves the PKCS#11 backend PIN under `backend_pin.strategy`.** At start-up the server resolves and persists the strategy (`auto`, `tpm2`, `sealed`, `manual`) and refuses to start when it cannot be met or falls below `backend_pin.minimum`. Under `sealed` the PKCS#11 backend starts after unseal with the released PIN; under `manual` the PIN comes from the unseal request, is held in memory only, and is zeroized at seal, when the backend stops. Shutdown zeroizes the held PIN, and `GET /api/v1/credentials/strategy` reports the strategy as `backend_pin_strategy` (#2262).
- **gRPC `GetCredentialStrategy` RPC.** gRPC clients read the credential strategy and `backend_pin_strategy`, as REST does; the gRPC transport no longer returns "not supported" for it (#2262).
