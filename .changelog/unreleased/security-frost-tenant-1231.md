- **High: FROST threshold keys are now scoped to the tenant that owns them (#1231).** Before this fix, the REST FROST routes (`pkg/api/rest/routes.go:174-182`), the gRPC `Frost*` RPCs and the MCP `frost.*` methods each called the FROST backend directly. They named a key by its ID alone and listed keys without a filter. Tests written against the old code showed the effect on all three transports. Tenant A could list every tenant's FROST keys, read tenant B's group public key, and delete B's key share. A could draw Round 1 nonces from B's share, produce a Round 2 signature share with it, and aggregate or verify against B's group key. A could also replace B's share by importing a package under B's key ID. Creating a key ID that another tenant already used failed with "already exists", which revealed that the key existed. All three transports are now thin adapters over new `XKMSService` methods in `pkg/xkms/servicer_frost.go`: `FrostGenerateKey`, `FrostImportKey`, `FrostListKeys`, `FrostGetKey`, `FrostDeleteKey`, `FrostGenerateNonces`, `FrostSignRound`, `FrostAggregate` and `FrostVerify`. These methods take the tenant from the authenticated identity, the same way the key lifecycle RPCs have since #1218. Each key is stored under a per-tenant storage key ID, `{tenant}:{keyID}` (`frost.StorageKeyID`). Its metadata records the tenant (`KeyMetadata.TenantID`), and `ListKeys` reports it. Because every lookup stays inside the caller's tenant, another tenant's key gets the bare `ErrKeyNotFound`. That answer is identical to the one for a missing key: REST `404`, gRPC `NotFound`, MCP `JSONRPCCodeNotFound`. A key ID now needs to be unique only within its tenant. Import writes only into the caller's tenant, through the new `FrostBackend.ImportKeyPackage`, and records the secret backend's real type instead of a hard-coded `software`. A platform-scoped caller, meaning one with no identity or in the system tenant, still lists every tenant's FROST keys, as `ListKeys` allows. A bare key ID from such a caller names only a platform key. Keys written before this change have no tenant and are treated as platform keys, so no tenant can see them. They are not migrated. Key IDs and tenants that contain `:`, `/` or `..` are now refused, both at the service and on the backend's round API. Wire changes: a missing key is `404`/`NotFound` on nonces, delete, aggregate and verify, where these used to return `500`/`Internal` (and verify used to return `200 {"valid": false}`). REST and MCP now refuse sign and aggregate requests without commitments or shares with `400`, as gRPC already did. `created_at` is the stored creation time, not the time of the request. A gRPC call made with no xkms service injected returns `Unavailable`. Describing a key no longer unseals its secret share.
