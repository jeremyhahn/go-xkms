- **xkey's FIDO2 touch notifier ran WebAuthn caller data through a shell, giving any web page that could call `navigator.credentials.create()`/`.get()` a path to arbitrary command execution, root command execution when `xkey fido2` ran under `sudo`.** `pkg/notify.CommandNotifier` substituted `%o`/`%r`/`%n`/`%u` (operation, RP ID, RP name, user name) directly into a command string and ran it with `sh -c`; `rp.name` and `user.name` come from any origin's WebAuthn call (`pkg/authenticator/cmd_makecredential.go`) and are replayed unchanged from stored credentials on every subsequent assertion (`cmd_getassertion.go`). Under `sudo`, the built-in `--notify dialog`/`--notify passive` paths (`cmd/xkey/cmd/fido2.go`) built a `su -c '...'` string the same way, so a quote in `user.name` was root command execution.
  - **Breaking**: `CommandNotifier` (`--notify-command`) no longer runs its template through a shell, and no longer substitutes request data into argv at all. `%o`/`%r`/`%n`/`%u` placeholders are retired: `NewCommandNotifier` now refuses a template containing any of them with a new typed error, `ErrTemplatePlaceholder`, so an old config fails loudly at startup instead of silently changing behaviour. The template is still split into argv once, at construction (`pkg/notify.splitCommandTemplate`, shell-like whitespace/quote rules), and that argv runs exactly as given, unmodified, via `exec.Command` — never through a shell. Request data reaches the command through exactly one channel: the `XKEY_OPERATION`/`XKEY_RP_ID`/`XKEY_RP_NAME`/`XKEY_USER_NAME` environment variables, for example `sh -c 'notify-send "Touch required" "$XKEY_RP_ID"'` — a shell expands a double-quoted variable without re-parsing its value as code.
  - An earlier version of this fix kept `%o`/`%r`/`%n`/`%u` argv substitution and tried to protect only a shell's `-c` script argument by name-matching known interpreters (`sh`, `bash`, ...). Review found that denylist incomplete and unfixable by extension: clustered shell flags (`sh -ec`), wrapper commands (`env`, `nice`, `nohup`, `sudo`, `doas`, `runuser -- `), other language interpreters (`python3 -c`, `perl -e`, `node -e`, `pwsh -Command`), and flag injection into a command with no interpreter at all (`notify-send` given a `UserName` of `--app-name=x`) all bypass a name-based denylist. Removing argv substitution entirely, rather than trying to enumerate every way to reach it, closes the whole class.
  - The `--notify dialog`/`--notify passive` sudo paths no longer build a `su -c` string at all. `cmd/xkey/cmd/fido2_sudo_notify.go` adds `sudoDialogNotifier`/`sudoPassiveNotifier`, which run `runuser -u <user> -- env ... zenity ...`/`notify-send ...` directly, with every caller-controlled value in its own fixed argv element (`--text=<value>`); the dialog's approve-then-touch sequencing (previously a shell `&&`) is ordinary Go control flow: run zenity, check its exit status, then run `xkey touch --socket ...` only on approval. `--no-markup` on zenity stops Pango markup injection, and `--` before notify-send's summary/body stops a value starting with `-` from being parsed as a flag.
  - An invalid `notify_command` (placeholders, empty, unterminated quote) now stops `xkey fido2` at startup with `ErrFIDO2InvalidNotifyCommand`. Previously `createNotifier` logged a warning and ran with no touch notifications at all.
  - Caller-controlled display fields (operation, RP ID, RP name, user name) are additionally run through `notify.SanitizeTouchRequest`, which strips control characters and bounds each field to 256 runes before it reaches any notifier or the environment — presentation hygiene, not the injection fix itself.
  - Files: `pkg/notify/command.go`, `pkg/notify/sanitize.go` (new), `pkg/notify/errors.go`, `pkg/notify/notifier.go`, `cmd/xkey/cmd/fido2.go`, `cmd/xkey/cmd/fido2_sudo_notify.go` (new), plus documentation: `docs/fido2/README.md`, `docs/password/cli.md`, `docs/virtual-authenticator/cli.md`, `skills/xkey-agent/reference/cli.md` (regenerated via `make skill-reference`).
  - Verified by `pkg/notify/command_test.go` and `cmd/xkey/cmd/fido2_sudo_notify_test.go`: a template containing `%o`/`%r`/`%n`/`%u` is refused; argv is exactly the operator's split template, unmodified, regardless of request content; hostile `rp.name`/`user.name` values (`'`, `"`, `;`, `$(id)`, backticks, a leading `-`, `--help`) reach the command only via environment variables, verbatim; template splitting and its quoting/escaping rules; and the sudo dialog's approve-runs-touch / deny-skips-touch sequencing and hostile-value argv construction via a fake `runuser` on `PATH`. `go vet` and `gofmt` clean under `codec_json tpm_simulator ble`.
