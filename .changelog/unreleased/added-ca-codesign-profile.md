- **Constrained `code-signing` CA profile** -- issuance under `code-signing` now validates the CSR instead of reshaping the template. The CSR must have a CN-only subject, no subject alternative names, and no requested CA basic constraints. It may request only digitalSignature and codeSigning, and its lifetime must stay within the 460-day maximum (365-day default). Each violation is refused with its own typed error (`ErrSubjectNotCommonNameOnly`, `ErrSubjectAltNameNotPermitted`, `ErrCARequestNotPermitted`, `ErrKeyUsageNotPermitted`, `ErrExtKeyUsageNotPermitted`, `ErrValidityExceedsProfile`); no field is stripped or clamped. A profile opts in through the new optional `CSRValidator` contract. Files: `pkg/ca/profile_codesigning.go`, `profile_contracts.go`, `ca.go`.
- **`SignOptions.BoundKey` binds a signed CSR to a keystore key** -- the CA resolves the named key in its keystore and refuses the CSR unless the CSR's public key is that key's (marshalled SPKI). An unknown key returns `ErrBoundKeyNotFound` and a different key returns `ErrBoundKeyMismatch`. The SDK re-exports the profile name, `CSRValidator` and the errors as `ProfileNameCodeSigning`, `CSRValidator` and `ErrCA*`. Files: `pkg/ca/types.go`, `ca.go`, `sdk/go/ca.go`.
