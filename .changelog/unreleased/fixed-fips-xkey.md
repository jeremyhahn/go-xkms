- **The xkey module reports the stdlib's refusals under `GODEBUG=fips140=only`.** The OATH SHA-1 and short-key gate keys on `crypto/fips140.Enforced`, the flag `crypto/hmac` checks, so SHA-1 HOTP/TOTP still work under `fips140=on`. The browser-extension handshake (`NewSessionCrypto`) and the phone TCP pairing server (`NewTCPPairingServer`) now wrap the stdlib's X25519 refusal instead of dropping it. Tests that run X25519 (Noise in `xkey/pkg/phone`, `pairing`, `attestation`, `attesttest`, `e2eprobe`; nativemsg; the sshechod curve25519 key exchange; the `xkey device relay` command tests) assert the refusal under `fips140=only` and the round trip outside it. The `xkey/cmd/xkey/cmd` device-resolution and OATH multi-backend tests no longer run X25519 or SHA-1 incidentally. The GUI phone service joins its pairing and connect errors with the cause, so the Noise refusal reaches the caller, and `ParseCertificate` leaves the SHA-1 and MD5 fingerprints empty under `fips140=only`. The `xkey/pkg/gui` and `xkey/pkg/gui/services` tests assert the Noise, NSS database and native-messaging refusals, echo `GCMNonceMode` over the PKCS#11 IPC round trip, expect the FIPS-aware password-backup KDF and seed OATH with HMAC-SHA-256.
