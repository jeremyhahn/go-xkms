- **An ECDSA IAK or IDevID enrolling with the TCG-CSR-IDEVID wire format packed a TPM2_Certify signature no server-side verifier -- including this package's own -- could parse.** `CreateIAK` and `CreateIDevID` (`pkg/tpm2/key.go`) took the TPM's raw `SignatureR`/`SignatureS` and ran `asn1.Marshal(struct{R,S *big.Int}{r,s})` into `TPMAttributes.Signature`, the field a TCG-CSR-IDEVID carries straight through into `atCertifyInfoSignature`/`sgnCertifyInfoSignature`. TCG "TPM 2.0 Keys for Device Identity and Attestation" v1.00 r12 section 13.1 defines both as the bare signature value with no algorithm alongside it, and `VerifyCertifyRaw`'s `signatureFromScheme` (`pkg/tpm2/certify_verify.go`) recovers r and s by splitting the buffer exactly in half -- ASN.1 DER is not that shape, and an RSA IAK never exercised this path, so the only existing ECDSA test verified a CSR against its own producer and never caught the mismatch. A CA verifying an ECDSA device's enrollment failed every time; an RSA IAK or IDevID was unaffected. Both branches now build the raw `r||s` pair through a new shared helper, `packRawECDSASignature` (`pkg/tpm2/eccpub.go`), which left-pads each component to the attesting key's curve field size -- 32 bytes for P-256, 48 for P-384, 66 for P-521 -- exactly as `signatureFromScheme` expects. No other consumer of `TPMAttributes.Signature` (`pkg/tpm2/idevid_csr.go`, `pkg/acme/client/tpm.go`) or of the packed CSR fields (`pkg/ca/tcg.go`, `pkg/attestation/invariants.go`) parsed the signature itself -- each already treats it as an opaque byte string -- so none needed a change. `CertifyKey`'s general-purpose attestation result (`pkg/tpm2/attestation.go`) and the CSR's own outer signature (`SignValidate`, verified with `ecdsa.VerifyASN1`) are unrelated APIs that correctly remain ASN.1 DER. Verified by `pkg/tpm2/certify_ecdsa_wire_format_simulator_test.go`, which builds a real ECDSA P-256 IAK and IDevID against the TPM simulator, asserts each packed signature is exactly 64 bytes, and asserts a DER-encoded signature is rejected. go-xkms#1182.
