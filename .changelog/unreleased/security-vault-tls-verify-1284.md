- **The HashiCorp Vault backend's `tls_skip_verify` option, which disabled TLS server certificate verification, is removed — BREAKING.** `pkg/backend/vault.Backend`'s `NewBackend` (via `pkg/xkms/register_vault.go`'s `tls_skip_verify` config key) built a `vault.TLSConfig{Insecure: true}` whenever the option was set, which skips verifying the Vault server's certificate entirely and leaves the connection open to a MITM despite looking like TLS. There is no legitimate configuration this option served that a CA is not the correct fix for. `vault.Config` gains `TLSCAFile`, `TLSCAPath` (verify the server against a private or self-signed CA), and `TLSCertFile`/`TLSKeyFile` (mTLS to Vault), each wired straight into `vault.TLSConfig`'s `CACert`/`CAPath`/`ClientCert`/`ClientKey`; `Config.Validate` refuses a `TLSCertFile` set without its `TLSKeyFile` or vice versa. A deployment that set `tls_skip_verify: true` must point `tls_ca_file`/`tls_ca_path` at the Vault server's CA instead, or use `http://` for a genuinely TLS-less dev server — there is no in-band way to skip verification of an `https://` connection.
  - Extended `make check-insecure-tls` (now `scripts/check-insecure-tls.sh`, replacing the inline Makefile grep) to also catch a non-literal `InsecureSkipVerify:`/`.InsecureSkipVerify =` value (not just the literal `true`), `Insecure: true` anywhere under `pkg/backend/vault`, and `insecure.NewCredentials()` in production code without a trailing `// insecure-ok: ...` justification comment. The existing `InsecureSkipVerify` allowlist (`pkg/crypto/spki/spki.go`, `pkg/trust/fetcher/spki.go`, `pkg/trust/bootstrap/tofu_tls.go`) is unchanged. Every pre-existing production `insecure.NewCredentials()` call site now carries an inline justification: the two explicit-client-config transports (`pkg/api/transport/grpc/transport.go`, `pkg/acme/api/grpc/adapter.go`'s TCP branch), three Unix-domain-socket transports with no network path for a MITM (`pkg/api/transport/unix/transport.go`, `pkg/acme/api/grpc/adapter.go`'s Unix branch), two further explicit-client-config gRPC clients (`sdk/go/client/ssh/grpc.go`, `xkey/pkg/agent/client.go`), and GCP KMS's local-emulator-only path (`pkg/backend/gcpkms/gcpkms.go`, already gated by `Config.Validate` to a custom `Endpoint`). `_test.go` files are excluded from the `insecure.NewCredentials()` check, matching the existing gate's scope: bufconn and other in-memory test transports have no network path for a MITM and are pervasive in this tree's test suites.
