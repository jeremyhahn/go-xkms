- **xkey's browser launcher opened any URL scheme it was handed, including `javascript:`, `file:`, and OS-registered handler schemes (`ms-msdt:`, `search-ms:`)** (#1275). `pkg/gui/services/browser_service.go`, `secure_browser_service.go`, and `oidc_service.go`'s default `browserOpen`, plus the `xkey oidc login`/`oidc aws` CLI commands, all passed a URL straight to `xdg-open`/`open`/`rundll32 url.dll,FileProtocolHandler` or a configured browser binary with no scheme check and no guard against a leading `-` being parsed as a flag. The reachable, attacker-influenceable path was OIDC discovery: `pkg/oidc/provider.go`'s `Discover` only checked that `authorization_endpoint` was non-empty, so a compromised or spoofed IdP's discovery document could point it at a dangerous scheme or an insecure host and have it opened in the user's browser.
  - New `pkg/urlsafety` package is the single validator every launch site now runs through: `ValidateLaunchURL` requires the scheme to be `http` or `https`, requires a non-empty host, and rejects a leading `-` and ASCII control characters, returning the parsed, normalized URL to pass to the launcher instead of the raw string. Plain `http` is allowed at this layer — the browser owns the decision to warn about a lack of transport security, and disallowing it would break an operator deliberately opening an internal, unencrypted URL.
  - `pkg/oidc/provider.go`'s `Discover` now requires every endpoint the discovery document supplies (`authorization_endpoint`, `token_endpoint`, `jwks_uri`, `userinfo_endpoint`, `registration_endpoint`, `revocation_endpoint`, `introspection_endpoint`, `end_session_endpoint`) to be `https`, with an exception for the loopback interface (127.0.0.1, ::1, `localhost`) that development IdPs commonly run on, using the new `urlsafety.IsLoopbackHost`.
  - `BrowserService.OpenURL`, `SecureBrowserService.LaunchBrowserWithOptions`, and `OIDCService`'s default `browserOpen` (wrapping `github.com/pkg/browser.OpenURL`) now validate before launching; the `xkey oidc`/`oidc aws` CLI commands route their `browser.OpenURL` calls through a single new `openLaunchURL` helper that does the same. `SecureBrowserService`'s Chrome and Firefox argv now also place the URL after a `--` end-of-switches separator, a second, browser-native guard against argument injection.
  - Files: `pkg/urlsafety/{urlsafety,errors}.go` (new), `pkg/oidc/{provider,errors}.go`, `pkg/gui/services/{browser_service,browser_errors,secure_browser_service,secure_browser_errors,oidc_service,errors}.go`, `cmd/xkey/cmd/{oidc,oidc_aws}.go`.
  - Verified by `pkg/urlsafety`'s table-driven tests (dangerous schemes, leading `-`, control characters, missing host, loopback detection); `pkg/oidc/provider_test.go`'s new discovery-endpoint-scheme cases; `browser_service_test.go`'s and `secure_browser_service_test.go`'s new cases proving a rejected URL never reaches `execCommand`; `oidc_service_test.go`'s and `oidc_test.go`'s new cases for the wrapped `browserOpen`/`openLaunchURL`. `go vet` and `gofmt` clean under `codec_json tpm_simulator ble`.
  - Fixes #1275.
