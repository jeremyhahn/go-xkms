- **The PKCS#11 module signs and verifies CKM_ECDSA input of any length.** PKCS#11 v3.2 §6.3.12 (Table 70) takes the raw digest at any length and truncates it to the curve order, but the service signs only a SHA-2 length digest, so `pkcs11-tool --sign -m ECDSA` over a file failed C_Sign and then C_SignFinal with CKR_ARGUMENTS_BAD. The module now truncates the input to the field width and left-pads it with zeros to the longest SHA-2 length the curve holds, which leaves the signed integer unchanged, and answers CKR_DATA_LEN_RANGE for input no such length can carry. C_Verify sends its input unchanged, because the service's verifier truncates it as SEC 1 v2 §4.1.4 requires, so a valid signature over a raw digest no SHA-2 length carries, such as a 66-byte one on P-521, still verifies (DS-3754).
