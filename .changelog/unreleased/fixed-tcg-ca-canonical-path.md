- **TCG CA calls use one canonical path on every transport.** The server serves the TCG CA at `POST /api/v1/ca/tcg/{ek,ak,sign-csr,enroll}`, and the REST and QUIC transports call it there, but the Unix transport posted to a nonexistent `/api/v1/tcg-ca/{issue-ek-cert,issue-ak-cert,sign-tcg-csr,enroll-device}`, so EK/AK issuance, TCG CSR signing and device enrollment over the Unix socket always failed. The MCP transport's path-to-tool table carried the same stale spelling. Both now use `/api/v1/ca/tcg/*`, and the stale spelling is gone from the tree.
