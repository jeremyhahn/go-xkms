- **`xkmsctl frost` sealed each secret share under a wrapping key it stored as plaintext PKCS#8 beside the shares** (#1324). The CLI's local store claimed its shares were not kept in the clear (#841), but the Ed25519 key the shares were sealed under came from a software backend built with `AllowPlaintextKeys: true` and attributes that set no password. So it sat unencrypted in `<key-dir>/frost/secrets`, next to the sealed shares in `<key-dir>/frost/public`, and both directories were created `0755`. Anyone who could read the key directory could unseal every share. The wrapping key is now encrypted PKCS#8 (PBES2) under an operator passphrase, and the store's directories are owner-only.
  - **Breaking**: the verbs that seal or unseal a share (`frost keygen` in participant mode, `frost import`, `frost round1`, `frost round2`) now require a FROST passphrase from `--passphrase-stdin`, `--passphrase-file` or `XKMS_FROST_PASSPHRASE`. No flag accepts it as a value. With no passphrase they refuse with `ErrFrostPassphraseRequired`. A wrong passphrase is `ErrFrostPassphraseRejected`, and so is a key directory written by an earlier build, whose wrapping key is plaintext: re-import the key package into a fresh `--key-dir`. `--backend` values other than `software` are refused for `xkmsctl frost` with `ErrFrostWrapBackendUnsupported`. xkmsctl builds no local TPM 2.0 or PKCS#11 key backend, so it cannot hold the wrapping key in hardware; `xkmsd`'s `backends.frost.secret_backend` remains the hardware path. `list`, `info`, `delete`, `aggregate` and `verify` touch only public material and need no passphrase. `info` now reads the public key package instead of unsealing the share.
  - The wrapping key lives in a PKCS#8 backend with `AllowPlaintextKeys` false, so an unencrypted write is refused by the backend as well. Every CLI share verb opens the store through one path (`openFrostShareBackend`), `import` included: it now stores through `FrostBackend.ImportKeyPackage` rather than a second hand-built `KeyStore`. `<key-dir>` (when absent), `<key-dir>/frost`, `frost/public` and `frost/secrets` are created `0700`, and the three FROST directories are re-moded to `0700` if they already exist. The SDK re-exports `ErrPKCS8KeyDecodingFailed` so the CLI can tell a rejected passphrase from other provisioning failures.

It covers a passphrase round trip that reopens the store and unseals, and parses the stored wrapping key as a PBES2 `EncryptedPrivateKeyInfo`, not plaintext PKCS#8. It checks that a wrong passphrase and a pre-#1324 plaintext key are both refused, that no passphrase is refused before any directory is created, and that `--backend tpm2` is refused. It also checks `0700` directory modes, including tightening existing `0755` ones, that the public backend cannot unseal, and the passphrase source precedence and error cases. `go vet` and `go test` are clean for `./cmd/xkmsctl/` and `./pkg/keyprovider/frost/...` under `codec_cbor codec_json codec_msgpack tpm_simulator frost`.
