- **xkmsd refuses TLS without `tls.client_auth` when the auth chain accepts mTLS** — `xkmsd init` provisions an mTLS administrator, but with `tls.client_auth` none or unset the handshake never asked for that certificate and the admin surface refused the administrator. `Config.Validate` now refuses `tls.enabled` with `tls.client_auth` none or unset whenever the auth chain accepts mTLS (type `mtls`, the `mtls` flag, or a composite with `mtls` or the default methods; `AuthConfig.usesMTLS`), with an error naming `tls.client_auth`; a config that loaded before is now refused until it sets `verify`, `request` or `require_and_verify`. The shipped `configs/xkmsd.yaml` (and the dev, local, example and integration configs) set `client_auth: verify`, so browsers and ACME clients without a certificate still connect. Pinned by `pkg/config/client_auth_mtls_admin_test.go` (#2254).
