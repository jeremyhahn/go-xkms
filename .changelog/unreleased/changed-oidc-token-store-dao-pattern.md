- **OIDC token persistence moved onto go-qrdb's DAO/entity pattern** -- `pkg/oidc.BackendTokenStore` (a raw `storage.Backend` `Put`/`Get` pair) is deleted; `pkg/oidc.DAOStore` (`NewDAOStore(kv qrdbsdk.KVStore)`) replaces it with the same `TokenStore` behavior (`Save`/`Load`/`Delete`/`List`/`Close`, the same `ErrTokenNotFound`/`ErrInvalidIssuer`/`ErrStoreClosed` sentinels) over a go-qrdb DAO keyed by normalized issuer. `pkg/oidc.DatabaseName` ("oidc") names the go-qrdb database the DAO declares itself into. `pkg/datastore` gains `DatabaseKVStore`/`ClientBackend`, the one way a composition root resolves a feature's own named go-qrdb database (created on demand via go-qrdb's `Client.Database()`, scoped via `Client.DatabaseScoped`, with a per-database backend override through the new `datastore.databases:` config list) -- see docs/datastore/architecture.md's "Feature-owned databases". xkey, which hosts no go-qrdb node, reaches the same DAO through `sdk/go.NewKVStoreAdapter` over its existing barrier-backed backend (`xkey/pkg/gui/services/oidc_service.go`'s `SetBackend`); its default storage engine stays `file`. `sdk/go/oidc` re-exports `DAOStore`/`NewDAOStore`/`DatabaseName` in place of `NewBackendTokenStore`.
