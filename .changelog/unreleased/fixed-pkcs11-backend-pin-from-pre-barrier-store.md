- **The `pkcs11` backend can log in without a PIN in the config.** With `backends.pkcs11.pin` unset, xkmsd now releases the token PIN that `xkmsd seal-pkcs11-pin` sealed into the TPM-backed pre-barrier store, the same PIN the PKCS#11 node seal uses. A configured PIN is used as before. If no PIN is sealed, the token login is refused as before. Any other release failure stops the start with its typed error. The backend now initializes before the `tpm2` backend, so the release never opens a second TPM connection. The API integration suite gets its `pkcs11` backend back, using a sealed PIN.
