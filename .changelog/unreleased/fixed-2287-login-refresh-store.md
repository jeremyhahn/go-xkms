- **Auth: PIV and WebAuthn login no longer answer 500 on a qrdb-backed xkmsd** — login routes are public, so their request context carries no identity, and the refresh-token store wrote the go-qrdb KV with it; an authenticating embedded node refused the write ("refresh store put failed: qrdb/auth: unauthenticated"). The refresh store's own bookkeeping (save, get, rotate, revoke) now runs as the node's service principal through `Node.ServiceContext`, on both the xkmsd server path and the apimodule host path (`WithServiceContext`). The service principal's grant is unchanged. A failed mint on the PIV and WebAuthn login paths is now logged at debug level with the error and the user and tenant only. The refresh user re-check under the anonymous context is tracked in #2292 (#2287).
