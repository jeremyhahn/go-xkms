- **The attestation record names `.` and `..` are refused.** `ValidateName` accepted them, but a client puts the name in a URL path segment and URL normalization resolves dot segments away: the TypeScript client's `deleteEndorsement('..')` became `DELETE /api/v1/attestation/`, which failed and left the trust anchor trusted, and the reference-values GET and DELETE had the same gap. The server now rejects both names with a `*NameError` when a record is stored, and the TypeScript client's `deleteEndorsement`, `getReferenceValues` and `deleteReferenceValues` reject them with `AttestationNameError` before any request (go-xkms#1608).
