- **Attacker-directed fetches and parsers now run under bounds (go-xkms#1175).**
  - The xkey agent server's connected-agent table can no longer be grown by a peer that keeps reconnecting. Entries are keyed on the authenticated agent ID where mTLS provides one, and on the connection otherwise. An entry is removed when its last connection closes. The table is capped at 1024 entries, and idle entries are evicted when it is full.
  - `ImportIssuingCAs` and `ImportDistributionCRLs` fetch only http and https URLs that resolve to public addresses. The check runs at dial time, after DNS resolution and on every redirect, so loopback, private, link-local and cloud-metadata addresses are unreachable. A certificate response is capped at 64 KiB and a CRL at 32 MiB. The CRL fetch, which had no timeout, now shares the AIA client's 30-second limit. The AIA walk also verifies that each fetched issuer signed the certificate that named it, stops on a repeated certificate, and refuses a chain more than five issuers deep. The new errors are `ErrPKIFetchRefused`, `ErrPKIFetchTooLarge`, `ErrAIAIssuerSignatureInvalid`, `ErrAIALoop` and `ErrAIADepthExceeded`.
  - The CA's AIA/CRL address filter and the ACME challenge-validation client's target filter (go-xkms#1172) were two independent implementations of the same SSRF guard. They're now one, `pkg/netguard`: the reserved-address classification (`netguard.ReservedAddr`), the guarded dialer (`netguard.DialControl`, `netguard.GuardedTransport` — no proxy, the `Control` hook checked after DNS resolution and on every redirect hop), and the size-capped body read (`netguard.ReadLimited`) that both clients build on. The merge is the stricter union of what each side refused: the CA's fetch client, which previously refused only loopback, RFC 1918/4193 private, link-local and CGNAT addresses, now also refuses the TEST-NETs, the IETF protocol-assignment and benchmarking ranges, NAT64, 6to4, documentation ranges and deprecated site-local addresses — the same set `policy.IsReservedIP` (now a thin delegate to `netguard.ReservedAddr`) already refused for ACME targets. No caller lost a refusal it depended on. Redirect policy, per-call size limits and the `AllowPrivateTargets` opt-in stay with each caller.
  - `tpm2.DecodePCRs`, which decodes the gob-encoded PCR banks inside attestation evidence, refuses input over 64 KiB before decoding. It also refuses banks that no TPM reports (`ErrPCRDataTooLarge`, `ErrInvalidPCRData`). This covers the ACME compliance hooks and xkey pairing.
  - The OIDC authenticator refuses a discovery, JWKS or userinfo response over 1 MiB (`ErrOIDCResponseTooLarge`).
  - `FileBackupAdapter` refuses a backup ID that is not a UUID before it becomes a file path (`ErrInvalidBackupID`). It also skips metadata records with such IDs when it loads its index.
