- **Removed the enroll-01 challenge type's dead per-client port parsing** (#1183). `pkg/acme/server/handlers/challenge.go` could parse a port suffix out of a challenge type (`"enroll-01-8880"`), but nothing on the offering side (`createChallenges`, `new_order.go`) ever produced one — every enroll-01/endorse-01/device-attest-01 challenge this server offers is the bare registered type string, which always validates against the type's fixed default port (8080 for the enrollment family, 80 for http-01). The parser made the port-suffixed form look supported when it never routed a challenge anywhere; two devices behind one NAT, or two concurrent enrollments on one host, could never both be served, and the earlier investigation into this exact symptom (documented in `CHANGELOG.md`'s `TestEnrollment_ConcurrentRequests`/`TestEnroll01_CompleteWorkflow` entry) had already established the protocol does not let a client choose its callback port. Actually offering a client-chosen port is a protocol change and needs an explicit design decision; this change only removes the parsing that falsely implied it already worked.
  - `parseChallengeAsDynamicPortAssignment` is deleted. `ChallengeHandler` now looks up the verifier and selects the default port directly from the exact, unsuffixed challenge type. `isEnrollXChallenge` and `IsEndorseChallengeType` (`endorse_eab.go`) now match the literal challenge type instead of stripping a port suffix that is never present.
  - Files: `pkg/acme/server/handlers/challenge.go`, `pkg/acme/server/handlers/endorse_eab.go`, and their test files (dead port-suffix-parsing tests removed; a handful of tests that used a port-suffixed challenge *type string* as an arbitrary unique map key, without testing port parsing, are unaffected).
  - Verified by the existing `pkg/acme/server/handlers` suite (`go test -race` clean) and `golangci-lint run` clean.
