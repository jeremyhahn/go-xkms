- **The ACME `http-01` and `dns-01` circuit breakers were global, so one account's always-failing validation target could stall validation for every other account** (#1189, #1190). `WrapChallengeVerifiers` wrapped each challenge type with a single breaker shared by every account (`http01`, `dns01`); an account naming a target that never responded, or a `dns-01` zone whose authoritative name server was slow, tripped that one breaker and made `ErrCircuitOpen` fail every other account's validation of the same challenge type, healthy targets included.
  - `circuitbreaker.Manager` now supports **per-target breaker groups** (`pkg/acme/server/circuitbreaker/target.go`, `Manager.TargetBreaker`/`RegisterTargetGroup`/`TargetGroupStatuses`): one breaker per validation target — the domain http-01 dials, or the zone dns-01 queries (the only attribution the verifier's signature actually gives the wrapper; there is no visibility into which authoritative name server `net.Resolver.LookupTXT` contacted) — created lazily and looked up by `circuitbreaker.WrapChallengeVerifierPerTarget`, which `WrapChallengeVerifiers` (`pkg/acme/server/resilience.go`) now uses in place of the single-breaker `WrapChallengeVerifier` for `http-01`/`dns-01`. A failing or slow target now only ever affects its own breaker.
  - Each group's table is bounded: an LRU-ordered `container/list` under one mutex evicts the least recently used target once the group's capacity is exceeded, and independently evicts a target idle past its TTL (the same list order serves both, since the least recently used entry is also the longest idle). New `ACMECircuitBreakerConfig` fields `target_capacity` / `target_idle_timeout_seconds` (on the `http01`/`dns01` resilience sections; meaningless elsewhere) configure the bound, defaulting to 1000 targets / 10 minutes idle (`DefaultACMEBreakerTargetCapacity`, `DefaultACMEBreakerTargetIdleTimeoutSeconds`). A refused target (invalid or reserved address) still does not count toward its breaker, per #1181.
  - `GET /acme/health`'s `HealthStatus` gains `target_groups`, a bounded per-group summary (`capacity`, `tracked`, `closed`, `half_open`, `open`, and up to 10 `top_open` target names) alongside the existing named-breaker `breakers` map; `healthy` is unaffected by `target_groups`, since one account's failing target is now expected, isolated behavior rather than a server-wide health signal.
