- **xkey SSH is server-backed when connected and local when offline, CLI and GUI.** The same switch `xkey oidc` makes:
  - CLI: a configured xkmsd (the full `resolveXKMSdEndpoint` chain, any scheme; previously only `XKMSD_URL`/`xkmsd_url`, always as REST) makes every `xkey ssh` command server-backed unless `--local` is given (new flag). Server calls present `XKMSD_TOKEN` or the stored login, the CA bundle and the `XKMSD_TLS_CERT`/`XKMSD_TLS_KEY` client credential.
  - GUI: `SSHService.SetServerClient` replaces the never-wired `SetRemoteClientFunc`. While a server is connected the SSH key view runs on it (an explicitly chosen local backend is refused with `SSHLocalBackendConnectedError`); a server whose SSH API cannot be dialed fails closed with `SSHServerUnavailableError` instead of quietly using local keys; on disconnect it returns to the local store. `ConnectionService.SSHClient` dials the connected server's SSH API with the connection's trust and login.
  - SDK: `client/ssh.NewClientForServerWith(server, ServerOptions{TLSConfig, Token})` takes a full `tls.Config` (client certificate, SPKI pin) and presents the token on every transport. gRPC (`GRPCOptions.TLSConfig`, `AuthToken`), gRPC over a Unix socket (local credentials) and MCP (`MCPOptions.AuthToken`) carried no token before. `NewClientForServer` delegates to it.
