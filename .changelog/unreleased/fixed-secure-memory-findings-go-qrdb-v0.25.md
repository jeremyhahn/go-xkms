- **Every go-qrdb v0.25 secure-memory finding is fixed at its site.** go-qrdb v0.25's vet tool added rule 4 (a `secure.Buffer.Bytes` read with no borrow held across it) and `securecopy` (a copy of protected bytes that is never wiped, returned or consumed, and any `string(...)` of protected bytes); v0.48.0-alpha shipped 118 such findings across the root module, `sdk/go` and xkey. Reads now go through `Buffer.WithBytes` or `secure.CopyOut` (go-qrdb `sdk/go/secure`), copies are wiped with `defer secure.Wipe` right after they are made, buffers are filled through `WithBytes` rather than through `Bytes()`, and the AES key-wrap paths in `pkg/crypto/wrapping` run each wrap under a single borrow of one register buffer. The remaining sites carry the analyzer's own per-site directive with the reason it holds: `//secure:unwiped` where an interface or wire format requires a string (`types.Password.String`, backup and CDP serialization, OIDC token accessors) or hands the value to its caller by contract (PKCS#11 `C_GetAttributeValue` of `CKA_VALUE`), and `//secure:unborrowed allocates-protected` where the callee allocates protected memory of its own and so cannot run inside a borrow. Behaviour is unchanged except that a destroyed `pkg/password` buffer now makes `String()` return `ErrPasswordZeroed`, and a failed PIN borrow in `pkg/fido2` returns `ErrPINTokenFailed` instead of hashing nothing.
