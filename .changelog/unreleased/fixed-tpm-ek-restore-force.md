- **`xkey tpm ek restore --force` replaces a stored EK certificate** -- restore always called `ProvisionEKCert`, whose `TPM2_NV_DefineSpace` fails with `TPM_RC_NV_DEFINED` when the EK certificate NV index already exists, so `--force` (which only skipped the public-key check) could never overwrite a stored certificate. `--force` now calls the new `ReplaceEKCert`, which replaces the certificate at the configured `EKConfig.CertHandle` index and no other: it checks the handle, the certificate's size and its DER first, so a rejected certificate leaves the stored one untouched (`ErrEKCertIndexInvalid`, `ErrNVCertEmpty`, `ErrNVCertTooLarge`, `ErrInvalidEKCertFormat`), then undefines the index and writes the new one, so a second run behaves like the first; the EK itself is never touched. Without `--force`, a stored certificate is refused with the typed `ErrEKCertExists` (`ErrTPMEKCertExists` in the SDK). `ProvisionEKCert` and `ReplaceEKCert` now write the certificate in chunks of at most `TPM_PT_NV_BUFFER_MAX` bytes, so a certificate larger than the NV buffer is no longer lost after the undefine; every chunk after the first authorizes over the index's written Name, so a multi-chunk write under a non-empty owner authorization no longer fails part-way. `ReplaceEKCert` undefines and redefines the index under the owner hierarchy, so it also works when no persistent EK exists, and refuses a platform-created index with `ErrEKCertPlatformIndex` (`ErrTPMEKCertPlatformIndex` in the SDK) before undefining anything. `xkey tpm ek restore --ec` now writes the ECC P-256 index (`0x01C0000A`) instead of the RSA 2048 one.
