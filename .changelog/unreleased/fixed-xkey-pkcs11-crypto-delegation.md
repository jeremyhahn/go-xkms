- **xkey's PKCS#11 encrypt, encrypt-asym and decrypt now honour every request field, and every IPC operation honours its caller's context** -- `EmbeddedTransport.Encrypt`/`EncryptAsym`/`Decrypt` were local re-implementations that dropped the AES mode, IV, additional data and tag size, ignored the OAEP label, and had no RSA decryption at all; each is now one call to the xkms service's `Encrypt`/`EncryptAsym`/`Decrypt`, so CBC/CBC-PAD with a caller IV, GCM with AAD and a truncated tag, and OAEP with a label work in-process, over the xkey socket and on `xkey usb device start`. `IPCTransport` no longer discards its context: a context that has already ended sends nothing, and one that ends mid-request abandons the connection, both failing with the new `ErrIPCRequestCanceled`. The xkey IPC server runs each handler under a request context that ends when the client hangs up or the server stops, and `ipc.PKCS11Handler` methods take that context. Files: `xkey/pkg/pkcs11/service.go`, `ipc_transport.go`, `errors.go`, `xkey/pkg/ipc/server.go`, `xkey/pkg/gui/services/pkcs11_ipc_handler.go`. Docs: `xkey/docs/pkcs11/engineering.md`.
