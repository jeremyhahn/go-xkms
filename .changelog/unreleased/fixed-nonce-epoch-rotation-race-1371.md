- **Fixed a race in ACME nonce epoch rotation that could install two epochs for one expiry** (#1371). `RestService` tracked the current signing epoch and the time it began as two separate atomics (`nonceEpoch atomic.Pointer[acmenonce.Service]`, `nonceEpochAt atomic.Int64`), updated with two consecutive, non-atomic stores in `rotateNonceEpoch`. A concurrent reader could observe the store to `nonceEpoch` (the fresh epoch) before the store to `nonceEpochAt` (still the retired epoch's start time), compute a stale age for the already-current epoch, and pass that current epoch back into `rotateNonceEpoch` as `stale`. Because the re-check there (`current != stale`) compared against that same already-current pointer, it passed trivially and let the reader perform a second, illegitimate rotation — defeating the single-rotation-per-epoch guarantee `nonceRotateMu` exists to provide. Under `-race -cpu=2,8` with the host CPU-saturated, this reproduced at roughly 1-in-200 concurrent-rotation runs (`TestRestService_NonceEpochRotation_NoConcurrentDoubleRotation`, `pkg/acme/server/handlers/nonce_wiring_test.go`); it did not reproduce with `GOMAXPROCS=1` or without external CPU contention, consistent with a narrow scheduling window between two independent atomic stores.
  - Fixed by collapsing the pair into one `nonceEpochRecord{epoch, at}` swapped through a single `atomic.Pointer[nonceEpochRecord]`, so a reader can never observe a fresh epoch paired with a stale start time. `rotateNonceEpoch`'s re-check now compares whole records, which is sound because a record is only ever replaced as a unit.
  - Files: `pkg/acme/server/handlers/service.go` (`nonceEpochRecord`, `RestService.nonceEpoch`, `currentNonceEpoch`, `rotateNonceEpoch`), `pkg/acme/server/handlers/nonce_wiring_test.go` (updated to the new record type; no test behavior changed).
  - Verified: 4000 runs of `TestRestService_NonceEpochRotation_NoConcurrentDoubleRotation` (`-race -count=1000 -cpu=1,2,4,8`) under artificial CPU oversubscription (32 busy-loop processes on a 24-core host) — 0 failures after the fix, versus 5 failures in 900 runs under the same stress before it. `go test -race` clean on `pkg/acme/server/handlers` and `pkg/acme/nonce`; `golangci-lint run` clean on both packages.
