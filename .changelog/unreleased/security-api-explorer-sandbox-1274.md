- **The xkey API Explorer response preview rendered fetched HTML in a same-origin, scripted `srcdoc` iframe** (#1274). `APIExplorer.svelte`'s preview tab set `sandbox="allow-same-origin allow-scripts allow-forms allow-popups"` by default, and that same default was writable via user config (`gui.api_explorer_sandbox_policy`) and enterprise policy (`policy.api_explorer_sandbox_policy`). A `srcdoc` frame with `allow-same-origin` shares the parent document's origin, so `allow-scripts` combined with it let script in *any* fetched HTML response reach `window.parent`, including every Wails service binding — `OIDCService.ExecuteScript` among them, which shells out. The default policy no longer includes `allow-same-origin` or `allow-scripts`: previewing rendered HTML needs neither, and without `allow-same-origin` the srcdoc document has a unique opaque origin, so `allow-scripts` alone (if a user re-enables it) can no longer reach the parent at all.
  - New shared validator, mirrored in TypeScript and Go: `xkey/frontend/src/lib/utils/sandboxPolicy.ts` (`validateSandboxPolicy`) and `xkey/pkg/config/sandbox_policy.go` (`ValidateAPIExplorerSandboxPolicy`). Both refuse `allow-scripts` + `allow-same-origin` together, and refuse `allow-top-navigation*`, `allow-popups-to-escape-sandbox`, and `allow-modals` outright, regardless of combination. `APIExplorer.svelte` and `Settings.svelte` validate every policy they load or build (user config, enterprise override, and the Settings toggles) and fall back to the safe default with a visible notification when a policy is refused.
  - Go is authoritative, not just advisory: `config.Config.Validate()` now rejects a `policy.api_explorer_sandbox_policy` (enterprise policy) that carries the dangerous combination or a forbidden directive, since that plane is opt-in and security-authoritative. `gui.GUIConfig.Validate()` normalizes (rather than rejects) an invalid `gui.api_explorer_sandbox_policy`, because every installation that has not touched Settings since before this fix already has the old dangerous string persisted on disk as its default, and rejecting it outright would lock every existing user out at next launch.
  - Added a `Content-Security-Policy` restricting frame sources to `frame-src 'self' about: data:` (plus `object-src 'none'; base-uri 'self'`), applied via a Wails `AssetServer` middleware (`pkg/gui/csp.go`) for the built app and via a `<meta>` tag in `frontend/index.html` for the Vite dev server. This is deliberately narrower than a full CSP: `script-src`/`style-src`/`connect-src` are left unrestricted because the Svelte build's inline style attributes, xterm.js, and the Vite dev server could not be exercised against a running GUI to confirm a stricter policy would not break them.
