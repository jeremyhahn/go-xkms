- **`CA.recordRevocation` now persists a revocation before it caches it, and checks for a duplicate through the replicated store, not only the in-memory map.** It used to insert into `ca.revocations` first and persist second: a failed store write still left the serial enforced on that node with no way to recover, because a retry hit the in-memory entry and returned `ErrAlreadyRevoked` for a record that had never actually been persisted. Its duplicate check also read only the map, so a node could revoke a serial another node already revoked and silently overwrite the original record's reason and time. The duplicate check now goes through `lookupRevocation` (the map, then the store), failing closed with a typed `ErrStorageError` on a store read fault; an existing record returns `ErrAlreadyRevoked` wrapped in `*errs.Detail` naming the original reason and time. The write itself uses `PutIfAbsent` -- `storage.Backend`'s unconditional create-if-absent primitive -- instead of a plain `Put`, and only a successful write updates the in-memory map (`cacheRevocation`) and triggers the CRL refresh that already followed it. A store write failure now returns a typed `*errs.Joined` wrapping `ErrStorageError` and the cause, with the map left untouched, so a retry after the store recovers persists instead of being rejected. For a replicated backend (every `go-qrdb`-backed `Backend` this package runs against), `PutIfAbsent` is a linearizable cross-node compare-and-swap keyed on "no record exists yet," so two nodes racing to revoke the same serial can both attempt the write but only one succeeds; the loser observes `stored=false` and reports `ErrAlreadyRevoked` with the winner's record read back through `lookupRevocation`, closing the race the duplicate check alone could not. Files: `pkg/ca/ca_extensions.go`, `pkg/ca/errors.go`. Verified by `pkg/ca/revocation_race_1131_test.go` (a failed `PutIfAbsent` leaves the map unchanged and a retry after recovery persists; two `*CA` instances over a shared store racing to revoke the same serial leave the loser with `ErrAlreadyRevoked` and the winner's reason/time intact; a store read fault during the duplicate check fails closed before any write is attempted), reusing the `pkg/ca/revocation_cluster_test.go` two-node harness. go-xkms#1131.
