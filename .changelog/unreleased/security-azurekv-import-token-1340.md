- **The Azure Key Vault backend no longer hands its import-wrapping private key to the caller** (#1340). `pkg/backend/azurekv.Backend.GetImportParameters` returned the ephemeral RSA wrapping key's PKCS#1 private key as `ImportParameters.ImportToken`, and `UnwrapKey`/`ImportKey` parsed the private key back out of the caller-supplied `WrappedKeyMaterial.ImportToken`. That broke the `ImportParameters` invariant that the unwrapping private key never leaves the backend: anyone who saw the token in transit (REST/gRPC/MCP response, logs) could decrypt the wrapped key material, and a caller could supply a private key of its own choosing. The backend-side store the fix for #1261 bounded was never read.
  - The wrapping private key is now sealed in an `importtoken.SealedRSAKey` held in the backend's `importtoken.Store`, keyed by a random UUID handle, and `ImportToken` is only that handle -- the same pattern the software and symmetric backends use. `UnwrapKey` (and `ImportKey` through it) resolves the handle with a single-use `Take` and refuses an unknown, expired or replayed handle with `backend.ErrKeyNotFound`; a failed unwrap also consumes the handle. The store is no longer keyed by CN, so two concurrent ceremonies for the same CN no longer overwrite each other's wrapping key, and `ImportKey`'s redundant "delete after import" step is gone.
  - Tokens issued before upgrade are refused; callers must request new import parameters. The backend still unwraps locally and imports the key as a JWK; Azure Key Vault's native key-exchange-key BYOK flow is not used.
  - Files: `pkg/backend/azurekv/{azurekv,azurekv_importexport}.go`, `docs/crypto-backends/engineering.md`.
  - Verified by: new `pkg/backend/azurekv/import_token_handle_test.go` (the token is not parseable as PKCS#1/PKCS#8 and has the handle's length; wrap/unwrap round trip for all four wrapping algorithms; unknown, expired, replayed, caller-supplied-private-key and post-failure handles refused with `backend.ErrKeyNotFound`; `ImportKey` refuses unknown and replayed handles; per-ceremony handles for one CN); `go vet` and `go test -race` under `-tags azurekv`; `go build -tags "codec_cbor codec_json codec_msgpack tpm_simulator frost azurekv" ./...`.
  - Fixes #1340.
