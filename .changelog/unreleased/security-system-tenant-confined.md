- **The system tenant no longer reaches into other tenants** -- a system-tenant identity was lifted past tenant isolation (`auth.IsCrossTenant`), so it could sign, issue and revoke certificates, manage TPM policies, rotate scope keys, and read SSH keys, OIDC credentials and passwords in any tenant. Every caller, the system tenant included, is now confined to its own tenant: `pkg/scope` refuses a cross-tenant request with `*scope.CrossTenantError`, and the service binding in `pkg/xkms/tenant_binding.go` answers a foreign tenant as an unknown one. Administering the tenant registry (create, list, delete, entitlements, quotas) and the TPM mode and vTPM stays system-only. Breaking: a platform administrator who managed a tenant's assets from the system tenant must now sign in to that tenant. Files: `pkg/scope`, `pkg/xkms/tenant_binding.go`, `pkg/ssh/tenancy/client.go`, `pkg/tenantgate`, `pkg/passwords`.
- **A request with no identity is refused, not treated as the platform** -- `scope.PrincipalOf(nil)` used to be the system tenant, so a request that reached a service without an identity acted as the platform. It is now unauthenticated and refused with `*scope.UnauthenticatedError`, which matches `scope.ErrRefused`. Only the `XKMSService` tenant binding (`callerTenant`) still maps an in-process call with no identity to the system tenant. File: `pkg/scope`.
- **The local unix socket attaches an identity to every admitted peer** -- a peer that passes the peer-credential policy now carries subject `uid:<peer uid>` in the system tenant, with `auth_method` `unix-peer` and its uid, gid and pid in the identity metadata. Without it, the socket's SSH, OIDC and password RPCs refused every caller once a missing identity stopped meaning the platform. A refused peer never gets an identity. Files: `pkg/api/unix/peercred.go`, `pkg/api/unix/grpc_server.go`.
