- **Key lookups are tenant-exact (#2233)**: a system-tenant get, version listing, rotation or deletion of a key no longer resolves another tenant's key of the same name on the unscoped backend view; it acts only on the system tenant's own key and answers `ErrKeyNotFound` when there is none. `FindKeyAttributes` resolves in the tenant of the view it is given. A request that names a tenant is first admitted through the caller's tenant (`auth.AdmitTenant`), so a dedicated-tenant caller naming another tenant is refused with `*qrdbsdk.CrossTenantDeniedError`. On MCP, a request with no authenticated identity acts as the system tenant, so its key lookups by name (`findKeyByCN`, `findKeyInBackend`, `exportKeyMaterial`) resolve only system-tenant keys.
