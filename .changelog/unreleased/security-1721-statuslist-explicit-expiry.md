- **The Android attestation status list refuses a response its own caching metadata already expired (#1721).** `HTTPStatusList` applies RFC 9111 §4.2 exactly, `freshness_lifetime > current_age` with the lifetime per §4.2.1 and the age per §4.2.3, the round trip included without an Age field: a response with `max-age=0`, an `Expires` in the past or invalid, or an invalid `max-age` is stale, so it is revalidated once (`Cache-Control: no-cache`), where it was used. The origin's own answer to that validation (no positive Age field) satisfies the current check and is never cached, so an origin serving `max-age=0` is contacted on every use (§4.3.3); a stale answer a cache served (a positive Age) is still refused. A response with no max-age or Expires is still used once and never cached. RFC 9111 is copied to `docs/references/rfc-9111.txt`.
