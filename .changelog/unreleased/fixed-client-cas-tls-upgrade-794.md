- **The unified API server's client-CA pool now keeps the operator's configured `tls.ca_file`/`tls.client_cas` after the embedded CA composes, instead of silently dropping them** (#794 triage). `upgradeUnifiedTLSCert` used to replace `tls.Config`'s client-CA pool outright with the CA bundle (`ca.CATrustPools.CABundleCertPool()`), so an mTLS client anchored only by an operator-configured client CA stopped being accepted the moment the CA composed, even though `tls.client_cas` still named that CA. It now installs the union of the configured client CAs -- resolved through the same `loadClientCAsUnion` helper `buildTLSConfig` uses at startup, via the new `unifiedClientCAPool` -- and the CA's bundle, so both continue to verify. A re-read `tls.client_cas` failure surfaces as the existing typed `*ErrCertParse`/`*ErrFileRead` rather than being swallowed; a CA-bundle fetch failure degrades only the pool (typed `*ErrTLSCertOp`, logged) while the certificate upgrade still proceeds. Files: `pkg/server/unified_tls.go`. Verified by `pkg/server/unified_client_ca_pool_test.go` and `pkg/server/unified_tls_test.go`.
