- **Every go-xkms binary now refuses to be inspected by other processes** -- nothing called go-qrdb's process hardening, so a debugger or any process running as the same user could read mlocked secret memory through `ptrace` or `/proc/<pid>/mem`, and a crash could write it to a core file. `sdk/go/secure` re-exports `HardenProcess` with its outcome, error types and `AllowProcessInspectionEnv`; `xkmsd`, `xkmsctl`, `trusted-acme-client`, `xkey` and `e2eprobe` call it first thing in `main` and exit 1 on error, and the PKCS#11 module hardens its host on the first `C_Initialize` (`CKR_GENERAL_ERROR` on failure). Linux sets `PR_SET_DUMPABLE=0`, macOS `PT_DENY_ATTACH`. `QRDB_SECURE_ALLOW_PROCESS_INSPECTION=true` leaves a process debuggable with a logged warning, and FIPS 140-3 mode refuses it. Files: `sdk/go/secure/secure.go`, `cmd/*/main.go`, `cmd/pkcs11-module/harden.go`, `xkey/cmd/*/main.go`. (#33)
