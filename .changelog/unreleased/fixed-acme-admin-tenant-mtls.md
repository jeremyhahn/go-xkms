- **ACME admin plane authenticates tenant users over mTLS** -- the admin plane looked every client certificate up in the system tenant only, so a tenant user's certificate never authenticated. It now resolves the tenant with go-qrdb's `TenantFromClientCert` rule, pinned to the deployment's trust domain (a tenant SPIFFE SAN, else the first OU, else the system tenant), and looks the certificate up in that tenant only. A SPIFFE SAN from another trust domain, a malformed or ambiguous one, a missing certificate or an unbound one is refused with `401` and never falls back to the system tenant. xkmsd also now passes its trust domain to the CSR signer, so tenant certificates it issues carry the `spiffe://<trust-domain>/tenant/<id>/...` URI SAN the rule reads. Files: `pkg/acme/admin/auth_mtls.go`, `cmd/xkmsd/admin.go`, `pkg/server/server.go`, `pkg/server/firstboot.go`.
