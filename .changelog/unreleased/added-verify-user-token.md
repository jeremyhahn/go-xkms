- **`pinUvAuthToken` through phone user verification (ruling 167)** — clientPIN `getPinUvAuthTokenUsingUvWithPermissions` (`0x06`) now mints a token when the key backend implements `keybackend.UserVerifier` (re-exported by `sdk/go/fido2/keybackend`), and `getInfo` reports `uv` for it; the #1145 refusal is gone. A refusal spends one `uvRetries` (`CTAP2_ERR_UV_INVALID`, then `CTAP2_ERR_UV_BLOCKED`), a cancel spends none. `PhoneKeyBackend.VerifyUser` runs `local.verifyUser` through the new `PhoneKeyBackendConfig.VerifyUser`, which paired-device backends set to `attestation.NewUserVerifier`: the UVK chain is checked to the Google hardware root, with KeyMint tags 503 to 506 requiring a fresh biometric, and the signature over a fresh challenge, on every use.
