- **CI cache trim now bounds in-use cache volumes.** `scripts/trim-ci-caches.sh` used to keep every cache volume a container mounted, so one runner host's Go build cache volume reached 57G and filled the disk. When the caches are still over the bound with only in-use volumes left, it now trims inside them through a read-write, network-less toolchain container: whole Go build-cache entry files oldest first (or `go clean -cache` when that volume alone is over the bound), the golangci-lint cache emptied whole, and the module cache never trimmed per file, only reported. A volume a running build holds is never trimmed: each stage holds a shared lock per cache volume, a lock file inside the volume itself (`.ci-cache.lock`, so job containers sharing one Docker daemon all see it), and the trim skips a volume whose lock it cannot take exclusively. `REAP_DRY_RUN=1` still changes nothing and the trim never fails the job.
