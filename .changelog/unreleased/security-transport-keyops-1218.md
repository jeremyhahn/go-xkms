- **High: one tenant could read, list, delete, rotate, export and copy another tenant's keys over REST, and read and list them over gRPC.** REST's `GetKeyHandler`, `ListKeysHandler`, `DeleteKeyHandler`, `RotateKeyHandler`, `ExportKeyHandler` and `CopyKeyHandler` (`pkg/api/rest/handlers.go`), and gRPC's `GetKey` and `ListKeys` (`pkg/api/grpc/service.go`), resolved keys over the unscoped backend themselves. A cross-tenant test confirmed the leak for every one of them before the fix. A tenant authenticated as A that named tenant B's key got B's public key, deleted B's key, replaced it with a new one, or received B's private key material wrapped for export. Listing returned every tenant's keys. REST's copy reached B's key and exported it, and failed only at the import step. gRPC's `DeleteKey`, `RotateKey`, `ExportKey` and `CopyKey` source lookup were already scoped (go-xkms#221), but gRPC's `CopyKey` imported the copy through the unscoped destination, so a tenant's copy landed with no tenant. All twelve are now thin adapters over the matching `XKMSService` method. `XKMSService.GetKey`, `DeleteKey` and `ListKeys` take no request struct, so they now read the caller's tenant from the authenticated identity on the context (`scopedTenantIDFromContext`). The `KeyServicer` signatures are unchanged, which also scopes MCP's `getKey` and the embedded transport. Another tenant's key is the same bare `ErrKeyNotFound` a missing key is, so the refusal is byte-for-byte the genuine-miss response: REST `404`, gRPC `NotFound`. A platform-scoped caller (no identity, or the system tenant) still sees every key. `CopyKey` adopts the service's semantics on both transports. The copy takes the source key's attributes, lands in the caller's tenant, and is wrapped for the destination's own import parameters. REST's `CopyKeyRequest` loses `key_type`, `key_size`, `curve`, `hash` and `aes_key_size`, which the copy no longer reads. A copy between two backend instances now succeeds; before, it failed on both transports with `invalid import token`. Wire changes: not-found and backend-not-found messages are now the service's (`keystore: key not found`); a malformed backend name is `400`/`InvalidArgument`; REST's `GetKey` returns `200` without `public_key_pem` when the key handle cannot be read; gRPC's `GetKey` fills `public_key_pem` for every asymmetric key. `transport.KeyInfo` gains `key_size`, `curve` and `partition`, and `transport.RotateKeyResponse` gains `key_type`, so no transport lost a response field. A backend without import/export support is refused with `ErrBackendUnsupported`, which now carries a `Cause` naming the missing half (`backend.ErrExportNotSupported` or `backend.ErrImportNotSupported`). Both transports' `mapKeyOpError` classify the backend causes the service wraps, such as `ErrKeyNotExportable`, as the direct backend call did. The dead gRPC `extractPublicKeyPEM` is deleted.
