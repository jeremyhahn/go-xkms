- **The password vault and its session moved off the entries namespace, to `/api/v1/password-vault`.** `GET /api/v1/password-vault` (vault status), `GET /api/v1/password-vault/session` (was `GET /api/v1/passwords/status`), `POST /api/v1/password-vault/unlock` and `/lock`, `POST /api/v1/password-vault/factors`, `PUT|DELETE /api/v1/password-vault/factors/{id}` and `POST /api/v1/password-vault/recover` replace the `/api/v1/passwords/vault...`, `/unlock`, `/lock` and `/status` routes. `/api/v1/passwords/{id}` now holds entries only, so an entry named `vault` or `status` is fetched by name like any other. The REST and QUIC client transports, the MCP path map, the TypeScript SDK (`passwords.unlock/lock/status/vault*`, unchanged method names) and the web console follow; gRPC, MCP method names and permissions are unchanged. No compatibility aliases: the stack is pre-v1 with one wire format.
