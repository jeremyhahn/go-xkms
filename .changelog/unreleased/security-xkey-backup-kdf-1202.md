- **xkey backups no longer derive their key from an unsalted SHA-256 of the password** — both the `xkey backup` CLI (`create`, `restore`, `contents`, `to-device`, `from-device`) and the GUI password-vault backup keyed their cipher with one SHA-256 of the password, so a stolen `.xkb` or `.enc` file could be brute-forced at GPU speed and attacked with precomputed tables across users. Password keys now come from the canonical go-xkms password hasher: Argon2id (t=3, m=64 MiB, p=4; PBKDF2-SHA256 under the Go FIPS 140 module) over a fresh 32-byte random salt. `pkg/crypto/kdf.PasswordHasher` gains `NewKeyParams`/`DeriveKeyFromParams` and a persisted `PasswordKeyParams` record (re-exported through `sdk/go`), which refuses any record whose costs differ from the ones its version pins; `xkey/pkg/backup.Key` (`NewPasswordKey`, `DerivePasswordKey`) is the one helper both paths use. The `.xkb` envelope is now version 2 with a `kdf` header and the GUI backup is an `XKPW` JSON envelope recording algorithm, salt and parameters; in both, the header is authenticated as AEAD additional data, so a tampered salt, cost or version fails. **Breaking:** version 1 `.xkb` files and pre-existing encrypted GUI backups are refused with typed errors (`backup.ErrLegacyBackupFormat`, `ErrRestoreLegacyFormat`), never migrated — re-create them. The CLI `--password` value flag, visible to every process via `ps`, is removed: the password is read from `--password-stdin` or `XKEY_BACKUP_PASSWORD`, as a `[]byte` wiped with `enclave.Wipe` after derivation.
