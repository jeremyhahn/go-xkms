- **SoftHSM 2.7.0, built from a pinned, checksum-verified release, replaces the distribution's 2.6.1 in every image** -- SoftHSM 2.6.1 answers an AES-GCM tag mismatch with `CKR_GENERAL_ERROR`, the code PKCS#11 reserves for an unrecoverable token error, so PKCS#11 tamper could not be reported as `types.ErrSealedDataAuthentication` on any image this repository tests with; 2.7.0 answers `CKR_ENCRYPTED_DATA_INVALID`, which the PKCS#11 backend classifies. New `scripts/build-softhsm.sh` is the single pin (version plus the SHA-256 of the upstream release archive, verified before anything is extracted) and installs at Debian's paths (`/usr/lib/softhsm/libsofthsm2.so`, `/usr/bin/softhsm2-util`, `/etc/softhsm`), stripped, file object store only. It is used by `Dockerfile.ci`, the devcontainer and `Dockerfile.virt-piv`, the integration-test `Dockerfile`, the Alpine SoftHSM sidecar (`test/docker/softhsm`, previously 2.6.1 from an unverified git tag), the `test/integration/{pkcs11,pkcs11/module,acmeadmin,storage}` images, xkey's e2e image, the published runtime images (`Dockerfile.{server,rest,grpc,mcp,quic,cli}` and the image `release.yml` generates) and the `ci.yml` jobs that initialize a token. Build-only images and stages (`Dockerfile.builder`, `release.yml`'s binary legs, the `ci.yml` build job) no longer install SoftHSM at all: the binaries `dlopen()` the module at run time. Builds whose context cannot reach `scripts/` get it as the named build context `softhsm-pin` from their compose files. `test/scripts/softhsm-pin.test.sh` (in `make test-scripts`) fails on any distribution SoftHSM install, any Dockerfile or workflow using SoftHSM without the script, and an archive that does not match the pin. New `TestSupportedSoftHSM_ReportsTamperAsSealedDataAuthentication` (`pkcs11` tag) proves it on the images: it requires SoftHSM 2.7.0 or later (an image regressed to 2.6.x fails, naming the script) and that a flipped ciphertext, tag or nonce, truncation, extension, a mismatched or omitted AAD and a foreign key each fail `Unseal` with `types.ErrSealedDataAuthentication` and the token's own `CKR_ENCRYPTED_DATA_INVALID`. The minimum SoftHSM version for PKCS#11 tamper classification, 2.7.0, is documented in `docs/pkcs11-backend/`. Closes #1418.
