- **A TPM device that never answers is an error, not an unprovisioned TPM.** `NewTPM2` probed the EK handle and then the EK certificate NV index, and treated any failure of either as "no EK yet", so a transport that failed before the TPM returned a response code (EOF from a dead or wrong device, a closed socket) came back as `ErrNotInitialized` with a live instance. Provisioning callers accept that error and went on to provision a device that was never there. Only a TPM response code now means unprovisioned; a transport failure returns the new `ErrDeviceNoResponse` with no instance and releases the device. `TestNewTPM2_DeviceNeverAnswersIsAnError` pins it.
