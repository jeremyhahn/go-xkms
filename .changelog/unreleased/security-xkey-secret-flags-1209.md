- **No xkey command accepts a secret as a command-line flag value anymore.** A value on `argv` is visible to every other process on the host via `ps`; each secret-bearing flag is now a `-stdin` boolean paired with an `XKEY_*` environment variable, following the `pin_input.go` convention #1202 established for `--pin`/`--so-pin`/backup `--password`. Changed: `xkey backup restore`/`contents`/`from-device --key` → `--key-stdin`/`XKEY_BACKUP_KEY`; `xkey password add --password` → `--password-stdin`/`XKEY_STATIC_PASSWORD`; `xkey password unlock --pin` → the shared `--pin-stdin`/`XKEY_PIN`; `xkey oath add --secret` → `--secret-stdin`/`XKEY_OATH_SECRET`; `xkey platform-store put --value` → `--value-stdin`/`XKEY_PLATFORM_STORE_VALUE` (`--file` is unaffected); and the barrier password shared by `xkey oath`, `xkey backup`, `xkey backup to-device`/`from-device`, `xkey device sync`/`oath-sync`/`pair`/`listen`/`attest-device`, `xkey provision`, `xkey oidc login`/`token`/`refresh`/`logout`, `xkey extension serve`, `xkey fido2`, and `xkey secret-service` — `--barrier-password` → `--barrier-password-stdin`/`XKEY_BARRIER_PASSWORD` (`--barrier-password-file` is unaffected). `xkey fido2 --set-pin` (the initial CTAP2 PIN to establish) is now `--set-pin-stdin`, deliberately with no environment variable, matching its historical CLI-only scope. `backupCredential.password` moves from a `[]byte` field to `*secure.Buffer` (`secure.NewBufferFromBytes`/`.Bytes()`/`.Destroy()`), the storage form `make secure-analyzer` requires for a struct field holding sensitive material. Every changed command keeps its old flag name gone outright (no compatibility shim, no deprecation period): stdin, environment, old-flag-removed, and no-source-supplied are each covered by new or updated tests.
