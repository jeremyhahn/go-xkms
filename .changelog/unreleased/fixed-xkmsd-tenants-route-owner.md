- **`xkmsd run` starts with the admin module, and starts again after `xkmsd init` (go-xkms#794).** Core is now the only owner of tenant create, list, get and delete at `/api/v1/tenants`, behind the tenant gate. The admin module keeps tenant update, status and the CA, EAB, roles and users sub-resources, so the duplicate route registration no longer panics at start-up. `xkmsd init` now seeds the built-in roles with the xkms role grants, so first boot on `xkmsd run` adopts the existing admin role instead of failing with `role: name already exists`.
