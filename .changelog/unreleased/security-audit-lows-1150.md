- **FIDO2/WebAuthn clients now refuse a server rpId the caller's origin does not cover, and never build an origin from the rpId** (#1150, WebAuthn L2 §5.1.3 step 8, §5.1.4.1 step 7). New `fido2.ValidateRPID` requires the rpId to equal the origin's host or be a registrable-domain suffix of it, rejecting public suffixes (`com`, `co.uk`, `github.io`, via `golang.org/x/net/publicsuffix`) and any suffix of an IP-literal host. It runs in `ParseWebAuthnRegistrationOptions`, `RegisterWebAuthn`, `AuthenticateWebAuthn`, the assertion options parser and both `SoftwareAdapter` ceremonies, before any authenticator is touched. An empty origin now fails with `fido2.ErrOriginRequired` instead of defaulting to `https://<rpId>`. The origin-less `FIDO2Handler.AssertWithOptions` is removed (use `AssertWithOptionsAndOrigin` or `Assert`). `webauthnclient.NewClient` refuses a config from which no origin can be derived. The server-URL origin helper is exported as `webauthnclient.OriginFromURL` and replaces xkey's private duplicate. `xkmsctl user register`, `user login` and `admin create` gain `--origin`. It defaults to the origin of an `http(s)://` `--server`, and over the Unix socket, gRPC or QUIC it is required.
  - Files: `pkg/fido2/{rpid,types,webauthn_assertion,webauthn_attestation}.go`, `pkg/webauthn/client/{client,types,software_adapter}.go`, `sdk/go/{fido2/fido2,webauthnclient/webauthnclient}.go`, `cmd/xkmsctl/{webauthn_origin,errors,user,admin}.go`, `xkey/cmd/xkey/cmd/{auth,webauthn_ceremony}.go`.
- **xkey's virtual authenticator enforces the CTAP 2.1 §6.5.5.5 consecutive-mismatch block for the user PIN.** After three wrong PINs in a row, every `pinHashEnc` check (`changePIN`, `getPinToken`, `getPinUvAuthTokenUsingPinWithPermissions`) returns `CTAP2_ERR_PIN_AUTH_BLOCKED` without spending a retry, even with retries left. A restart (the power cycle) or `authenticatorReset` clears the block, and a correct PIN resets the count. `getPINRetries` reports `powerCycleState`. Every mismatch regenerates the keyAgreement key and keeps an existing pinUvAuthToken. The counter type (`pinMismatchGuard`) is shared with the SO PIN path, and `SOPINMaxConsecutiveFailures` is renamed `PINMaxConsecutiveFailures`.
  - Files: `xkey/pkg/authenticator/{pin_mismatch,so_pin,cmd_clientpin,errors,authenticator}.go`.
- **Browser-extension pairing and identity-verification failure counters and lockouts are durable.** They were held in the native host's memory, and the browser launches a fresh host per connection, so a relaunch reset them. They now live in `<data dir>/extension/pairing-limits.json` (0600, atomic write) beside the pairing state, and every check re-reads them because the GUI and all host instances share the file. Unpairing does not clear a lockout. An unreadable or corrupt file, or a failure that cannot be persisted, fails closed. The pairing code is compared with `subtle.ConstantTimeCompare`.
  - Files: `xkey/pkg/nativemsg/{pairing,pairing_limits}.go`.
- **WebAuthn logins with a possibly cloned credential are logged at Warn and audited.** A login whose signature counter did not advance (go-webauthn `CloneWarning`) now records `auth.webauthn.clone_warning` through the new `ServiceParams.AuditLogger`, with stored and presented counts and `first_detection` in the details. xkmsd, the REST server and `rest.BuildWebAuthnService` (`WebAuthnServiceParams.AuditLogger`) wire it, and xkmsd now initialises its audit logger before the WebAuthn service. The login policy is unchanged: the login still succeeds, and whether to refuse a flagged credential is left to the owner. The action classifies `SeveritySecurity`, so a failed audit write fails the login.
  - Files: `pkg/webauthn/{clone_warning,service}.go`, `pkg/api/rest/{host,server}.go`, `pkg/server/server.go`.
