- **Invitations are minted only under `users:invite`.** `CreateUser` now asks go-qrdb's `users:invite` before it creates an email-login-key account and mints its activation invitation; a caller holding `users:create` alone is refused with `PermissionDeniedError` and no account is created. The decision is made against the tenant the request names, so no caller (the system tenant included) can mint an invitation into a tenant not its own. Accounts created without an email login key (bootstrap, no invitation) still need only `users:create`. The self-built ServiceModule host decides on the AuthMiddleware the host hands over (`SetTenantTargetAuthorizer`), so delegated grants count, and audits these decisions on the node's audit plane even when the host set its own authorizer.
