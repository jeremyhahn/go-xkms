- **Five low-severity findings from the 2026-09-28 cryptographic-misuse audit are fixed.** Each was traced to a production path (go-xkms#1205):
  - `xkey`'s native-messaging session crypto authenticates a frame before it can affect replay state. `SessionCrypto.Decrypt` (`xkey/pkg/nativemsg/crypto.go:170-217`) used to advance the `recvNonce` compare-and-swap before `gcm.Open` verified the tag, so a forged frame with a high counter and an invalid tag still poisoned the replay window and refused every later legitimate frame as a replay -- a denial-of-service reachable by anyone who could inject a frame. `Decrypt` now authenticates first and advances `recvNonce` only once `gcm.Open` succeeds; an unauthenticated pre-check against the last accepted nonce still short-circuits an obviously stale frame without doing cryptographic work or mutating state.
  - `types.KeyAttributes.String()` (`pkg/types/types.go:1223-1256`) no longer has a `Debug`-gated "Secrets" block: it never renders `Password` or `SealData`, regardless of `Debug`, because the method has no way to know whether its caller is a trusted diagnostic path or an untrusted sink. `Debug` also defaulted to `true` for TPM2 EK, IAK, IDevID and SSRK keys (`pkg/tpm2/config.go:91,109,120,141`) and now defaults to `false` for all four; the field still gates non-secret diagnostic logging elsewhere (`PlatformPassword.Bytes`'s cache-hit/unseal-attempt lines, `store.DebugKeyAttributes`'s attribute dump), which is unchanged and never logged a secret.
  - `pkg/auth`'s JWT and OIDC authenticators pin `jwt.Parse` to `jwt.WithValidMethods`, scoped to the verification key's actual type -- RS\*/PS\* for RSA, ES\* for ECDSA, EdDSA for Ed25519 (new `pkg/auth/jwtalg.go`, wired at `pkg/auth/jwt.go:160` and `pkg/auth/oidc.go:384`). This closes an algorithm-confusion path where a token forged with `alg: HS256` and signed with the verification key's own bytes as an HMAC secret would otherwise reach the signature check; HS\* is refused unconditionally on every public-key path, including a JWKS response smuggling a symmetric ("oct") key. On OIDC, when the discovery document publishes `id_token_signing_alg_values_supported`, the key's permitted methods are further narrowed to their intersection with that list, refused as `NoCommonSigningAlgorithmError` if the intersection is empty.
  - The `Encrypt` RPC's RSA fallback (`pkg/xkms/servicer_crypto.go:613`) no longer performs PKCS#1 v1.5 encryption unconditionally. PKCS#1 v1.5 authenticates nothing and its conformance check is the Bleichenbacher/Marvin decryption oracle (RFC 8017 §7.2.2), so it is now gated on the same `crypto.allow_legacy_key_wrap` policy that already governed the matching `WrapKeyByID` mechanism, and refused with a typed `ErrLegacyWrapDisabled` (via `ErrValidation`) otherwise once the resolved key is confirmed to be RSA. `EncryptAsym` (RSA-OAEP, `POST /api/v1/keys/{id}/encrypt-asym`) is the unconditionally-available replacement and needs no configuration change.
  - The generic Argon2 KDF adapter's floor (`pkg/crypto/kdf/argon2.go`) is raised from 8 MiB at t=1 to OWASP's Argon2id recommendation, 19 MiB at t=2 (`MinArgon2Memory`, `MinArgon2Time`). Every built-in caller (`kdf.DefaultParams`, the password hasher's default parameters) already ran at 64 MiB / t=3 / p=4 and needed no change; the floor governs request-supplied parameters on the `DeriveKey` API surface.
  - Verified by: `xkey/pkg/nativemsg/crypto_test.go` (`TestSessionCrypto_ForgedHighCounterFrame_DoesNotPoisonReplayWindow`); `pkg/types/types_test.go` and `pkg/xkms/types_test.go` (`String()` never contains a secret even with `Debug: true`); `pkg/auth/jwt_test.go` and `pkg/auth/oidc_test.go` (an HS256 token forged against the public key's bytes is refused; RS256/ES256 tokens still verify); `pkg/xkms/servicer_crypto_test.go` (`Encrypt`'s PKCS#1 v1.5 fallback refused by default, accepted with `crypto.allow_legacy_key_wrap`), plus updated fixtures in `pkg/api/rest/handlers_transport_audit_test.go` and `pkg/api/grpc/service_coverage_gaps_test.go` that now opt into the legacy policy to exercise the same construction; `pkg/crypto/kdf/kdf_test.go` (`TestArgon2Adapter_OWASPFloor`, below/at the new floor).
  - Files: `xkey/pkg/nativemsg/crypto.go`; `pkg/types/types.go`; `pkg/tpm2/config.go`; `pkg/auth/{jwt,jwtalg,oidc}.go`; `pkg/xkms/servicer_crypto.go`; `pkg/crypto/kdf/argon2.go`.
