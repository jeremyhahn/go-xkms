- **xkey fido2 stops on a rejected Platform SRK PIN and guards the PIN file.** When the TPM rejects the Platform SRK PIN, `xkey fido2 --backend tpm2` exits with status 78, which `deploy/systemd/xkey.service` lists in `RestartPreventExitStatus`, so restarts cannot walk the TPM into dictionary-attack lockout. A `--pin-file` that its group or other users can access is refused (0600 or stricter), the whole file buffer is wiped after the read, and the daemon keeps the PIN sealed in protected memory until the one auth that uses it. `*TPM2` is now checked at compile time to carry the Platform key store setter.
