- **CI runs in two tiers, and the nightly suite is manual** -- an ordinary pull request now runs only the PR tier (changes, lint, static analysis, architecture gates, one build job that compiles xkmsctl, xkmsd and xkey, the nested-module build, changed-package unit tests and CI Gate). The full tier adds the full unit suite with its coverage gate, race, raft builds, nested-module tests, security, the TPM simulator and the docker image scan. It runs on a push to `main`, on `workflow_dispatch`, on `train/*` and `merge-train/*` branches, and on any pull request labelled `ci:full` (`labeled` is now a `pull_request` trigger, so adding the label starts a run). Each full-tier job states its condition in full. CI Gate, still the one required check, tags every job `pr` or `full` and accepts a skip only from a `full` job when the full tier was not selected. `make test-buildgates` (`internal/buildgates`, `TestCIGateTiersMatchTheJobs`) fails if a tag, a job's `if:`, or the gate's `needs:` disagree, and lint runs it. The build matrix, which was per binary rather than per platform, is now a single job. The docker image scan runs on the full tier and is no longer limited to pushes to `main`. `nightly.yml` has no timer trigger and runs only on dispatch. Refs #1483.
