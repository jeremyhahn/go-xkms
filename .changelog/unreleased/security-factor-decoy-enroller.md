- **Every auth factor issues decoy enrollments shaped like real ones** -- `piv`, `pkcs11`, `fido2` and `mtls` implement go-qrdb's `DecoyEnroller`. A login for a user who has no enrollment for a factor now gets a challenge that matches that factor's real ones, so it cannot reveal who holds which factor. Before, every factor fell back to go-qrdb's built-in mTLS decoy. Each decoy is derived from go-qrdb's decoy seed and the user id with HKDF-SHA256, so the same user always gets the same decoy. It follows the predominant shape of the factor's enrolled roster: key type and size, mechanism, slot, credential-id format, relying party, certificate profile. Its public key is valid, but no private key exists, so verification always fails.
