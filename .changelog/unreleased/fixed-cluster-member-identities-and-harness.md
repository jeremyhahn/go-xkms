- **A multi-node xkmsd cluster forms again on go-qrdb v0.25.x.** go-quicraft admits a Raft member by its identity and nothing else, and xkms had no way to pass one, so every multi-node boot failed with "no node identity in Config.MemberIdentities". `cluster.member_identities` (`XKMS_CLUSTER_MEMBER_IDENTITIES`, "nodeID=spki:<hex>" pairs) is mapped onto qrdb's `raft.member_identities`. Test: `pkg/server` `TestBuildXKMSQRDBConfig_ClusterFields`.
- **The cluster integration suite runs green against passphrase-barrier nodes.** The nodes boot sealed; the harness now initializes each node's barrier through its sealed window (allowed off loopback only on the private compose network), unseals a node it restarts, reads the first-boot admin credential from the datastore, finds node containers by compose project and service rather than a container name that never existed, sends `key_type` as the purpose with an explicit `algorithm`, and gives the standalone node a SAN for the name the suite reaches it by. The sealed-window client and the initialize/unseal calls are exported from `test/integration/xkmsdtest` (`SealedWindowClient`, `ReadBarrierState`, `InitializeBarrier`, `UnsealBarrier`, `OpenBarrier`) so the cluster harness reuses them rather than copying them.
