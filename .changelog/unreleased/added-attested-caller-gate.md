- **The attested-caller gate runs on the node.** `attestation.peer_gate: optional|required` (default `off`, standalone datastore only) installs `peergate.Gate` on the embedded go-qrdb node through `node.WithPeerAttestationGate`, with the embedder's policy from `server.WithAttestedCallerPolicy`; go-xkms ships no PCR golden values. Peer evidence moves from the per-process `MemoryStore` to `peergate.DAOStore` in the node's datastore (database `peergate`). Challenge and Submit are module verbs on REST (`/api/v1/peer-attestation/challenge`, `/evidence`), gRPC (`PeerAttestationChallenge`, `SubmitPeerAttestation`) and MCP (`peer.attestation.challenge`, `peer.attestation.submit`), granted to User and Operator and never gated themselves. Hosts of the xkms module install the same gate with `sdk/go` `WithAttestedCallerGate(policy)` and `PeerAttestationGate()`, and bind the module's storage to the node's service principal with `WithServiceModuleServiceContext(node.ServiceContext)`, without which a node that enforces authentication refuses it. Covered by gate on/off and required-refuses-unattested tests, DAO round-trip and eviction tests, and the verb permission goldens. SPEC: attested-caller-gate.
