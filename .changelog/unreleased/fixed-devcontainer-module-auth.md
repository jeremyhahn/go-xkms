- **Containers fetch private modules with the CI runner's credentials** -- the devcontainer and every integration compose file built their Gitea `insteadOf` rewrite from `GITEA_GO_TOKEN`, which only the gitignored `.devcontainer/.env` supplies, so on CI the rewrite carried an empty token and the nightly `make integration-test` failed on the first private module ("Failed to authenticate user"). The Makefile now resolves the credentials once (`GOMODAUTH_*`: the runner-injected `GIT_CONFIG_*` first, then `GITEA_GO_TOKEN`/`GITEA_HOST`, otherwise public resolution) for `stage-gomodauth`, the builder containers and every compose file. A compose file loaded directly by `devcontainer.json` still falls back to the `.devcontainer/.env` rewrite. `make devcontainer-module-env` prints the devcontainer's module resolution (GOPROXY, GOFLAGS, GOMODCACHE, GOPRIVATE, whether a fetch credential is set, never its value, and the cached first-party modules); the nightly runs it before the integration suite. Files: `Makefile`, `.devcontainer/docker-compose.yml`, `test/integration/*/docker-compose.yml`, `test/scripts/gomodauth.test.sh`, `.github/workflows/nightly.yml`.
