- **An archive outage no longer reddens a CI image build.** Every stage that runs `apt-get` in an image CI builds now installs one shared apt configuration, `build/docker/devcontainer/apt-retries.conf`, before its first `apt-get`, or inherits it from the stage it is built `FROM`. That covers the devcontainer `Dockerfile`'s tools, native, base, toolchain and devcontainer stages, `Dockerfile.softfido` and `Dockerfile.virt-piv`, `Dockerfile.cli` (built by the image job on every pull request), and the root `Dockerfile` and the backend test images under `test/integration/` (built by the full-tier integration job's `make integration-test`). The configuration retries each failed fetch ten times with exponential backoff capped at 60 s and bounds each connect and stalled transfer at 30 s, replacing the five-retry setting the devcontainer `Dockerfile` wrote inline in three stages. The file is a `TOOLCHAIN_INPUTS` entry, so changing it rebuilds the toolchain image. New `internal/buildgates/apt_test.go` (`make test-buildgates`) fails an apt layer in those Dockerfiles that runs before the shared file is installed, sets apt options inline or splits `apt-get update` from the install, and one that installs recommends where its Dockerfile otherwise uses `--no-install-recommends`. It also fails the shared file when a retry or timeout setting is missing or disabled. Closes #342.
