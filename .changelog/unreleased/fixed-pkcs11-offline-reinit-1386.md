- **The offline PKCS#11 module initializes again after `C_Finalize`, and raw `CKM_ECDSA` signs on in-process keys** — `libxkms_pkcs11.so` in offline mode (`XKMS_PKCS11_MODE=local`) answered `CKR_DEVICE_ERROR` to a `C_Initialize` that followed `C_Finalize`: `Module.Finalize` drops the embedded client the library injected, and `C_Initialize` rebuilt the offline module only when no global module existed, so the finalized module fell back to dialing the default remote target. PKCS#11 v3.2 §5.4 allows re-initialization, and `p11-kit server` always performs it (a probe initialize/finalize, then the RPC client's initialize), so no p11-kit-hosted deployment could come up. `cmd/pkcs11-module` now records the module it built and rebuilds it under one lock when that module has been finalized; a module a Go caller installed (xkey) is still initialized as it is and never replaced. Separately, a raw ECDSA signature (hash `NONE`, PKCS#11's `CKM_ECDSA`, which strongSwan's pkcs11 plugin uses) failed on every in-process key with `ecdsa: Sign must be called with a hash, not with crypto.Hash(0)`, because Go 1.27's `ecdsa.PrivateKey.Sign` refuses a zero hash identity; `signWith` now signs a raw digest on an `*ecdsa.PrivateKey` through `ecdsa.SignASN1`, which accepts a digest of any length and truncates it to the curve order as PKCS#11 v3.2 §6.3.4 requires. The other signers were audited: the PKCS#11 signer issues raw `CKM_ECDSA` itself; the TPM2 signer infers the scheme hash from a 32/48/64-byte digest and refuses any other length with the typed `ErrSchemeHashUnresolved`/`ErrUnsupportedOperation`; AWS KMS and GCP KMS refuse a zero hash with their typed `ErrInvalidAlgorithm`. Azure Key Vault's signer ignored the zero hash and always sent ES256, so a raw digest on a P-384 key failed remotely. It now takes the algorithm from the key's curve (P-256/ES256, P-384/ES384, P-521/ES512) and refuses a digest of another length with the new typed `ErrRawECDSADigestUnsupported` before any request is sent. Tests: `TestCInitialize_OfflineReinitializesAfterFinalize` (both seal strategies: initialize, generate a P-256 token key, sign and verify, finalize, initialize, find the key, sign and verify), `TestCInitialize_OfflineLeavesInjectedModuleInPlace`, `TestCInitialize_OfflineBuildFailureIsDeviceError`, `TestSignDigest_*`, `TestSign_RawECDSA_ThroughService` (32/48/64-byte digests through the service), `TestOffline_RawCKMECDSA` (raw `CKM_ECDSA` sign and verify on P-256 and P-384 with 32/48/64-byte digests in offline mode; a changed digest fails), `TestRawECDSAAlgorithm` and `TestSigner_RawECDSA` (azurekv).
