- **TPM key blobs persist as go-qrdb DAO records** -- every TPM object artifact (public and private area, saved context, policy record, certificate) is one `TPMBlob` entity in the `tpm2` database, with natural key `<tenant>/<CN>/<ext>`, an ID derived from it and lookups by it. `pkg/tpm2/store.NewBlobStore(logger, daos)` takes the injected DAO factory (SDK: `NewTPMBlobStore`, `TPMBlobStore`, `TPMBlobDatabase`); `NewBackendBlobStore` keeps the same entities over a `storage.Backend` that supports guarded writes (SDK: `NewTPMBackendBlobStore`), and `BlobStore.Tenant` gives each tenant its own store, replacing the tenant-prefixed `tpm-keys` storage. `tpm2.Config.KeyStorage` is now `Keys *store.BlobStore` (`ErrKeyStorageRequired` is now `ErrKeysRequired`), `compose.TPMPolicyParams` and the TPM policy feature no longer take a `Storage`, and `store.FileBackend`, `FSBlobStore`, `BlobStorer`, `NewFactory`, `FileCertStore` (now `BlobCertStore`) and `backend/tpm2.NewFileKeyBackend` are removed, along with the SDK's `NewTPMFactory`, `NewFileBackend` and `TPMBlobStorer`. xkmsd keeps the general TPM2 backend's blobs in the datastore's `tpm2` database, behind the barrier; only the node-barrier seal key stays in the pre-barrier key directory. A server that asks for a database before its datastore is open now fails with `ErrNoDatastore` instead of panicking. Blobs written by the old layout are not read.
