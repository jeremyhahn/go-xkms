- **BREAKING: factor proofs bind go-qrdb's ChallengeMessage** (#1684). The `mtls`, `pkcs11` and `piv` factors no longer verify a signature over SHA-256 of the bare nonce. They verify a signature over `qrdbsdk.QuorumChallengeMessage(ChallengeID, purpose, Nonce)`, built by the new `pkg/factor/internal/challenge.Message`. The purpose is `MethodData[qrdbsdk.QuorumChallengePurposeKey]` (`""` when none), the same value go-qrdb's own `mtls` factor reads. A proof therefore binds the challenge ID and the quorum purpose, and a proof made for one purpose no longer answers a challenge for another with the same nonce. Each of the three factors now refuses a challenge with an empty nonce. The prover is `qrdbsdk.SignQuorumChallenge`. `piv.Factor.SignNonce` is replaced by `SignChallenge(ctx, slot, challengeID, purpose, nonce)`, which refuses an empty nonce with the new `EmptyNonceError`. There is no compatibility path: a signature over the bare nonce is refused. The `fido2` factor is unchanged, because its WebAuthn challenge is the nonce. Docs: `docs/auth-factors/api.md`, `docs/auth-factors/engineering.md`.
