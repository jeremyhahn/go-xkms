- **`xkey device relay` pinned nothing, `xkey device listen`/`relay` served the full xkmsd bridge on Noise static-key possession alone with no liveness proof, and `remote.syncPasswords`/`syncOATH`/`syncAll` exported the password vault and OATH secrets to any paired phone with no desktop approval** (#1306). Four gaps found auditing the phone-pairing protocol against its own docs, closed by reusing the existing Noise/attestation/bridge primitives rather than a new mechanism.
  - `xkey device relay` generated a fresh, unpinned Noise static key every invocation and bound `:8444` on every interface; a phone holding *any* Noise key could complete the handshake, and it never served the xkmsd bridge at all (no `RequestHandler`). It now pins to a specific already-paired device (required `--device` resolution shared with `listen`), reuses that device's own persistent local/remote static keys, binds `127.0.0.1:8444` by default (an explicit non-loopback `--listen` opts into network exposure), and wires the identical request handler and xkmsd bridge `xkey device listen` uses. `phone.TCPPairingConfig` gained `ExpectedRemoteStatic` (mirroring `BLEPeripheralConfig`'s existing pin, refused at construction if set to anything but a full-length key: `ErrTCPServerInvalidPin`) so the pin is enforced by the Noise handshake itself, not merely by configuration intent.
  - A phone-initiated session (`xkey device listen`'s BLE peripheral and, now, `xkey device relay`'s TCP responder) served every `remote.*` method immediately after the Noise handshake, with no re-attestation — unlike a laptop-initiated connection, which `PhoneKeyBackend.Connect` already proves liveness on via the #129 challenge-response protocol. Both `phone.TCPPairingConfig` and `phone.BLEPeripheralConfig` now carry a required `LiveAttest pairing.LiveAttestFunc`: immediately after the handshake and before any request reaches the handler, the responder sends `local.attestDevice` to the phone over the same connection (`pairing.InlineExchange`, a minimal single-exchange request/response built from each transport's raw send/receive primitives) and requires a verified answer. A `nil` `LiveAttest` refuses every connection (`ErrLiveAttestationUnavailable`) rather than silently skipping the check; both CLI commands wire `newLiveAttestor`, the same verifier constructor the initiator path already used.
  - `pairing.Bridge` now requires a `SyncApproval pairing.SyncApprovalFunc` to serve `remote.syncPasswords`, `remote.syncOATH` or `remote.syncAll` — the three methods that export the local password vault or OATH credentials to the phone (`remote.syncTrustStore` and `remote.syncStatus` are unaffected; they carry no secrets). A `nil` approver refuses all three (`ErrSyncApprovalRequired`); a configured approver that declines refuses with `ErrSyncNotApproved`. `xkey device listen`/`relay` wire a new session-level approver (`newSessionSyncApproval`) gated by a new `--allow-sync` flag, one decision made at session start rather than a per-request prompt (both commands run as a foreground daemon with no UI thread to interrupt per request); `xkey fido2`'s phone bridge wires `nil`, since it has no equivalent opt-in flag. A new enterprise policy pair, `policy.phone_sync_allow_secret_export` / `policy.lock_phone_sync_policy` (`PhoneSyncAllowSecretExport`/`LockPhoneSyncPolicy` in `pkg/config.PolicySection`), can lock the decision either way under the existing SO-PIN-sealed policy mechanism, mirroring `PairingAllowUnattestableDevices`/`LockPairingAttestationPolicy`'s precedent exactly (`allowPhoneSyncExport`).
  - `xkey device pair` now derives a short authentication string (SAS) from the #129 attestation channel binding (`pairing.ShortAuthString`, three four-digit groups) and prints it after the handshake, for the operator to compare against what the phone shows — informational only today, since the Android app does not yet display a matching code; see the docs below for exactly what it must compute and show.
  - Several helpers that had no Bluetooth dependency of their own were moved out of `ble`-tagged files into shared, untagged ones so `xkey device relay` (which needs none of them) compiles and works without `-tags ble`: barrier open/seal (`device_barrier_shared.go`), the enterprise-policy resolver and attestation-trust loader (`device_pairing_policy_shared.go`), the local-key unseal/live-attestor constructor (`device_session_shared.go`), the sync-service opener (`device_sync_shared.go`), and the phone-initiated request handler/bridge wiring, now shared by `listen`, `relay`, and `xkey fido2`'s phone bridge (`device_listen_handler.go`).
