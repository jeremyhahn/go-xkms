- **Two concurrent first signing calls of a tenant on a tenant-scoped TPM backend both sign with one release key, and the signing verbs classify key-policy refusals.** The TPM backend refuses to generate over an existing release key with a blob-exists error, not `ErrKeyAlreadyExists`; release-key provisioning now treats it as the key the other call made, so the second call signs with that key instead of failing with `ReleaseKeyProvisionError`. A `SignCoRIM` or `SignImage` refused by the key's policy, or by a disabled or revoked key, is now gRPC `PermissionDenied` or `FailedPrecondition`, REST 403 or 409 and the matching MCP error, as on the key management API, instead of an internal error (go-xkms#1956).
