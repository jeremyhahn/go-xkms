- **Two concurrent first signing calls of a tenant on a tenant-scoped TPM backend both sign with one release key, and the signing verbs classify key-policy refusals.** The TPM backend refuses to generate over an existing release key with a blob-exists error, not `ErrKeyAlreadyExists`; release-key provisioning now treats it as the key the other call made, so the second call signs with that key instead of failing with `ReleaseKeyProvisionError`. On any collision, including two software-backend instances sharing storage, which publish the key before its tenant record, the losing call now waits up to a few seconds, within its context, until the winner's key resolves for the tenant, instead of failing its first signature with `ErrKeyNotFound`; a key that never resolves fails with a `ReleaseKeyProvisionError` wrapping `ErrKeyNotFound`. A `SignCoRIM` or `SignImage` refused by the key's policy, or by a disabled or revoked key, is now gRPC `PermissionDenied` or `FailedPrecondition`, REST 403 or 409 and the matching MCP error, as on the key management API, instead of an internal error (go-xkms#1956).
