- **A backend-backed SSH key's owner and name could collide on another key's backend CN within the same tenant partition, letting one address overwrite another's private key material.** `backendKeyID` (`pkg/ssh/keys/generate.go`) built the CN as `"ssh-" + strings.ReplaceAll("<scope>/<owner>/<name>", "/", "-")`. That flattening is not injective once `owner` or `name` already contains a `-`: `owner="a-b", name="c"` and `owner="a", name="b-c"` both produced `"ssh-user-a-b-c"`, so generating the second address's key silently reused, and could overwrite, the first's backend key object. `backendKeyID` now hex-encodes `owner` and `name` independently and joins `"ssh-" + scope + "-" + hex(owner) + "-" + hex(name)` with `-`; `hex.EncodeToString` only ever emits `[0-9a-f]`, so a `-` in the result can only be one of the three literal separators the function writes, making the join unambiguous for any bytes `owner`/`name` contain. `scope.BuildKeyID` is still called first, purely for its existing validation, so the error types callers already handle (`*scope.ScopeInvalidError`, `*scope.KeyIDMalformedError`) are unchanged. The encoded CN is refused with a new `*keys.BackendKeyIDTooLongError` rather than truncated if it would exceed 255 bytes — the same limit `pkg/validation.ValidateKeyID` enforces on every other xkms key identifier, chosen so truncation can't reintroduce the same kind of collision. Pre-release: existing collisions are not migrated; any key generated under the old encoding is addressed by its old CN and readable, but a fresh `GenerateOnBackend` call for the same `(scope, owner, name)` now always produces the new CN.
  - Files: `pkg/ssh/keys/generate.go`, `pkg/ssh/keys/errors.go`.
  - Verified by `pkg/ssh/keys/backend_keyid_test.go` (`TestBackendKeyID_InjectiveAcrossHyphenBoundary` reproduces the exact reported collision; `TestBackendKeyID_PropertyNoCollisions` sweeps adversarial owner/name fragments for collisions; `FuzzBackendKeyID_Injective` fuzzes owner/name pairs for injectivity; `TestBackendKeyID_StaysWithinBackendConstraints` and `TestBackendKeyID_TooLong` cover the character-set, length and refusal contracts) and the end-to-end regression `pkg/ssh/tenancy/client_test.go`'s `TestBackendKeys_DistinctAddressesDoNotCollide` (generates, signs and `Get`s both previously-colliding addresses through the real software backend and proves each signature verifies only under its own key).
