- **PINs and Seal/Unseal passwords cross the transports as `types.SecretBytes`** -- `PIVSignRequest.PIN`, `ImportPIVKeyRequest.PIN` and the password fields of the Seal and Unseal requests are `types.SecretBytes` (exported through `sdk/go` as `SecretBytes`) instead of `string`, in the transport types and in the REST, MCP and protobuf conversions, so a PIN or password is never a Go string that cannot be wiped. The JSON form is byte-identical, so existing clients and stored requests are unaffected; Go callers pass `[]byte`-backed values, and the consumer of a request wipes the PIN it carried on success and on every refusal. The gRPC `SealRequest.password` and `UnsealRequest.password` fields change from `string` to `bytes` for the same reason; both are length-delimited on the wire, so existing gRPC clients interoperate unchanged, and the generated `xkms.pb.go` is regenerated for those two fields only. Part of #1398.
