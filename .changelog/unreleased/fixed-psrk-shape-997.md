- **The Platform SRK's shape now agrees between the simulator first-boot backend autodetect and the operator enrollment ceremony** (#997). `pkg/backend/tpm2/config.go`'s `ToTPMConfig` hardcoded `PlatformPolicy: false` into the `PlatformSRKConfig` it built, so a Platform SRK created by `provisionSimulatorEKSRK`'s first-boot recipe carried no PCR-policy `AuthPolicy` in its template at all -- disagreeing with the always-`PlatformPolicy: true` PSRK `pkg/tpm2`'s enrollment path (`PlatformKeyStore.Initialize`/`EnrollPlatformSRK`, and `DefaultConfig`) has created since #677 settled the design (`authValue` = user PIN, `authPolicy` = platform PCR policy). `pkg/server/platform_store.go`'s `buildTPM2PlatformSealer` papered over the mismatch by forcing the `KeyAttributes` it returned to `PlatformPolicy: true` regardless of what the TPM object actually was, so a Platform SRK backend-probed on a fresh simulator authorized through the wrong compound-policy branch and every `Seal`/`Unseal` against it failed.
  - `ToTPMConfig` now always sets `PlatformSRK.PlatformPolicy: true`, matching `pkg/tpm2.DefaultConfig`; there is no plain-password shape for the Platform SRK to fall back to.
  - `buildTPM2PlatformSealer` no longer overrides `PlatformSRKAttributes()`'s resolved `PlatformPolicy` -- it already derives correctly from configuration (`pkg/tpm2/key.go`'s `PlatformSRKAttributesFromConfig`), and forcing it masked exactly this kind of shape mismatch instead of surfacing it.
  - `CreateSRK` needed no change: it already derives the AuthPolicy baked into a Platform SRK's template from the live platform PCR at creation time (`capturePlatformPolicyPin`), independent of whether `CreatePlatformPolicy` has run -- both the simulator autodetect path and the enrollment path already relied on this and never called `CreatePlatformPolicy` first, so making both agree on `PlatformPolicy: true` is sufficient for them to derive identical `AuthPolicy` digests from the same PCR state.
  - Verified with a new `pkg/backend/tpm2` test that provisions a Platform SRK through each path independently and asserts their persisted `AuthPolicy` digests match, a PIN-branch round trip proving key operations under an enrolled Platform SRK still work, and a `pkg/server` fresh-probe Seal/Unseal round trip through `buildTPM2PlatformSealer` -- the path this bug actually broke and that no existing test exercised end to end.
