- **The platform policy seals to the board's boot PCRs, set once in `TPMConfig`** — the sealing PCR set is now `PlatformPCRs` (`tpm2.PCRSet`) in the one `tpm2.PlatformPCRSelection` embedded in `tpm2.Config`, defaulting to PCRs 7 and 11 and configurable per board; it replaces `PlatformPCR` and `DefaultPlatformPCR` (the resettable debug PCR 16). xkmsd's `backends.tpm2.platform-pcrs` (`XKMS_BACKENDS_TPM2_PLATFORM_PCRS`, replacing `platform-pcr`), `pkg/backend/tpm2.Config`, xKey's `tpm.platform-pcrs` and `--platform-pcrs`, and the SDK's `xkms.TPMPCRSet` / `xkms.DefaultPlatformPCRs` all carry the same type. Config load and `NewTPM2` refuse an empty set, duplicates, indexes above 23 and the resettable PCRs 16 and 23 with typed errors (`ErrPlatformPCRSetEmpty`, `ErrPlatformPCRDuplicate`, `ErrPlatformPCROutOfRange`, `ErrPlatformPCRResettable`, each in a `*PlatformPCRError`). xKey's config load refuses an invalid `tpm.platform-pcrs` (`XKEY_TPM_PLATFORM_PCRS`) the same way, and the GUI no longer warns and falls back to `{7, 11}`: it refuses to open the TPM. The CLI `tpm` commands seal to `tpm.platform-pcrs`, and `--platform-pcrs` overrides it. The platform policy pin records the set as a `PCRSelect` bitmap. Objects sealed under the old PCR 16 policy are not migrated (pre-release, no compatibility path). Simulator test `TestSealUnseal_BoardPCRSet_BindsOnlyConfiguredPCRs` shows a board set binds only its own PCRs (#1551, #1443).
