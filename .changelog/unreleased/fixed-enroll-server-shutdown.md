- **`Client.EnrollDevice` and `Client.DeviceAttest` now release the enroll-01/device-attest-01 challenge port before returning, on every path** (go-xkms#1125). `startEnrollServer`/`startAttestServer` ran `server.ListenAndServe()` in a `go` statement launched fire-and-forget, so a bind failure was only ever logged (`"HTTP server error"`), never returned, and no code anywhere held a reference to the `*http.Server` to shut it down -- the listener outlived the enclosing `EnrollDevice`/`DeviceAttest` call for the rest of the process's life. A long-running agent (or a test binary running more than one enrollment) that enrolled a second device found its own first enrollment still holding the port, surfacing as an unrelated-looking `listen tcp :8080: bind: address already in use` several steps into the second attempt instead of at its actual cause.
  - Added `challengeServer` (`pkg/acme/client/enrollment.go`): `newChallengeServer` binds the listener synchronously via `net.Listen` before returning, so a port conflict is reported immediately as a typed `*caerrors.TrustedCAError` (`caerrors.ConnectionFailureError`) instead of surfacing later as an opaque authorization timeout. `shutdown` is idempotent, nil-receiver safe (so it can be deferred unconditionally), and blocks until both `http.Server.Shutdown` returns and the `Serve` goroutine has exited, guaranteeing the port is free the instant it returns.
  - `startEnrollServer` and `startAttestServer` now build their mux and delegate to `newChallengeServer` instead of calling `ListenAndServe` directly; both return `(*challengeServer, error)`. `EnrollDevice` and `DeviceAttest` call them synchronously (no more `go` statement, no more `time.Sleep(100 * time.Millisecond)` "give it time to start" guess -- the synchronous bind makes that wait unnecessary), check the returned error, and `defer` a `shutdown()` that runs on every return path. Because each authorization in the loop reuses the same configured address, a prior iteration's server (a second `authzURL` on one order) is shut down before the next is started, rather than only at function return.
  - Files: `pkg/acme/client/enrollment.go`.
  - Tests (`pkg/acme/client`): `TestNewChallengeServer_BindsAndReleasesPortOnShutdown` and `TestChallengeServer_Shutdown_NilAndDoubleSafe` exercise `challengeServer` directly. `TestNewChallengeServer_PortInUse_ReturnsTypedErrorPromptly` occupies the port first and asserts the typed error returns in well under a second. `TestEnrollDevice_ReleasesPortOnSuccess` and `TestEnrollDevice_ReleasesPortOnMidFlightFailure` drive `EnrollDevice` through a full enroll-01 round trip against a mock ACME server (the latter forced to fail at the `len(certChain) < 2` check, after the challenge server has already bound and served) and assert a probe listener can bind the configured port immediately after `EnrollDevice` returns, on both the success and the failure path. `TestEnrollDevice_ChallengeServerBindConflict_ReturnsTypedErrorPromptly` pre-binds the configured port and asserts `EnrollDevice` returns the typed bind error before `WaitAuthorization`/`WaitOrder` would ever run.
  - This is the root cause behind the acme-tpm CI lane's `TestEnrollment_ConcurrentRequests` and `TestEnroll01_CompleteWorkflow` failures tracked in `fixed-acme-tpm-ci-lane-1125.md`: both share the server's hardcoded port-8080 default with `TestEnrollDevice_CompleteWorkflow`, which ran first and, before this fix, never released it. No lane changes were needed -- `test/integration/acme-tpm/enroll01_integration_test.go`'s own `startChallengeServer` helper already binds synchronously with a bounded retry and `require.NoError`; its retry budget just could not out-wait a port this library never released.
