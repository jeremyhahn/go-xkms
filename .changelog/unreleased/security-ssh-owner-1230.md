- **High: a tenant Admin could list, sign with, delete and plant authorized_keys entries for other tenants' and other users' SSH keys, on every transport.** REST, gRPC and MCP passed the request's `scope` and `owner` straight to the shared embedded SSH client, and the RBAC gate binds the caller's own tenant, so it could not see them. Tests against the old code confirmed every attack: tenant A named `scope=tenant, owner=B` or `scope=user, owner=<another user>` and got B's keys listed, B's public key exported, a signature from B's key, B's keys and authorized_keys entries and known-hosts pins deleted, and new keys, authorized_keys entries and pins written under B. The single flat store also let `alice` in tenant A reach `alice` in tenant B's `user/alice` keys, since a subject is unique only within a tenant. Backend-backed keys of equal names in two tenants shared one backend key name. Every transport now calls one SSH service, `pkg/ssh/tenancy`, which `xkmsd` builds in `ensureSSHClient`. A tenant-scoped caller may address `scope=tenant` only with its own tenant ID as the owner, and `scope=user` or `scope=service` only with its own subject. A platform identity (no identity or the system tenant) may address any owner. A refused read or delete answers exactly as a missing asset: the same REST `404`, gRPC `NotFound` or MCP `JSONRPCCodeNotFound`, with the same body. A refused write gets the not-found for the address it names, and nothing is written or generated. Listings return only what the caller owns, whatever filters they carry. Each tenant's SSH assets live in their own partition (`tenants/<tenant-id>/` under the `ssh` storage view), and their backend keys are generated and resolved with the tenant's `KeyAttributes.TenantID`. A platform identity reaches a tenant's `scope=tenant` assets in that tenant's partition, and otherwise the platform partition, which is the unprefixed view.
  - **REST permissions are now per verb:** `ssh:read` to read, `ssh:write` to create, `ssh:delete` to remove, and `ssh:use` to sign. Before, every SSH route gated on `ssh:use`, so a signing grant also deleted keys and added authorized_keys entries. MCP and gRPC keep their existing gates; they still gate signing on `ssh:write`.
  - **Breaking:**
    - A tenant-scoped caller using `xkmsctl ssh`'s default `--owner default` is now refused. It must pass its own subject, or its tenant ID for `--scope tenant`.
    - SSH assets that tenant-scoped callers created before this change sit in the platform partition, and those callers can no longer see them. There is no migration; recreate them.
