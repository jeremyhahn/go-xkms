- **The xkey IPC server now checks who is connecting, and `sudo xkey fido2` now resolves the same socket as the invoking user's desktop clients.** Before this change, `xkey/pkg/ipc/server.go` served every connection it accepted. The `0700` socket directory and `0600` socket file were its only access control, so any process that could reach the socket could ask for PKCS#11 signatures, stored passwords and autofill secrets. The server now checks every accepted connection before reading anything. It uses the same kernel peer-credential check (`verifyPeer`) and the same trusted set (`trustedUIDs`: this user, root, and the sudo user) as the client. `verifyPeer` now also returns the peer's uid. An untrusted client is closed without a response and logged at `Warn` with its `peer_uid`. On platforms where xkey reads no peer credentials (anything other than Linux, macOS and FreeBSD), the server drops every connection, the same way the client already refuses to connect (go-xkms#1137). Separately, sudo strips `XDG_RUNTIME_DIR`, so a daemon started with `sudo` fell back to `~/.xkey/run` while the invoking user's clients looked under `$XDG_RUNTIME_DIR/xkey/`, and the two never met. Under sudo (root with `SUDO_UID` set) and with `XDG_RUNTIME_DIR` unset, `runtimeDirFor` now picks `/run/user/$SUDO_UID` when that directory exists, is not a symlink, is owned by `SUDO_UID` and has mode `0700`. Otherwise it keeps the previous fallback (go-xkms#1138). **Behaviour change:** a client running as any user other than the server's user, root or the sudo user is now refused even if the socket's permissions would admit it.
