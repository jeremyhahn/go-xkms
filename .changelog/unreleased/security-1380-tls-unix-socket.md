- **xkmsd's unix socket speaks TLS and authenticates every caller** -- the plaintext unix gRPC listener and the qrdb control plane it hosted are gone; the socket is now the embedded qrdb node's TLS unix listener, which serves the xkms module and qrdb's own services through the same authentication chain as every network transport, so an anonymous caller is refused. `protocols.unix` therefore requires `tls.enabled` (the bootstrap certificate serves when no cert files are set; it names localhost only with `tls.include_localhost_sans`), and the `unix.enabled`, `unix.socket_mode` and `unix.protocol` keys are removed. `xkmsctl` (including `cluster`, `rebalance` and `auth factor`) dials `unix://` with TLS and its `--tls-cert`/`--tls-key`/`--tls-ca` flags, and `cluster` and `rebalance` present `--token` as a bearer on every control-plane RPC, so a token with `--tls-ca` and no client certificate authenticates (a token is refused for plaintext `grpc://`); the PKCS#11 module needs `tls_enabled` with `tls_cert`/`tls_key`/`tls_ca` to reach xkmsd. The sign server's socket is unchanged (go-xkms#1380).
