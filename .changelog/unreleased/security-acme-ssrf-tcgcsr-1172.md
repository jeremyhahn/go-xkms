- **ACME challenge validation can no longer be aimed at the server's own network, and a hostile TCG-CSR-IDEVID can no longer make the CA allocate gigabytes** (#1172). A `permanent-identifier` was validated only as non-empty and `enroll-01` built its target with `fmt.Sprintf("http://%s:%s%s%s", ...)`, so an identifier such as `169.254.169.254/latest/meta-data/#` chose the host, port and path of a server-side GET and POST; `http-01` had no private-address filter; both read responses with an unbounded `io.ReadAll`; and the challenge's `error.detail` echoed the dial error or status code back, making the challenge a port and reachability oracle. The response then fed `tpm2.UnmarshalIDevIDCSR`, which called `make([]byte, n)` for fifteen attacker-chosen 32-bit lengths before checking what the message held.
  - New `pkg/acme/challenges/validation.Client`, the one HTTP client `http-01`, `enroll-01` and `device-attest-01` use: a bare hostname/IP target only (`policy.ValidateNetworkTarget`), URLs assembled with `url.URL` + `net.JoinHostPort`, a `net.Dialer.Control` hook that refuses every `policy.IsReservedIP` address (loopback, RFC 1918/4193, link-local incl. metadata, multicast, unspecified, CGNAT, TEST-NETs, NAT64, 6to4; IPv4-mapped unmapped) after DNS resolution, so rebinding is refused too; no proxy; `http-01` follows at most 10 http/https redirects with every hop re-checked, the others refuse redirects; responses capped with `io.LimitReader` (64 KiB default, the base64url size of a 1 MiB TCG-CSR for the `enroll-01` fetch) and refused, not truncated, when over.
  - New `acme.challenges.allow_private_targets` (`XKMS_ACME_CHALLENGES_ALLOW_PRIVATE_TARGETS`, default false) is the only way to reach a reserved target, for test lanes and private-network labs.
  - `ChallengeHandler` logs and audits the verifier's full error but returns a fixed category (`connection` "Challenge validation failed: connection failed" / "unexpected HTTP status" / "response too large" / "redirect not permitted", or `incorrectResponse` "Challenge validation failed"); a refused target reads the same as any connection failure.
  - `policy.ValidatePermanentIdentifier` (UTF-8, at most 1024 bytes, no whitespace or control characters) replaces the non-empty check; the value stays opaque per the ACME device-attestation draft, and the hostname/IP requirement applies where it is dialed.
  - `pkg/tpm2`: `UnmarshalIDevIDCSR` refuses input over `MaxIDevIDCSRSize` (1 MiB) and bounds every length field, signature included, by the bytes remaining before allocating (`*IDevIDCSRTooLargeError`, `*IDevIDCSRFieldSizeError` wrapping `io.ErrUnexpectedEOF`); `UnpackIDevIDCSR` refuses a size field larger than its slice before allocating (`store.ErrCorruptCopy`); `ParseEventLog` bounds each event at `MaxEventDataSize` (1 MiB, `*EventDataTooLargeError`).
  - Breaking (pre-release): `http01.Verify`, `enroll01.Verify` and `deviceattest01.Verify`/`VerifyAttestation` take a `*validation.Client` instead of a `*net.Resolver`; `sdk/go/acme.ACMEAttestationVerifiers` takes the client as its first argument. The SDK re-exports `ACMEChallengeClient`, `ACMEChallengeClientConfig`, `NewACMEChallengeClient`, `MaxIDevIDCSRSize`, `IDevIDCSRTooLargeError` and `IDevIDCSRFieldSizeError`.
