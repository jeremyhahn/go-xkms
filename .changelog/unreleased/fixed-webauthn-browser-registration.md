- xkmsd's WebAuthn registration no longer answers `internal_error`: the WebAuthn user store's calls into the embedded qrdb node run as the node's service principal, where the request context carried none and qrdb refused them as unauthenticated.
- The node's service principal holds `users:read`, `users:create`, `users:update` and `users:delete`, the qrdb users calls the WebAuthn user store makes, where qrdb denied a registering user's lookup as `cannot read on users`.
- xkmsd's WebAuthn registration finish no longer answers `internal_error` after saving the credential: the token issuer's qrdb refresh store writes the first token pair as the node's service principal, where the anonymous request's context was refused as unauthenticated.
- `POST /api/v1/auth/refresh` no longer refuses a valid refresh token minted by a passkey registration: the refresh user re-check's qrdb lookups run as the node's service principal (`TokenIssuerParams.CallContext`), where the public endpoint's anonymous request context was refused as unauthenticated; the re-check still refuses a disabled or deleted account.
- `POST /api/v1/auth/refresh` no longer refuses every PIV/mTLS session of a holder outside the system tenant: xkmsd's refresh user re-check resolves the subject on the embedded node's user service in the refresh token's own tenant (`TokenIssuerParams.UserLookup`), where the system-tenant service principal was refused reading a user in another tenant; a subject claimed in another tenant still does not resolve.
