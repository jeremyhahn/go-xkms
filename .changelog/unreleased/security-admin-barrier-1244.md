- **A tenant administrator can no longer operate the system barrier through the ACME admin plane (#1244).** The `/admin/barrier/*` routes ran their own barrier client, so #1227's platform-scope check on the XKMSService barrier methods never applied to them. qrdb grants a tenant's own Admin, SO and Custodian roles every `seal:*` / `barrier:*` permission these routes declare. A tenant-A administrator therefore passed the permission gate on all eleven routes: status, initialize, seal, unseal, Shamir initialize, unseal-share, rekey, recovery-key generation, recovery, recovery-key status and root-token generation. It could seal the barrier that protects every tenant, re-initialize it, rekey it, replace the recovery quorum or mint a root token. The admin barrier service now holds no barrier of its own. It runs every operation through `SystemBarrier`, the XKMSService's system-barrier methods, so `requirePlatformScope` refuses a tenant-scoped caller before the barrier is touched. The refusal is answered like the admin plane's other platform-only routes (tenant creation, the audit trail): `403` with the gate's own denial body. The platform identity keeps the barrier. xkmsd now mounts the barrier routes on its admin router over the server's XKMSService, so the admin SPA's Seal Manager reaches them. They were previously unmounted there. A server with no composed XKMSService is refused at start-up (`ErrAdminXKMSServiceRequired`). The admin plane's unused remote barrier mode (`BarrierModeRemote`, `BarrierRemoteModeError`) is removed. `mode` is now always `embedded`, and a barrier that is not initialized now answers `409` rather than `500`. `pkg/server.Server.XKMSService` is now exported.
