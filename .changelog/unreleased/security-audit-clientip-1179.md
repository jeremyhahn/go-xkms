- **The ACME audit trail's source IP can no longer be forged, and an IPv6 client can no longer evade a rate limiter by rotating within its own /64** (#1179). `audit.extractClientIP` believed `X-Forwarded-For` from any caller and recorded the raw header value verbatim, so any client could forge the audit trail's source IP (and pad it without bound); separately, every rate limiter bucketed IPv6 clients on their full address, which an ISP-delegated /64 lets a single client rotate through freely.
  - `pkg/acme/audit` now resolves the recorded source IP through the same `ratelimit.TrustedProxies.ClientIP` (`pkg/ratelimit/clientip.go`) the REST and ACME rate limiters use: the transport peer without its port, or, only when that peer is a configured trusted proxy, the right-most untrusted `X-Forwarded-For` hop. `audit.SetTrustedProxies` wires it from the one `server.trusted_proxies` config key; `cmd/xkmsd/acme.go`'s `startACMEServer` parses that key once and hands the result to both `acmeserver.TrustedProxies` (the ACME rate limiter's own resolver, previously never wired from config in production) and `audit.SetTrustedProxies`, so a forwarding header is trusted, or not, identically for rate limiting and for the audit trail. Audit records keep full address precision.
  - `ratelimit.RateLimitKey` folds a resolved client address into a rate-limit bucket key: unchanged for IPv4, masked to its `/64` for IPv6, unchanged for a non-IP value (a JWS key ID). `ratelimit.Middleware` (REST) and the ACME rate limiter's `rateLimitClientIPKey`/`rateLimitClientIDKey` (every `*RateLimiter`/`*TenantRateLimiter` constructor) apply it when building their bucket key; `ClientIP`/`ClientID` themselves are unchanged and still resolve the full-precision address.
