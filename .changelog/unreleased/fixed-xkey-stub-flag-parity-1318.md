- **xkey's non-BLE build now registers every flag the BLE build does for commands that ship a `!ble` stub** (#1318). Each stub (e.g. `backup_device_stub.go`) had its own copy of `init()`'s flag registration, hand-kept in sync with its `ble`-tagged counterpart (e.g. `backup_device.go`) — and it had drifted: `backup from-device` was missing `--key-stdin` in the non-BLE build, and `device scan` registered no `--timeout` flag at all. Flag registration for every such command pair (`backup to-device`/`from-device`, `device attest`, `device listen`, `device pair`, `device scan`, `oath sync`/`push`/`pull`, `piv phone-list`/`phone-push-cert`/`phone-pull-cert`/`phone-generate`, `device share`/`import`, `device sync`/`sync-status`/`sync-push`/`sync-pull`) now lives in a single untagged `registerXxxFlags` function called by both the `ble` and `!ble` implementations, so the two flag sets cannot drift again. Two flags that existed only on one side and were dead code were dropped for the same reason: `device attest --verbose` (stub-only, never read) and the `device.listen.*`/`device.sync*.*` viper bindings the stub registered but the `ble` build never did.
  - Files: `xkey/cmd/xkey/cmd/backup_device_flags.go`, `device_attest_flags.go`, `device_listen_flags.go`, `device_pair_flags.go`, `device_scan_flags.go`, `device_oath_sync_flags.go`, `device_piv_sync_flags.go`, `device_share_flags.go`, `device_sync_flags.go` (new); `backup_device.go`, `backup_device_stub.go`, `device_attest.go`, `device_attest_stub.go`, `device_listen.go`, `device_listen_stub.go`, `device_pair.go`, `device_pair_stub.go`, `device_scan.go`, `device_scan_stub.go`, `device_oath_sync.go`, `device_oath_sync_stub.go`, `device_piv_sync.go`, `device_piv_sync_stub.go`, `device_share.go`, `device_share_stub.go`, `device_sync.go`, `device_sync_stub.go`; `.github/workflows/ci.yml` (the `nested-module-test` job's `xkey unit suites` step now runs `./cmd/xkey/cmd` under the plain `codec_json tpm_simulator` tag set too, not only `ble`, so this class of drift fails CI).
  - Verified by the existing `TestBackupCommands_NoKeyValueFlag/from-device` and `TestDeviceTimeoutFlags_DocumentTheConfigurationDefault`, both of which now pass without `-tags ble`, and by the new `TestBLEStubFlagParity` (`xkey/cmd/xkey/cmd/device_ble_stub_flag_parity_test.go`), which pins the exact flag set of all nineteen command pairs and runs unchanged under both tag sets.
