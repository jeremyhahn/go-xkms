- **Fixed four concurrency bugs where a `Close`/`Stop` could race a concurrent sender, panicking with "send on closed channel" or "close of closed channel"** (#1271).
  - `xkey/pkg/phone` BLE transport: `handleResponseNotification` and `handleStatusNotification` run on BlueZ D-Bus goroutines and can still be delivering notifications after `Close` begins. `Close` used to close `responseChan`/`statusChan` while those handlers concurrently checked `closed.Load()` and then sent, so a handler that lost the race panicked sending on a closed channel. `BLETransport` now closes a `done` channel instead; `responseChan`/`statusChan` are never closed, and `Receive` selects on `done` to unblock promptly when the transport closes.
  - `xkey/pkg/virtualdevice` native FIDO2 device: the CTAPHID keepalive goroutine (`xkey/pkg/authenticator/hid_adapter.go`) calls `handleResponse` via the response-handler callback and can still be running when `Close` runs. `Close` used to close `respChan` under a mutex that `handleResponse` never took, so a concurrent send could hit the closed channel. `NativeVirtualDevice` now closes a `done` channel instead; `Read` selects on `done` and `respChan`, and `respChan` is never closed.
  - `pkg/acme/client/service` `RenewalOrchestrator.Stop`: gated `close(stopChan)` on `running.Load()` instead of a compare-and-swap, so two concurrent `Stop` calls could both pass the check and both close the channel. `Stop` now gates the close on `running.CompareAndSwap(true, false)`, matching `Start`.
  - `pkg/acme/client` `RenewalService`, its `RenewalConfig`/`CertificateInfo`/`RenewalStatus` types, and the dead SDK alias `ACMERenewalConfig` were removed. Nothing in production ever constructed a `RenewalService` — `pkg/acme/client/service.Service` (used by `cmd/acme-client`) composes `RenewalOrchestrator` exclusively, which supersedes it and already has the `Stop` fix above. Only the package's own tests referenced `RenewalService`.
  - Files: `xkey/pkg/phone/ble_transport.go`, `xkey/pkg/virtualdevice/native_virtual_device.go`, `pkg/acme/client/service/renewal_orchestrator.go`, `pkg/acme/client/config.go`, `pkg/acme/client/types.go`, `sdk/go/acme/acme_server.go`; `pkg/acme/client/renewal.go` and `pkg/acme/client/renewal_test.go` removed.
  - Verified by `TestBLETransport_NotificationsRaceClose`, `TestBLETransport_Receive_UnblocksOnClose`, `TestNativeVirtualDevice_HandleResponseRacesClose`, and `TestRenewalOrchestrator_ConcurrentStop`, each of which reproduces the original panic under `-race` against the prior implementation.
