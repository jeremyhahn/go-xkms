- **Go builds and tests run with `-trimpath`, so the shared Go build cache stops growing per clone directory.** The Makefile exports `GOFLAGS` with `-trimpath` for every go build/test target (the `coverage` `-p=2` line extends it) and every `GOFLAGS` env in `.github/workflows/ci.yml` carries it. Without it cmd/go hashed the package directory into each action ID, so every lane and verify clone built new cache keys (#2309).
- **A pull request that changes a Makefile, a go.mod/go.sum or `.github/workflows/ci.yml` runs the full CI matrix** (Integration, Race Detector, TPM2 Simulator Tests, Nested Module Tests, raft tag matrix) without the `ci:full` label: preflight sets `full_paths` from `FULL_TIER_PATTERN` and CI Gate fails if a selected full job skips (ruling 1041(4), #2309).
- **The full-tier path selector fails closed:** on an unlabelled pull request preflight keeps `full_paths` true unless a successful diff shows no `FULL_TIER_PATTERN` file, so a failed diff (missing merge base, unavailable commit) still runs the full matrix (#2309).
- **`pkg/xkms.Version()` (XKMSService.Health, gRPC Health) reports the build version under `-trimpath`:** the Makefile LDFLAGS set `pkg/xkms.buildVersion` from `VERSION` at link time instead of the package reading `VERSION` through its source path (#2309).
- **Devcontainer targets keep `-trimpath`:** `run_in_devcontainer` and `run_with_server` forward the exported `GOFLAGS` into each `docker compose exec` (as `XKMS_CALLER_GOFLAGS`, appended to the devcontainer's `-mod=readonly`), so `integration-test-fido2`, `integration-test-pkcs11-module` and the other devcontainer targets build without directory-dependent cache entries (#2309).
- **A toolchain-image stage never uses a shared cache volume without its lock:** when any cache-volume lock cannot be taken (mktemp, mkfifo, flock or the holder failing), `scripts/in-toolchain-image.sh` releases the locks it took and runs on private caches, so a trim in another job cannot evict entries under a running build (#2309).
