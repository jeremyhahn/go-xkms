- **The xkey agent server's mTLS revocation check was skipped on TLS session resumption** (#1285). `Server.buildTLSConfig` wired the agent-connection and revocation-status check (`EnrollmentService.VerifyAgentCertificate`) onto `tls.Config.VerifyPeerCertificate`, which Go does not call when a session resumes from a ticket — a revoked or removed agent holding a still-valid ticket kept access for up to the ticket's 7-day lifetime. The check now runs as `tls.Config.VerifyConnection`, which Go calls on every handshake including a resumed one, using the certificate chain Go restores into `ConnectionState.VerifiedChains` for the resumed session. The server also now sets `SessionTicketsDisabled: true` as defence in depth: this server's agent connections are long-lived and already reconnect with their own backoff, so there is no latency-sensitive case here that needs 0-RTT resumption, and disabling tickets means no connection can reach the wire without running the full handshake.
  - Files: `xkey/pkg/agent/server.go`, `xkey/pkg/agent/server_test.go`, `xkey/pkg/agent/server_resumption_test.go` (new).
  - Verified by `TestServer_TLSSessionResumption_RevokedAgentRefused`, a real TLS handshake test that captures a session ticket over a loopback connection, revokes the agent's certificate, then resumes the session and confirms the server refuses it (`ConnectionState.DidResume` is asserted true at the moment the check runs, so the test fails if it stops exercising the resumption path); `TestServer_TLSSessionResumption_NonRevokedAgentStillResumes` proves a still-enrolled, unrevoked agent's resumed session keeps working; `TestServer_BuildTLSConfig_SessionTicketsDisabled` proves the production config disables tickets. The xkey agent client (`xkey/pkg/agent/client.go`) and every other `tls.Config` in xkey (`grep -rn VerifyPeerCertificate xkey`) were audited and found not to rely on `VerifyPeerCertificate` for a security decision; `cmd/xkey/cmd/auth.go`'s SPKI-pinned client config already uses `VerifyConnection`.
