- **pkg/tpm2 no longer leaks locked password memory.** Passwords are mlocked enclaves with no finalizer, so dropping one without `Clear()` kept it locked until exit and long-lived processes could exhaust `RLIMIT_MEMLOCK` (later allocations then fail with "secure enclave unavailable"). `Install` now releases the configured hierarchy auth it presents; `PlatformPassword.Create` releases the random secret it seals and restores the caller's password when sealing fails; `PlatformKeyStore.Initialize`/`SetUserPIN` release the user PIN on error, replace (not stack) the SO PIN on retries, allocate it once, and release the previously cached SRK password on recreate. The `EK`/`SRK`/`IAK`/`LAK`/`IDevID`/`LDevID` `AttributesFromConfig` builders now check the ECC curve before allocating any password, and EK/SRK release the first password when the hierarchy auth fails (`config_password_release_test.go`). Regression tests compare the process allocator's locked bytes before and after each path (`provision_coverage_simulator_test.go`, `password_test.go`, `platform_test.go`). SPEC: tpm2.
