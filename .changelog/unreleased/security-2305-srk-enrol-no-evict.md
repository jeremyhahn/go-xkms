- **Platform SRK enrolment never replaces an enrolled SRK.** Two concurrent first enrolments could both see no SRK; the second then evicted the first one's SRK and recreated it under its own PIN, orphaning every key under it. `EnrollPlatformSRK` now adopts an SRK its PIN authorizes and refuses any other with `ErrPlatformSRKEnrolledOtherPIN`, never evicting it (replacing an SRK is the explicit `Initialize` path only), and `xkey tpm srk enroll` holds an exclusive lock on `<data dir>/tpm-srk-enroll.lock` for the whole probe-then-create sequence and checks an existing SRK against the PIN under it, exiting with "already enrolled with a different user PIN".
