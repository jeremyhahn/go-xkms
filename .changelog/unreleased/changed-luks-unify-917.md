- **One LUKS implementation, built on `go-luks2`, with a configurable TPM seal parent.** `pkg/luks` is now the single LUKS implementation in the stack: `LibExecutor`, a new production `Executor` on `github.com/jeremyhahn/go-luks2` (now a direct root-module dependency), attaches a loop device to a file-backed container on `Unlock`/`Create` and detaches it on `Lock`, formats, mounts and unmounts, and runs the kernel-keyring preflight (`EnsureKeyringAvailable`) before every operation that needs it. `xkey/pkg/luks.Volume` no longer drives `go-luks2` itself; it is a thin wrapper over `sdk/go/luks`'s `Executor`, keeping only what is genuinely xkey-specific (privilege-drop chown after mount, secure container wipe). `TPMSealer`'s storage parent is now an explicit, validated config (`TPMSealerConfig{Parent SealParent, PCRBank string}`): `SealParentPSRK` (default) binds the sealed passphrase to go-xkms's Platform SRK and platform PCR policy, written as an `xkms-tpm2` token, consistent with go-xkms#681's PSRK-only rule; `SealParentSSRK` binds it to a plain PolicyPCR digest under the TCG Shared SRK with empty parent auth, written as a `systemd-tpm2` token for `systemd-cryptenroll`/crypttab boot-time unlock -- a documented, narrow exception to #681, which go-xkms seals but deliberately never unseals (`ErrTPMSSRKUnsealUnsupported`), since `pkg/tpm2`'s `Unseal` has no session path for an ad hoc PolicyPCR policy. Both seal paths set a fresh, discarded 32-byte guard password on the sealed object to close an empty-password bypass of `UserWithAuth`-bearing keyed-hash objects (verified against the TPM simulator). All actual sealing/unsealing is delegated to `pkg/tpm2.TPM2`; `pkg/luks` drives no TPM command of its own beyond the SSRK path's PolicyPCR digest computation. Tokens are now go-luks2's own `*luks2.Token` type instead of a parallel struct. See `docs/luks/` and `xkey/docs/luks/` (go-xkms#917).
