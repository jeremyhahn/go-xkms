- **`xkey extension serve` now names why it cannot unseal a barrier sealed with pkcs11 or shamir, instead of one generic "not supported in headless mode" message** (#699). Previously every strategy other than `tpm2`/`passphrase` fell through to the same catch-all refusal; that error is kept only for a genuinely unrecognized strategy ID. Two named, typed refusals replace it for the strategies that are actually reachable: `ErrServePKCS11StrategyUnavailable` says the PKCS#11 token PIN has no non-interactive source yet — the intended one is a PIN sealed to the TPM under the platform PCR policy, auto-unsealed the way the barrier's own TPM2 auto-unseal works, which is go-xkms#677's still-open server-side work — and names `xkey barrier unseal` as the interactive alternative; `ErrServeShamirStrategyUnavailable` says a headless process cannot collect the M-of-N operator quorum Shamir reassembly needs, and names the same interactive command. TPM2 auto-unseal and passphrase unseal are unchanged. The cloud KMS strategies (AWS KMS/GCP KMS/Azure Key Vault/Vault) were refused the same way at first (`ErrServeCloudKMSStrategyUnavailable`), but gained real headless backend wiring in the same unreleased window and that sentinel was deleted (#757; see `added-xkey-cloudkms-barrier-757.md`). Files: `xkey/cmd/xkey/cmd/extension_serve.go`; docs in `xkey/docs/usage/cli/extension.md`. Verified by new tests in `xkey/cmd/xkey/cmd/extension_serve_test.go`: one per strategy (`pkcs11`, `shamir`) proving the typed refusal fires before any unseal is attempted, plus the existing `TestServeErrors_AreDistinct` extended to the new sentinels.
