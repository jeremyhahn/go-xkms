- **`acme/client.EnrollDevice` now installs the IAK certificate it receives during enrollment, so device-attest-01 works on real TPMs without a manual install step** (#1100). Enrollment parsed the issued IAK certificate out of the finalized chain and returned it to the caller, but never called `TPM2.ProvisionIAKCert` — `pkg/acme/challenges/device-attest-01.Setup` reads the certificate back later, via `IAKCertificate()`, to build a device-attest-01 statement's `x5c[0]`, so a device that enrolled and then attested in a separate process (the normal case on real hardware) had no certificate to answer with even though enrollment had succeeded. #1059 fixed only the in-process TPM simulator path, which re-mints a throwaway certificate on every open regardless of what enrollment issued.
  - `client.TPMModule` gained `ProvisionIAKCert(cert *x509.Certificate) error`, implemented by `XKMSTPMAdapter` as a thin delegate to the underlying `TrustedPlatformModule.ProvisionIAKCert`. `EnrollDevice` calls it immediately after parsing the IAK certificate from the finalized chain, before returning; a provisioning failure is a typed `*caerrors.TrustedCAError` naming the cause.
  - The hardware device path (`pkg/acme/client/service.openDeviceTPM`) previously opened without any certificate store at all — `TPM2.ProvisionIAKCert`/`IAKCertificate` refuse with `ErrCertStoreNotConfigured` unless the device configures an NV index for its IAK certificate. It is now given `store.FileCertStore`, a new `CertificateStorer` implementation backed by the same `storage.Backend` the device's key blobs already persist to (`pkg/tpm2/store`), so a hardware device's IAK certificate survives a process restart without a new, separately configured store. The in-process TPM simulator keeps `MemoryCertStore`: it re-provisions a fresh throwaway certificate every time it opens, so nothing needs to persist across restarts for it.
  - Files: `pkg/acme/client/tpm.go`, `pkg/acme/client/enrollment.go`, `pkg/acme/client/service/device_tpm.go`, `pkg/tpm2/store/file_cert_store.go` (new), `pkg/tpm2/store/interfaces.go`.
  - `ProvisionIAKCert`'s public-key match check also caught three test fixtures across the tree that drove `EnrollDevice` against the real in-process TPM 2.0 simulator but returned a canned IAK certificate for an unrelated key, fixed with a new `testutil.FakeACMEDirectory.SetCertsFromCSR` hook that mints the certificate for the IAK public key the client's submitted TCG-CSR-IDEVID actually carries: `TestDeviceManager_Enroll_Success` (`pkg/acme/client/service`), `TestDeviceEnroll_Success` (`pkg/acme/gui/client/api`), `TestDeviceEnrollCmd_Success` (`cmd/acme-client`). Every other caller of `EnrollDevice`/`NewFakeACMEDirectory` in the repo (`pkg/acme/client`'s own suites, `sdk/go`, `xkey`, `test/integration`) either drives a mock `TPMModule` that performs no real key-material check or issues from a genuine CA, so none needed the same fix.
