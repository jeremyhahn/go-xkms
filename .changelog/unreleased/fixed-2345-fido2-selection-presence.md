- **authenticatorSelection waits for user presence (#2345).** A browser sends CTAP 2.1 authenticatorSelection to every connected authenticator and uses the one the user touches; xkey answered at once, so it always won and a hardware key was never offered. Selection now asks for presence through the configured touch handler (honoring `--require-touch` and `--notify`) with UP_NEEDED keepalives, and answers OPERATION_DENIED on decline, USER_ACTION_TIMEOUT when nobody answers, and KEEPALIVE_CANCEL when the browser cancels after another key was touched. The CTAP 2.0 idiom (MakeCredential with a zero-length pinUvAuthParam) waits for the touch before its PIN_INVALID / PIN_NOT_SET answer. The prompt names the relying party when known. An approved Selection satisfies the presence check of the next MakeCredential or GetAssertion on the same CTAPHID channel within 30 seconds, once, so choosing xkey costs one touch.
- **The Selection presence grant ends with the credential operation it covers (#2345).** A completed MakeCredential or GetAssertion clears the grant even when PIN authorization needed no prompt, so a later request cannot reuse it; the user intent check before PIN_REQUIRED accepts a live grant without consuming it, so the operation after the PIN exchange does not prompt again.
