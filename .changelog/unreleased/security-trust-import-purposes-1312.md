- **Network-fetched CA bundles and restored backups are no longer auto-classified, and the Android key attestation OID no longer grants `android-hardware`** (#1312). Three follow-ups to #1304, each a path on which someone other than the operator chose a trust anchor's purpose. The GUI's trust-strap import (`TrustService.ImportFromTrustStrap`) and `xkey trust bootstrap` imported the server's bundle through the auto-classifying `AddPEM`, while `xkey trust fetch` filed the same kind of bundle under `bootstrap-ca`. `xkey backup restore` ignored the purpose each certificate's archive entry recorded and re-classified it, which promoted a `synced` certificate out of quarantine. `ClassifyCertificate` granted `android-hardware` to any certificate carrying the Android key attestation extension (1.3.6.1.4.1.11129.2.1.17): a real attestation extension sits on a device leaf, never on a root, and anyone can mint a self-signed CA carrying the OID.
  - New `truststore.BootstrapImportOptions(server)`: purpose `bootstrap-ca`, source `platform:<host>`. `xkey trust bootstrap`, `xkey trust fetch`/`import-platform` (defaults, still overridable by `--purpose`/`--source`) and the GUI trust-strap import all file through it. `truststore.TrustStore` gains `ImportPEM`, which both stores already implemented.
  - `backup.TrustStoreWriter` is now `ImportPEM(pem, *truststore.AddCertificateOptions)`, which is the same seam sync uses, so `sync.TrustStoreAccessor` embeds it again. `RestoreTrustStore` files each certificate under its recorded purpose, source and tags. A missing or unrecognized recorded purpose refuses the trust-store restore before any certificate is written, with `*backup.RecordedPurposeError` (matches `ErrRestoreFailed` and `ErrMissingRecordedPurpose`/`ErrInvalidRecordedPurpose`). Archives without purposes are not migrated. `CreateBackup` now fails with `ErrCollectFailed` when a certificate's metadata cannot be read, instead of silently archiving it without a purpose.
  - `ClassifyCertificate` grants `android-hardware` only for a byte-exact match against the embedded Google Hardware Attestation Roots. The OID branch and `hasAndroidAttestationOID` are removed. An operator who needs another attestation root files it with `xkey trust classify <fingerprint> --purpose android-hardware`.
