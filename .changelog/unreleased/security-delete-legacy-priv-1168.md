- **Deleting a TPM2 key now removes its legacy `<CN>.priv` blob too, and the refusal error for a pre-Platform-SRK symmetric key names the exact file to delete.** go-xkms#1148 moved symmetric (AES) keys onto the Platform SRK seal path and stored their private blob as `<CN>.blob` instead of the old `<CN>.priv`, but `FileBackend.Delete` (`pkg/tpm2/store/file_backend.go`) never removed `<CN>.priv`, so any key written before that change kept its unprotected AES key on disk after a delete. `Delete` now also removes `FSEXT_LEGACY_PRIVATE_BLOB` (`.priv`, `pkg/tpm2/store/interfaces.go`). It is the only key-deletion path in `pkg/tpm2`/`pkg/backend/tpm2` — `DeleteKeyPair`, `DeleteKey` and `Backend.DeleteKey` all call through it — so no other path needed the same fix. `DeleteKey` still cannot reach that step for a pre-#1148 key: for a sealed object it first unseals to prove ownership, and a pre-migration key has no `<CN>.blob` to unseal, so `ErrUnprotectedSymmetricKey`'s detail (`pkg/tpm2/symmetric.go`) now names the `<CN>.priv` file to delete by hand, e.g. `old-key: delete old-key.priv from the TPM2 key directory`. No scanning command was added; the manual recovery path is documented in `docs/tpm2/user.md` §"Legacy symmetric key cleanup" and `docs/tpm2/engineering.md` §"Symmetric keys". Verified by `pkg/tpm2/symmetric_psrk_simulator_test.go`: `TestFileBackendDelete_RemovesLegacySymmetricPrivateBlob` proves a legacy-format key's `.priv` and `.pub` are both removed, `TestFileBackendDelete_RemovesCurrentFormatSymmetricKey` proves a normal delete still works, and `TestSymmetricKeyPSRK_RefusesUnprotectedBlob` proves the refusal error carries the file name (go-xkms#1168).
