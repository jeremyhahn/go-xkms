  - `integration-test-acme-tpm` brings up a dedicated swtpm plus an xkmsd instance with its embedded ACME server enabled (`test/integration/acme-tpm/config.acme-tpm.yaml`, `challenges.enroll01`/`endorse01`) and runs the suite (`-tags='integration,tpm2,codec_cbor,codec_json,codec_msgpack,gms_pure_go'`) against both. `test/integration/acme-tpm/certgen` generates the ACME listener's throwaway TLS cert with the Go stdlib rather than shelling out to `openssl`, which the runtime image does not carry.
  - `integration-test-challenges` runs `test/integration/challenges/{enroll01,endorse01}` (`-tags=integration`) against the same acme-server config; `dns01` and `http01` are excluded on purpose — they are their own multi-service E2E stacks that still build against the pre-merge `go-trusted-ca` sibling checkout, tracked separately from this issue.
  - Both targets are added to the `integration-test` aggregate, so the nightly workflow (`.github/workflows/nightly.yml`, which invokes `make integration-test` wholesale) now exercises them with no workflow YAML change needed.
  - `config.acme-tpm.yaml` uses `storage.backend: "file"`, not `"qrdb"`: `"qrdb"` flips on the embedded qrdb node's own barrier, which for `barrier.strategy: "passphrase"` never auto-unseals at construction (only `"none"` and a provisioned `"tpm2"` do) and blocks boot behind a pre-boot sealed-window listener that `pkg/server/sealed_window.go` refuses to open on a non-loopback `server.host` — nothing in this repository drives that ceremony unattended today, `configs/xkmsd-integration.yaml`'s own `KNOWN GAP (go-xkms#653)` comment included. `test/integration/api/config.test.yaml` is the proven fixture this now matches: `storage.backend: "file"` never constructs the embedded qrdb node at all, so the daemon boots and serves with the barrier simply left sealed-but-inert, which this lane's ACME/software-keystore path never touches. One consequence: `protocols.rest/grpc/quic/mcp` are all off (only `"qrdb"` storage may serve network protocols per `Config.Validate`'s `NetworkServing` check) — harmless here since the ACME listener is its own dedicated `net.Listener`, independent of `protocols.*`.
  - The first real docker run (8 PASS / 42 FAIL) turned up bitrot in a suite that had never executed, three fixture-level causes, all now fixed: (1) `test/integration/acme-tpm`'s in-process test CA built a raw pkcs8 backend with no key password and no `AllowPlaintextKeys`, which current `pkg/keyprovider/pkcs8` validation refuses (`ErrPlaintextKeyNotAllowed`) -- fixed by setting `AllowPlaintextKeys: true` on that backend, the same fixture idiom already used by `pkg/keyprovider/pkcs8/pkcs8_test.go`, `test/integration/pkcs8`, and `test/integration/tpm2/capture_helper.go` (never loosened in `pkg/keyprovider/pkcs8` itself). (2) Both lanes' test clients didn't trust the acme-server's self-signed certificate (`certgen`) -- fixed by mounting the `acme-data` volume read-only into the `test` service and setting `ACME_CA_CERT=/data/acme-tls/acme.crt`, which the raw-http test helpers (`getTLSConfig`/`GetTLSConfig`) already read, and by wiring the same file into `pkg/acme/client.Config.TrustedRoots` for the ACME-client-based tests (`createTestACMEClient`); no `InsecureSkipVerify` anywhere. (3) Three `attestation_integration_test.go` subtests hand-built `&xkmssdk.ProdCaData{}` struct literals instead of calling `xkmssdk.NewProdCaData(&quote)`, leaving `Version` at its zero value, which `UnpackProdCaData` correctly rejects as `ErrInvalidProdCaData` before it is anywhere in production code -- fixed by calling the constructor.
  - **Left unfixed, reported instead of patched**: 4 of the 42 failures (`TestDeviceAttest_InvalidConfig`, `TestEnrollDevice_InvalidConfig`, `TestEnrollDevice_MissingEnvVar`, `TestRequestEndorsementKeyCertificate_InvalidConfig`) are a real production bug in `pkg/acme/client/enrollment.go`: `EnrollDevice`, `RequestEndorsementKeyCertificate`, `DeviceAttest` and `expandEnvVars` all wrap validation errors with `caerrors.MalformedError("...: %v", err)` (lines 175, 181, 453, 744, 750) -- `%v`, not `%w`, which discards the `Unwrap` chain, so `errors.Is(err, client.ErrMissingTPMModule)` (and the other sentinels) can never succeed no matter what the tests do. The tests' `assert.ErrorIs` expectations are correct; the fix belongs in `enrollment.go`, not in the test fixtures, and is out of scope for this CI-wiring issue.
