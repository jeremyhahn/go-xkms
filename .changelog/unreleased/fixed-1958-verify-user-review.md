- **Built-in user verification keeps the host waiting and spends no uvRetries it should not (#1958).** The CTAP-HID adapter sends CTAPHID_KEEPALIVE during getPinUvAuthTokenUsingUvWithPermissions, as for makeCredential and getAssertion, so a host no longer times out while the user answers on the phone; an rpId the verifier cannot name (over 255 bytes or not UTF-8) is CTAP2_ERR_INVALID_PARAMETER before the user is asked; a trust store that cannot be loaded is an unavailable verification; and the Android status list keeps the first `max-age` of its Cache-Control fields (RFC 9111 §4.2.1), so a later one no longer extends a stale list's lifetime.
- **An Android status list marked no-store or no-cache is still refused once expired (#1958).** no-store and no-cache now only stop the list being reused; a response past its `max-age` (less its `Age`) or its `Expires` is stale, so an expired revocation list that omits newly revoked certificates is no longer accepted.
- **A failed built-in user verification leaves the outstanding pinUvAuthToken's PIN protocol in force (#1958).** getPinUvAuthTokenUsingUvWithPermissions agrees its shared secret in request scope and switches the PIN protocol and keys only when the verified user's new token replaces the old one, so a cancelled, refused or unavailable request under protocol 1 no longer makes a protocol 2 token's 32-byte pinUvAuthParams fail.
