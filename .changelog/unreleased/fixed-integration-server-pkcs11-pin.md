CI: the compose `xkms-server` that the PKCS#11 module integration suites dial starts again. `configs/xkmsd-integration.yaml` gave the SoftHSM backend a literal `backends.pkcs11.pin`, which server start-up refuses because that field is a protected secret target (go-xkms#654). That field resolves only `credential://` references, and a fresh test volume holds no credential before its first boot, so the backend is dropped from the config. The suites only ever used the software backend by default. A new `pkg/server` test runs every shipped config through the server's own secret resolution, so a literal in a protected field now fails the unit tests instead of the integration run (DS-3769).
