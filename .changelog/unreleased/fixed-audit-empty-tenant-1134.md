- **A system auditor without `audit:read:cross` can now see audit events emitted without an identity** (#1134). `toTransportEvent` (`pkg/audit/qrdb.go:65-100`), the single mapping both `QRDBLogger` and `ChainedFileLogger` emit through, tagged an event with the raw tenant off the context identity, so an event emitted with no identity bound — a background job, an internal operation — stored `""`, the audit chain's match-everything filter. After #1115 clamped a system-scoped caller without `audit:read:cross` to `qrdbsdk.SystemTenantID` (`pkg/xkms/servicer_audit.go:119-128`), that caller's query never used the empty filter again, so the event became invisible to everyone except an `audit:read:cross` holder. The tenant is now resolved through `qrdbsdk.NormalizeTenantID` at emission: no identity, or an identity with an empty `TenantID`, is stored as `system`; every other tenant is unchanged. Events already stored under `""` are not rewritten — this is a pre-release repository and the fix applies going forward only. Verified by `pkg/audit/qrdb_test.go` (`TestQRDBLogger_NoIdentityNormalizesToSystemTenant`, `TestQRDBLogger_EmptyIdentityTenantNormalizesToSystemTenant`) and the round trip `pkg/xkms/servicer_audit_tenant_test.go`'s `TestQueryAudit_SystemAuditorSeesIdentityLessEvent`, which emits through a real embedded qrdb node and reads it back as a system Auditor.
