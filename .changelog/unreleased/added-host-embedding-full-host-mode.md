- **Full host mode: a host that mounts the xkms ServiceModule gets every store-backed feature.** A self-built module (no `WithRESTServer`) used to be host-inert: no Password Manager, SSH, CA, platform store, backend credentials, PCR policies or PIN management. `pkg/compose` is now the one construction path for these subsystems, used by xkmsd and by an embedding host alike. It records a typed `*FeatureDisabledError` or `*FeatureBuildError` for each feature it leaves off, and `Stores.Wire` publishes the rest into an `XKMSService`. The module composes them once, from dependencies the host supplies, re-exported in `sdk/go` as `WithServiceModuleBarrierRegistry`, `WithServiceModulePINBackend`, `WithServiceModulePlatformSealer`, `WithServiceModuleCredentialStrategy`, `WithServiceModuleCA`, `WithServiceModulePCRReader` and `WithServiceModuleBarrierRoutes`. Stores persist in the host's qrdb KV under `xkms/<feature>/`. PCR policy definitions now persist through the new `policy.BackendPolicyStore` rather than only in memory. The PIN backend both unlocks tenant Password Manager sessions and mounts `/api/v1/pin/*`, which is permission-gated (`pin:read` to verify or read the lockout, `pin:write` to set, change or reset) and refuses tenant-scoped callers. The barrier, custodian, shares and init route families stay unregistered on a self-built module unless the host opts in with `WithServiceModuleBarrierRoutes`, so a host that owns its barrier keeps those paths.

  - Verified by `pkg/compose` tests, `pkg/apimodule` host-mode tests, `sdk/go/apimodule_host_test.go` and `pkg/seal/policy` backend-store tests.
