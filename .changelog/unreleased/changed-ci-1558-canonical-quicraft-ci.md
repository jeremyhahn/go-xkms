- **CI follows the canonical go-quicraft ci.yml (ci-template v1.27.0) outside its CUSTOMIZE blocks (#1558)**. The workflow keeps the template's trigger, its concurrency, its one image job running the lint, build, test, security and deps stages in the toolchain image, its integration and nightly soak jobs, arch-gates, and the CI Gate with pr/full/nightly tiers. Everything specific to go-xkms sits inside `# >>> CUSTOMIZE (go-xkms)` blocks or on lines marked `# CUSTOMIZE`. That covers build tags, `GOWORK=off`, the extra lint checks, the CLI image scan, the compose teardown, and the static-analysis, build, nested-module-build, nested-module-test, build-raft, race and tpm2-simulator jobs (on bigdisk, rulings 145/146). `scripts/assert-build-tags.sh` and `scripts/trim-ci-caches.sh` are new. `scripts/in-toolchain-image.sh`, `scripts/reap-stale-ci-stacks.sh` and the Makefile (`it-image`, `COVERAGE_THRESHOLD`, `IT_PROJECT`) follow. Under the template, changes, arch-gates and the CI Gate carry no timeout-minutes. v1.27.0 adds the `lint-gates` job, which passes with an OK because go-xkms defines no `lint-gates` target. Main runs are grouped per commit. A draft PR runs no CI: every job skips, and CI Gate fails on the draft. A docs-only PR would run RELEASABILITY_TEST, which go-xkms leaves empty. `internal/buildgates` now requires the draft guard on every job and CI Gate's DRAFT check. Before the Build job compiles, it checks that it owns every entry at the top of the shared GOCACHE volume, and fails with the foreign owner's uid when it does not. Without the check, Go fails with "not in std" errors that do not name the cause.
