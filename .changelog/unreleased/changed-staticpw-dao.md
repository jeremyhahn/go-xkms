- **The Password Manager has one store, persisted as go-qrdb DAO records** -- `pkg/staticpw`'s `DAOStore` is the only concrete store: `NewStore(daos)`, `NewTenantStore(daos, tenantID)`, `NewSharedTenantStore` and `NewPersonalTenantStore` keep entries, folders, aliases and vault factors as `GenericDAO` records in the `staticpw` database, and `NewDAOTeamStore(daos)` keeps xkey's team list there too. `BackendStore` and the personal `dek_backend.go` layer are gone; a personal store seals each record body with the user's DEK. `NewTenantPasswordStoreManager` takes go-qrdb's `TenantStoreResolver` instead of a `*seal.BarrierRegistry`, so each tenant's entries live in that tenant's own system database behind its barrier; a tenant ID that is not valid is refused with `ErrInvalidTenantID` (400 on REST). Hosts supply the resolver with `apimodule.WithTenantStores` (SDK: `WithServiceModuleTenantStores`). A host without a go-qrdb node builds its factory with the new `sdk/go.NewBackendDAOFactory(backend)`, which xkey does over its barrier; `seal.BarrierBackend` now implements `storage.CompareAndSwapper` so DAO creates work over it. Records written by the old storage-backed store are not read.
