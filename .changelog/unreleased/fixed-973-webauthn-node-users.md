- **Passkey sign-up, invite redemption and token refresh work on a node that enforces authentication.** These public routes looked users up through the qrdb client using the request's anonymous context, so an embedded node refused them: registration/begin and login/begin answered 500, a fresh invite answered 404 "link is not valid", and a refresh after login answered 401. They now read users through the embedded node's own user service, on the xkmsd server and through `apimodule.WithNodeUsers` for hosts that embed a node. The service principal's permissions are unchanged. A WebAuthn 500 now logs its cause at Error through the server logger, where it used to log only at Debug.
