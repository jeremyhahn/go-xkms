- **TPM policy registries belong to a node, and named policies authorize without a database.** Scope, policy and assignment keys are prefixed by the node ID (`<node>/<tenant>/...`), so nodes sharing one datastore keep separate registries; xkmsd passes `cluster.node_id`, and `compose.TPMPolicyParams` gains `NodeID`. Records written before this change are not read (`TestRegistry_NodesOwnTheirRecords`). The `.tpmpolicy` binding record (now version 3) carries the scope authority's public area and the policy's approvals, refreshed on update, revoke and authority rotation; `NewTPMStaticPolicyResolver` (sdk/go) builds a resolver from records, installed with the new `TrustedPlatformModule.SetPolicyBindingResolver`. Older records are refused (`TestService_OfflineAuthorization`, `TestStaticPolicyResolver`). SPEC: tpm-policies. (#1533)
