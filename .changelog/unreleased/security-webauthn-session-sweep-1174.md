- **Abandoned WebAuthn ceremony sessions are swept and capped** (#1174). `MemorySessionStore` removed a session only on `Take`/`Delete`; expiry was checked on read and `Cleanup` had no production caller, so an unauthenticated `POST /api/v1/webauthn/login/begin` repeated forever grew memory without bound.
  - `webauthn.SweepSessions` / `Service.SweepSessions` (`pkg/webauthn/session_sweeper.go`) call `Cleanup` every `DefaultSessionSweepInterval` (1 min) until their context ends. xkmsd runs it for its one shared WebAuthn service from `Server.Start` on a goroutine tracked by the server wait group; `Shutdown` stops and joins it. `rest.WebAuthnStores.StartCleanupRoutine` now wraps the same function.
  - `MemorySessionStore` holds at most `DefaultMaxSessions` (10,000; `WithMaxSessions` overrides). At the cap `Save` sweeps expired sessions itself and refuses with the typed `*webauthn.SessionLimitError` only when all are live, so a store without a sweeper (a composing host's self-built surface) still recovers. The browser and SDK ceremony routes answer 503 with code `session_limit`; gRPC answers `ResourceExhausted`.
  - The webauthn package has no separate challenge store (the challenge lives in the session), so the session store was the only one affected.
