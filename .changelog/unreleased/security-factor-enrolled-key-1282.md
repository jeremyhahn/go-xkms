- **The PIV, PKCS#11 and FIDO2 auth factors verified signatures against a public key taken from the response, so any key the caller held would pass** (#1282). `Enroll` stored the real key in `enrollment.PublicKey`, but `Challenge` never passed it on, and qrdb's `VerifyFactor` gives a factor only the stored challenge and the client's response. So `Verify` read the key from `response.Metadata`: `public_key_pem` (PIV), `public_key_der` or `public_key_pem` (PKCS#11), `cose_public_key` (FIDO2). An attacker could sign the nonce with their own key, send that key with the signature, and pass. Each factor now works the way the mTLS factor already did. `Challenge` copies the enrolled key into `MethodData`: `enrolled_cert_pem` (PIV, PEM), `enrolled_public_key_der` (PKCS#11, standard base64 PKIX DER), `enrolled_cose_public_key` (FIDO2, standard base64 COSE). `Verify` reads the key only from the challenge. It refuses with `AuthFactorVerificationFailedError` when the key is missing, and it never reads key material from a response.
  - FIDO2 verification now also follows the WebAuthn assertion checks it had skipped. `authenticatorData` must begin with SHA-256 of the enrolled `rp_id`, which the challenge carries from the enrollment, and must have the user-present flag set. It is parsed with go-webauthn's `protocol.AuthenticatorData`. `clientDataJSON` is parsed, not substring-matched, and must have `type` `webauthn.get` and a `challenge` equal to the issued nonce in base64url. The signed data is still `authenticatorData || SHA-256(clientDataJSON)`. User verification is not required, because no enrollment records that requirement. The unused `public_key_hash` enrollment metadata was removed.
  - Wire change: factor responses carry no public key. PIV and PKCS#11 responses are only the signature in `Value`. FIDO2 responses are the signature plus `authenticator_data` and `client_data`. No producer in this repository sent the removed fields; only tests did.
  - Files: `pkg/factor/piv/factor.go`, `pkg/factor/pkcs11/factor.go`, `pkg/factor/fido2/factor.go` and their tests, `docs/auth-factors/{architecture,engineering,api}.md`.
  - Verified by the new `Test*_Verify_RejectsAttackerKeyInResponse` and `Test*_Verify_RejectsChallengeWithoutEnrolledKey`/`Cert` tests in each factor package, plus `TestFIDO2Factor_Verify_RejectsWrongRPIDHash`, `RejectsMissingUserPresence` and `RejectsRegistrationCeremony`. The existing round-trip tests now pass a response that carries no key.
  - Fixes #1282.
