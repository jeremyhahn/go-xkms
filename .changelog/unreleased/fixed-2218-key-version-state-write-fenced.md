- **Key-version state changes no longer overwrite a concurrent rotation.** Enabling, disabling or retiring key versions wrote the version record back blindly, so a write landing during another node's rotation could record a version whose key material that rotation then removed, and a stale read could drop a newer version from the record. The write now goes through only while the stored record is still the one read and no rotation holds a live claim; otherwise the request fails with a version conflict (REST 409, gRPC FailedPrecondition) and can be retried. An expired rotation claim no longer blocks these writes (#2218).
