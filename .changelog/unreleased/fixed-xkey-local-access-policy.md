- **xkey GUI honours an enterprise policy that turns local app access off** -- the IPC socket followed the requested local app access setting, so it opened even when the verified enterprise policy (`extension_enabled: false`) refused it, and stayed open after a policy disabled it at runtime. The socket now follows `AutoFillService.IsEnabled`, which reports the effective, policy-approved value, and is reconciled as soon as a verified policy is applied. Files: `xkey/pkg/gui/app.go`, `enterprise_policy.go`, `services/autofill_service.go`.
- **xkey GUI shutdown waits for IPC handlers of servers already stopped** -- a lock or seal stops the IPC server without waiting for in-flight handlers, and dropped it, so shutdown could seal the barrier and close stores under a handler still running. Every stopped server now drains on a tracked goroutine, and shutdown closes local app access first and waits for all drains before sealing. That wait no longer gives up after one second: a handler that outlives its cancellation, such as a minutes-long hardware key generation, now holds the barrier seal and every store close until it returns. File: `xkey/pkg/gui/app.go`.
- **xkey CLI SSH commands release the local SSH store when they finish** -- the local SSH client and the profile, host-key and session stores opened the storage backend but never closed it, because the stores and the embedded client treat it as caller-owned. Repeated commands in one process leaked file descriptors, and on the Pebble engine the second open failed with "lock held by current process". Each helper now hands back a closer that releases the backend, and closes it when construction fails. Files: `xkey/cmd/xkey/cmd/ssh.go`, `ssh_connect.go`, `ssh_sessions.go`, `ssh_console_cmd.go`.
- **`xkey ssh connect` opens the local SSH store once** -- with an xkey-managed key, `ssh connect` opened the local SSH client and then a second backend for the host-key pin store while the first was still held, which the Pebble engine refuses in the same process ("lock held by current process"). The host-key store now runs over the client's own stores and backend. Files: `xkey/cmd/xkey/cmd/ssh.go`, `ssh_connect.go`.
