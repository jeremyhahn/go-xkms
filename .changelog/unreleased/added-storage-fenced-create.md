- **Storage: fenced create.** go-qrdb v0.25.0's tenant service creates a tenant only when its metadata store can write the record while it and the tenant's tombstone are absent, in one atomic step (`kvstore.FencedCreator`). xkms's storage stack gains that optional capability, `storage.FencedCreator` (`PutIfAllAbsent`): the engine backends decide it under their guarded-write lock, `qrdb.Backend` as one consensus transaction, and the prefix, file, LUKS, sealed and barrier wrappers forward it or report `storage.ErrFencedCreateUnsupported` -- never a check followed by a write. xkms's own tenant composition (`seal.NewHardwareTenantService`, used when the qrdb node's barrier is not engaged) creates tenants again. Held to a shared contract suite (`storagetest.RunFencedCreateContract`).
