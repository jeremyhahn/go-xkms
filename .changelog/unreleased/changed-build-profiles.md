- **Every feature is compiled in by default, and a missing one fails closed** -- every `WITH_*` toggle in the root `Makefile` and `xkey/Makefile` now defaults to `1` (PKCS#11, TPM2, AWS KMS, GCP KMS, Azure Key Vault, Vault, FROST and the six object stores); a build opts a feature out with `WITH_<FEATURE>=0`. The provider umbrellas `WITH_AWS`, `WITH_GCP` and `WITH_AZURE` are unset by default and override their provider's toggles only when set. Both Makefiles gain `build-full` and `build-minimal` profiles (every toggle on / every toggle off) listed by `make help`. `xkms.AutoInitialize` no longer skips a configured backend the binary was built without: a `BackendConfigs` key or `DefaultBackend` naming an unregistered backend returns `*xkms.FeatureNotCompiledError` (feature, `WITH_*` toggle and build tag; matches `xkms.ErrFeatureNotCompiled`), and a key-storage resolution failure returns `*xkms.BackendStorageError` (matches `xkms.ErrBackendStorageUnresolved`). The new `xkms.RequireBackend` applies the same check to direct factory lookups. Run-time absence of hardware or a service is still logged and skipped. `make build-cli` now honours the feature tags (it previously passed only `gms_pure_go`). Documented in `docs/configuration/build-system.md`.
