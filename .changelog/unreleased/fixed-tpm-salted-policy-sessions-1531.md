- **TPM policy sessions that authorize a command are now salted, so they no longer panic under FIPS 140-only mode.** An unsalted, unbound policy session has an Empty Buffer session key. go-tpm builds its command HMAC from that key, and under `GODEBUG=fips140=only` Go's `crypto/hmac` panics on it; one example was `CreateIDevID` → `DevIDAdminSession` → `TPM2_Certify`. Every policy session that authorizes a command now starts in `startPolicySession`, which always salts it with the session salt key (the persistent EK, or an ephemeral NULL-hierarchy key). The paths covered are the DevID key policy, the Delegation Policy NV write, the policy-index NV read, the platform PCR session, `NonceSession` and the EK policy for `TPM2_ActivateCredential`; trial sessions stay unsalted. A salt-key failure is reported as `ErrSaltKey`, wrapped in the site's own typed error, and leaves no session loaded. `pkg/tpm2/policy_session_salt_simulator_test.go` checks each site's `TPM2_StartAuthSession` on the wire, in default mode and under `fips140=only` (#1531).
