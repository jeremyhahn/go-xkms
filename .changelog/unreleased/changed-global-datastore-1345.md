- **`storage.backend`'s "file"/"pebble"/"memory" values, which each built their own private, unreplicated storage engine per xkms subsystem, are removed; xkms now has exactly one global, always-qrdb-backed datastore, configured under the new `datastore:` section (#1345).** Before this change, `Server.createStorage`/`createStorageAt` (`pkg/server/storage_factory.go`) switched on `storage.backend`: `"qrdb"` shared one embedded or remote qrdb node across every subsystem, but `"file"`, `"pebble"` (the default) and `"memory"` each opened a *separate* storage engine per subdirectory — unreplicated, outside the barrier's reach as a single unit, and outside RBAC's identity plane. That was backwards for a library whose whole premise is that go-qrdb owns storage and xkms only composes it (`CLAUDE.md` "Layer Ownership"). `createStorage`/`createStorageAt` now unconditionally return a key-prefixed view over the one shared datastore; they can no longer fail on an unrecognized backend name, because there is nothing left to switch on.
  - **New `config.DatastoreConfig`** (yaml `datastore:`) replaces `config.StorageConfig` (yaml `storage:`): `engine` (`memory`/`file`/`pebble`, default `pebble`) selects the local qrdb database engine — mapped straight onto `qrdbsdk.DaemonDatabaseConfig.Backend`, never a parallel enum — and is only meaningful when `mode` (`standalone`, default, or `remote`) is `standalone`; `path` is the on-disk root (required for `standalone` unless `engine: memory`); `remote` (`config.DatastoreRemoteConfig`, replacing `config.QRDBConfig`) configures dialing an already-running external qrdb cluster (`address`, `transport: rest|grpc`, `tls`) when `mode: remote`.
  - `config.Validate` now fully enumerates the datastore configuration space at config-parse time — invalid `engine`/`mode` values and mode-specific requirements (path, remote address/transport) are refused with a typed `*errs.Message` — instead of the old scheme, where `storage.backend` accepted any non-empty string as long as `storage.path` was set and only failed later, at server construction, in `createStorage`'s `default` case.
  - Network protocols (REST/gRPC/QUIC/MCP) now require `datastore.mode: "standalone"` (previously `storage.backend: "qrdb"`); `cluster.enabled` likewise. RBAC's identity plane is now available in every configuration (standalone or remote) — `config.ComplianceGaps`'s old "RBAC enabled without an identity plane" gap no longer exists, because there is no longer a datastore configuration without one.
  - Barrier encryption-at-rest is unaffected in shape (`config.BarrierConfig`) but now applies uniformly: there is no longer a `storage.backend` choice that silently bypasses it for an entire class of deployments.
  - **Breaking, no compatibility shim (pre-release alpha):** `storage:`/`XKMS_STORAGE_*` config keys are gone; `storage.backend: "file"`/`"pebble"`/`"memory"` deployments must move to `datastore.engine` (same values, same meaning, now shared through the one qrdb-backed store) and drop `storage.backend: "qrdb"` entirely (its behavior is now the unconditional default). `storage.qrdb.*` moves to `datastore.remote.*` when `datastore.mode: "remote"`. Nothing migrates existing on-disk data between the old private per-subsystem stores and the new shared datastore; this is a fresh-deployment change, not an in-place upgrade.
