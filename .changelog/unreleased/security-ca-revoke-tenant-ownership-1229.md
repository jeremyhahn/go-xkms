- **CA certificate revoke had no ownership check; any authenticated caller holding `certs:revoke` could revoke another tenant's certificate, or the server's** (#1229).
  - `pkg/ca`'s `signCSR` — the single issuance site shared by `SignCSR`/`SignCSRWithSPIFFE` and `IssueCertificate`/`IssueCertificateWithProfile` — now records the tenant a certificate was issued for (`""` for the system/platform scope) against its serial via the new `recordCertTenant`, persisted alongside the existing revocation and issued-key records under `cert-tenant/<serial-decimal>.json` in the same replicated `revocationStore`.
  - `XKMSService.RevokeCertificate` (`pkg/xkms/servicer_ca.go`) reads the recorded tenant back with the new `CertificateTenant` and runs it through the same `bindTenantTarget` every other tenant-scoped operation in this service uses: a tenant-scoped caller may revoke only its own tenant's certificates, and any other certificate — including a foreign tenant's or the server's own — is refused with the same not-found-shaped `*TenantBindingError` used elsewhere, before `CA.Revoke` is ever reached. A cross-tenant (system) caller may still revoke any certificate. `IssueCertificate` now binds `req.TenantID` against the caller's own tenant before forwarding it, exactly as `SignCSR` already did, so a tenant-scoped caller cannot mint a certificate attributed to a different tenant either.
  - `certs:revoke` remains the single permission gate, already required identically on REST (`POST /api/v1/ca/revoke`), gRPC (`RevokeCertificate`), MCP (`xkms.ca.revoke`) and the ACME admin API — that consistency is unchanged. go-qrdb's built-in Admin role already grants `certs:revoke` by default in every tenant it is seeded into, including the system tenant, so system admins and tenant admins hold it without any new default-grant registration in xkms.
  - A certificate issued through a path that never calls `signCSR` (TCG EK/AK/IDevID device-identity certificates, the CA's own root/intermediate chain) carries no tenant record and so resolves to the system/platform scope, reachable only by a cross-tenant caller — strictly more restrictive than before, never a regression.
  - `provider.CA.IssueCertificateRaw` gained a `tenantID` parameter and `provider.CA` gained `CertificateTenant`; every mock implementing the interface (`pkg/xkms`, `pkg/apimodule`, `pkg/server` test doubles) was updated to match.
  - Files: `pkg/ca/ca.go`, `pkg/ca/ca_extensions.go`, `pkg/ca/service_adapter.go`, `pkg/ca/provider/provider.go`, `pkg/xkms/servicer_ca.go`, `docs/certificate-authority/{engineering,api,cli}.md`.
  - Verified by: `pkg/xkms/servicer_ca_test.go` (`TestRevokeCertificate_ForeignTenantRefused`, `TestRevokeCertificate_OwnTenantAllowed`, `TestRevokeCertificate_SystemAdminRevokesAnyTenant`, `TestRevokeCertificate_CertificateTenantError`, `TestIssueCertificate_ForeignTenantRefused`, `TestIssueCertificate_OwnTenantRecorded`), plus the full existing `pkg/ca` and `pkg/xkms` suites, `pkg/api/authz_consistency_test` and `pkg/api/grpc`'s permission-denial goldens, unaffected.
