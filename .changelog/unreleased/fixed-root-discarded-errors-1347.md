- **Ten call sites in the root module and `sdk/go` discarded an error instead of reporting it, several inside a rollback/cleanup path where the failure is the one thing a caller needs to know** (#1347).
  - `pkg/backend/pkcs11/pkcs11_ecdh.go`'s `deriveECDH` dropped the `DestroyObject` error from its `defer`. The function now carries a named return and joins a `DestroyObject` failure into the returned error (new `ErrDerivedSecretNotDestroyed`) via `*errs.Joined`, the same pattern `unwrapWithEphemeralKEK` already uses in this package.
  - `pkg/storage/luks/backend.go`'s `Unlock` rollback called `b.volume.Lock()` behind `//nolint:errcheck`; a failed rollback lock is now joined into `ErrDelegateCreateFailed` with `errors.Join`. `Lock` discarded `delegate.Close()` the same way; it is now joined with a `b.volume.Lock()` failure when both fail, or returned alone.
  - `pkg/crypto/rand/pkcs11.go`'s `newPKCS11Resolver` discarded `Finalize`/`CloseSession` failures on every construction-time rollback path, and `Close` discarded `Logout`, `CloseSession` and `Finalize` outright. Both now collect the failures with `errors.Join` instead of losing them.
  - `pkg/staticpw/team_store.go`'s `Create` and `pkg/staticpw/dao_store.go`'s `CreateFolder` discarded the duplicate/marker lookup error entirely, so a real storage failure (not "not found") was silently treated as "the name is free" and the create proceeded. Both now return any lookup error other than the not-found sentinel.
  - `pkg/pivcert/pkcs11/slotmodel.go`'s `enumeratePrivateKeys` and `enumerateCertificates` dropped their `FindObjectsFinal` errors. Both now join a failure (new `ErrFindObjectsFinalFailed`) into the returned error through a shared `joinFindObjectsFinalErr` helper.
  - `sdk/go/acme/transport/mcp/transport.go`'s `handleHTTPError` read the error response body with an unbounded, error-discarding `io.ReadAll`. It now reads through `io.LimitReader` (new `maxHTTPErrorBodyBytes`, 1 MiB, matching the cap `sdk/go/login.go` already applies) and includes a read failure in the resulting message instead of dropping it.
  - `sdk/go/client/ssh/local.go`'s `ResolveLocalSigners` discarded `os.UserHomeDir`'s error and fell back to an empty home directory, which searches the wrong (root-relative) paths for identity files. It now returns the error.
  - `pkg/backend/avr/key.go`'s `keyAttributes` and `pkg/backend/avr/attestation.go`'s `checkAliasCertificate` both discarded `AttestLevel`'s error for a crypto tier the host cannot classify. Read against `NewBackend`'s identical, already-established handling of this exact condition (tiers extend, so refusing here would take a fleet down on a host upgrade alone) and against `hasDeviceKey`, which already gates both call sites' current callers on a classified tier: the decision is to keep the fail-safe-to-`Unattested` behavior, not turn it into a hard failure, but log `ErrUnknownCryptoTier` instead of discarding it, matching `NewBackend`'s own `logger.Warn` call for the same condition.
  - `pkg/acme/server/handlers/challenge.go`'s `parseChallengeAsDynamicPortAssignment` never actually returned a non-nil error on any of its paths (a non-numeric or out-of-range trailing segment is valid input meaning "no port", not a parse failure). The dead `error` return is removed from its signature, and its three callers (two in `challenge.go`, one in `endorse_eab.go`) updated.
