- **A CSR-signed login certificate carries the caller's tenant SPIFFE SAN** (go-xkms#1602, #1622): with a trust domain configured, `SignCSR` under the `client` profile or no profile stamps `spiffe://<tenant>/user/<CN>` for the authenticated caller's tenant, so go-qrdb login derives the tenant from the certificate. Other profiles (`code-signing`, `server`, ...) get the SAN only when the request names a tenant, so code-signing and server CSRs, including an empty or wildcard CN, issue without an explicit tenant.
