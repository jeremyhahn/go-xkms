- **Backends can be registered from outside go-xkms** -- an external Go module can now register its own backend type from its `init()` with `xkms.RegisterExternalBackend(xkms.ExternalBackend{Type, Factory})`, which the SDK re-exports as `RegisterExternalBackend`. The registered name becomes valid everywhere a built-in backend name is: `BackendType.IsValid`, `types.StoreType.IsValid`, `types.ParseStoreType` and the backend segment of a Key ID. Its keys carry the same name as their `StoreType`, and `AutoInitialize` constructs it from `AutoConfig.BackendConfigs` like any compiled-in backend. The name claim beneath the hook is `types.RegisterBackendType`. A refused registration returns `*types.BackendTypeRegistrationError`, which matches `types.ErrInvalidBackendTypeName`, `types.ErrBackendTypeRegistered` or `xkms.ErrNilBackendFactory`. Refusals cover an empty or malformed name, a built-in name, a name that is already registered and a missing factory. The backend registry and factory maps are now lock-free copy-on-write maps. Documented in `docs/crypto-backends/engineering.md`.
