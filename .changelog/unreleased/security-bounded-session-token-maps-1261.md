- **Two families of per-request, in-memory state only ever grew, and one held secret key material with no destruction path.** Both are fixed without any behavior change to a caller that completes its ceremony promptly.
  - `pkg/keyprovider/frost.FrostBackend.sessions` (build tag `frost`) recorded a `SigningSession` -- including the participant's secret Round-1 nonces -- on every `GenerateNonces` call, but nothing ever read it back: `SignRound` takes its nonces from the caller's own `NoncePackage` by design (see `docs/frost/security.md`; the caller holds and is responsible for zeroizing its nonces between rounds), `ExpiresAt` was never checked, and the only cleanup was `Close`. The map, its `SigningSession` type, and `DefaultSessionTimeout` are removed; `docs/frost/architecture.md` and the package doc no longer describe a server-side session the code never had.
  - `pkg/backend/software.SoftwareBackend.importTokens`, `pkg/keyprovider/symmetric.Backend.wrappingKeys`, and `pkg/backend/azurekv.Backend.importTokens` each cached the ephemeral RSA wrapping keypair a `GetImportParameters` → `WrapKey` → `ImportKey`/`UnwrapKey` ceremony needs, in a plain map keyed by import token. None of the three enforced their own 24-hour `ExpiresAt`, none capped how many ceremonies could be in flight, and only the software backend zeroized on shutdown -- the symmetric backend never cleared its map at all, even on `Close`. A caller (or attacker) that requested import parameters and never finished the ceremony left a live wrapping keypair -- for the symmetric backend, an unsealed `*rsa.PrivateKey` -- resident for up to 24 hours, unboundedly.
  - New shared `pkg/backend/importtoken` package: a generic `Store[T]` that sweeps expired entries on every `Put`, enforces a hard cap (`*LimitExceededError` rather than silently evicting another caller's live ceremony -- unlike a session cache, one entry cannot substitute for another, so evicting the oldest would take a wrapping key away from whoever has been waiting longest with no signal until their later `UnwrapKey` inexplicably failed), and always runs a caller-supplied destroy callback on eviction (sweep, `Take`, `Delete`, or `Close`). `SealedRSAKey` factors out the seal/open/parse/destroy handling the software backend already had for its wrapping keys (private half inside a `*secure.Secret`, opened into a `*secure.Buffer` only for the duration of one `Use` call) so the symmetric backend's previously-unsealed `*rsa.PrivateKey` gets the same protection.
  - A token is now single-use: `UnwrapKey`'s `Take` consumes it -- successful or not, since the wrapping key was already opened to discover a failure -- so a completed or failed ceremony cannot be replayed, and the redundant "delete after successful import" step in each `ImportKey` is gone (`azurekv`'s `UnwrapKey` parses its private key from the wire-supplied `WrappedKeyMaterial.ImportToken` rather than this store, so its fix is scoped to bounding and zeroizing that dead-but-still-sensitive map, not to consumption semantics).
  - Files: `pkg/backend/importtoken/{store,errors,rsakey}.go` (new), `pkg/keyprovider/frost/{backend,rounds,doc}.go`, `pkg/backend/software/software.go`, `pkg/keyprovider/symmetric/backend.go`, `pkg/backend/azurekv/{azurekv,azurekv_importexport}.go`, `docs/frost/architecture.md`.
  - Verified by: new tests in `pkg/backend/importtoken` (token consumption, expiry sweep, cap enforcement, eviction zeroization) and in each of the four backends (single-use tokens, cap enforcement, expiry sweep, `Close` zeroizing pending material); `go vet` and `gofmt` clean under `codec_cbor codec_json codec_msgpack tpm_simulator frost` (and separately under `azurekv`); full `-race` suites green for `pkg/keyprovider/frost`, `pkg/backend/software`, `pkg/keyprovider/symmetric`, `pkg/backend/importtoken`, and `pkg/backend/azurekv`.
