- **Password vault key factors on the server: PIV (slot 9d), certificate and TPM keys.** A key factor is enrolled with the key's public key or certificate; the server draws a fresh 32-byte secret sealed to it (`pkg/vaultkey`: ECDH-ES with an HKDF-SHA256 KDF for EC P-256/P-384/P-521, RSA-OAEP-256 for RSA of 2048 bits or more), wraps the DEK under a key derived from the secret, and keeps only the sealed challenge, a key-check value and the key's SPKI SHA-256 fingerprint. To unlock, the private key's holder recovers the secret (`vaultkey.Open`, through any xkms key backend: `NewBackendToken`) and sends it with the fingerprint. The server cannot unlock alone and the DEK never leaves it. New wire fields on every transport (`public_key`, `certificate`, `key_fingerprint`, `key_ref`; factor `key_algorithm`, `key_challenge`, `key_check`, `certificate_subject`), new factor types `piv`, `certificate`, `tpm`, and `ErrVaultKeyExists` (409). The last-factor refusal now reads "cannot remove the last unlock factor".
