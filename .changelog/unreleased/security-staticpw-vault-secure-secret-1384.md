- **`pkg/staticpw`: `VaultCredential.Secret` is now `*secure.Secret`, and `pkg/testutil/vaulttest`'s `SimulatedKey.PIN` test double follows the same rule.** The passphrase, hmac-secret output, and recovery code a vault factor wraps a DEK under were held as a plain `[]byte` struct field; they are now sealed in protected memory at the servicer boundary (`vaultCredential` in `pkg/xkms`) and opened only to derive a factor's key-encryption key (`vaultFactor.kek`) or check its length (`VaultCredential.validate`), each time destroying the opened buffer immediately after use. Wire and transport types (`transport.PasswordVaultCredential`, the REST/gRPC/MCP request types) are unchanged — they remain the plaintext boundary the analyzer does not flag. Closes the secure-analyzer rule-3 findings on `pkg/staticpw/vault.go` and `pkg/testutil/vaulttest/simkey.go` (go-xkms#1384).
