- **Wiring a store into a shared XKMSService no longer races the requests reading it.** The store setters (`SetBarrier`, `SetPINManager`, `SetPasswordStore`, `SetPasswordStoreManager`, `SetPlatformStore`, `SetCredentialService`, `SetPolicyManager`, `SetCA`, `SetCustodianClient`, `SetShareClient`) assigned plain fields with no synchronization. A host that mounts the xkms ServiceModule composes its stores on first use by any transport (`compose.Stores.Wire`), so one transport's wiring could run while another's request read the same fields -- a data race the race detector reports. Each of these references is now held in a lock-free atomic holder (`subsystem[T]`, over `atomic.Pointer`), and every service method loads it once, so a request sees one consistent store for its whole duration.
  - Files: `pkg/xkms/subsystem.go`, `pkg/xkms/service.go`, `pkg/xkms/servicer_{barrier,ca,ca_tcg,credentials,custodian,password,pin,policy,seal_store,share}.go`.
  - Verified by `TestWire_ConcurrentWithServiceReads` (`pkg/compose`, run under `-race`: `Stores.Wire` repeated concurrently with a read of every wired store through the service; it reports 10 data races on the previous code), and `TestSubsystem_ZeroValueHoldsNothing` and `TestSubsystem_LoadReturnsTheLatestStore` (`pkg/xkms`).
