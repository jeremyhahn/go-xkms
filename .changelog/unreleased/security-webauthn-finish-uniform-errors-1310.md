- **gRPC and SDK REST login finish leaked full go-webauthn error text, reopening the account-enumeration oracle #1296 closed on the browser route** (#1310).
  - `pkg/api/grpc/service_fido2.go`'s `FinishAuthentication` echoed the raw service error as `status.Error(codes.InvalidArgument, cErr.Error())`, and `pkg/api/rest/handlers_fido2.go`'s `handleSDKFinishAuthentication` echoed it as a 400 body with the same text. A finish against a decoy session (unknown or refused account) said "user not found"; a wrong assertion against a real account showed go-webauthn protocol detail — distinguishable on both transports even though the browser route already hid it.
  - Added `webauthn.ClassifyLoginFinish` (`pkg/webauthn/errors.go`), the one place that classifies a login-finish error into a missing session, an expired session, or the uniform failure bucket (wrong assertion, unknown or refused account, account not in standing, unknown credential, or a malformed assertion). The browser route (`Handler.handleLoginFinishError`), gRPC (`loginFinishStatusError`) and SDK REST (`Server.writeLoginFinishError`) all call it, so all three transports agree: every login-finish failure gets one fixed response — gRPC `codes.Unauthenticated` with the text "verification failed", REST 401 with code `verification_failed` — except a missing or expired session, which stays a distinct 400/`InvalidArgument`, matching the browser route. `pkg/xkms/servicer_fido2.go`'s `FinishAuthentication` now classifies a malformed assertion's parse failure through `webauthn.NewVerificationError` too, so it folds into the same uniform bucket on gRPC and SDK REST instead of leaking as a bare 400. The real cause is logged server-side at Warn on every transport, never returned to the caller.
  - Files: `pkg/webauthn/errors.go`, `pkg/webauthn/http/handler.go`, `pkg/xkms/servicer_fido2.go`, `pkg/api/grpc/service_fido2.go`, `pkg/api/rest/handlers_fido2.go`, `docs/webauthn/api.md`.
  - Verified by: `pkg/api/grpc/service_fido2_finish_uniform_test.go` (decoy finish and wrong-assertion finish against a real account produce byte-identical gRPC status and message; a missing session stays distinct), `pkg/api/rest/handlers_fido2_finish_uniform_test.go` (same parity for SDK REST, JSON-equal bodies), `pkg/api/rest/handlers_fido2_test.go` (`TestHandleSDKFinishAuthentication_ParseError` updated for the new uniform 401).
