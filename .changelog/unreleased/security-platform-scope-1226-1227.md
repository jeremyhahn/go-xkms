- **Platform-global state is refused to tenant-scoped callers on every transport (#1226, #1227).** The RBAC gate resolves a self-scoped permission against the caller's own tenant, so a tenant-local Admin passed it for the sealed platform store (`keys:*`), credential submission, the system barrier (`seal:*`, `barrier:*`), the token PINs (`pin:*`), the server's PIV card (`piv:*`) and the PCR policies (`policy:*`). It could read the platform's backend credentials out of the platform store, overwrite or delete them, seal the platform for every tenant, delete the recovery keys, rekey custody, take the SO PIN, lock the token, overwrite the server card's PIV slots and delete the platform PCR policies. Every `XKMSService` method on these subsystems now calls `requirePlatformScope` first: `SealStore*`, `SubmitCredential`, the new `ListCredentials`, every system-barrier method, every PIN method, the eight PIV slot methods and every `Policy*` method. The refusal is the tenant binding's `*xkms.TenantBindingError`, which answers REST 404, gRPC `NotFound` and MCP `JSONRPCCodeNotFound` with the unknown-tenant message. The platform identity, and an in-process caller with no identity, are unaffected. `BarrierEnableEncryption` and the per-tenant barrier operations keep their tenant binding. No transport holds these subsystems any more. REST, gRPC/Unix and MCP call the service methods: the REST platform-store, policy, credential, barrier, PIN and PIV handlers, the gRPC barrier, PIN and PIV RPCs, and the MCP barrier and PIV methods. `rest.Config` loses `Barrier`, `PINManager`, `PlatformStore`, `PolicyManager` and `CredentialService`. `mcp.Config` loses `Barrier`, and `mcp.Server` loses `SetBarrier`. `pkg/api/grpc` loses `SetBarrier`, `GetBarrier`, `SetPINManager` and `GetPINManager`. REST barrier initialize and unseal keep the secret in protected memory through the new `BarrierInitializeWithCredentials` / `BarrierUnsealWithCredentials`. Side effects:
  - Production gRPC and MCP barrier and PIN calls previously answered "not configured", because their package-level references were never set. They now serve the composed barrier and PIN backend.
  - A service without the subsystem answers 503 / `Unavailable` / `ErrCodeServiceUnavailable`.
  - `GetLockoutStatus` no longer panics on a backend that reports no lockout (the software backend).
  - `BarrierInitializeShamir` applies a request's threshold/total only when one is set, because the REST, gRPC and MCP wire forms carry only the secret.
  - REST `GET /barrier/status` and `GET /pin/lockout` now emit the `transport` response types, which have the same JSON field names.
