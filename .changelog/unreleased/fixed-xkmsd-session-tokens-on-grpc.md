- **xkmsd's session tokens authenticate on every unified-server transport.** The embedded qrdb node's own auth chain (gRPC, MCP) knew only mTLS, so a token xkmsd minted, accepted on REST, was refused there with `no_peer_cert`.
  - xkmsd now registers a bearer authenticator on the node through qrdb's `WithAuthenticators` seam (`pkg/server/qrdb_bearer.go`). It reads the request's Authorization through qrdb's `HTTPAuthorizationFromContext`, which every transport feeds (go-qrdb v0.25.0). It declines with `ErrUnauthenticated` when there is no bearer token, verifies with the live xkms authenticator (reloads apply), and never admits a request through the no-op authenticator.
  - It reports its method as unobservable (`UnobservableMethodAuthenticator`): a session token says who, not how. Its issuers therefore enforce the account's permitted-method policy when they mint. WebAuthn already did; the PIV/mTLS login now does too (`CheckAuthMethod` for `mtls`), so an account that may not use a certificate gets no token.
