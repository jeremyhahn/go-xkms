- **xkmsd's session tokens authenticate on the unified gRPC surface.** The embedded qrdb node's own auth chain (gRPC, MCP) knew only mTLS, so a token xkmsd minted, accepted on REST, was refused there with `no_peer_cert`. xkmsd now registers a bearer authenticator on the node through qrdb's `WithAuthenticators` seam (`pkg/server/qrdb_bearer.go`). It verifies with the live xkms authenticator, so reloads apply, and never admits a request through the no-op authenticator. MCP is not covered yet: qrdb passes the MCP request's Authorization header to authenticators only through `pkg/auth.HTTPAuthorizationFromContext`, which its SDK does not re-export.
