- **Password vault integration suite.** `make integration-test-password-vault` (replacing `integration-test-xkey-password`, whose local-store tests it folds in and brings up to date) runs every vault factor on its real token against a real xkmsd in the devcontainer -- passphrase, passkey on xkey's virtual authenticator, certificate key, TPM on swtpm under `platform` and a named policy, PIV on SoftHSM -- with recovery, two-user isolation and the browser bridge through the real native host. Shared harnesses: `test/integration/xkmsdtest` (a real xkmsd) and `test/integration/xkeytest` (the virtual authenticator, now also used by the logins suite). Fixes it found: xkmsctl's passkey verbs take `--device` to name the security key; `xkey password vault|unlock --key` log in to a PIV card or PKCS#11 token named by `--pkcs11-token`/`--pkcs11-library` (or the config's `piv` section) with `XKEY_PIV_PKCS11_PIN`; xkmsctl, xkey and `pkg/localtpm` open a TPM over TCP as `--tpm-device tcp://host:port`.
