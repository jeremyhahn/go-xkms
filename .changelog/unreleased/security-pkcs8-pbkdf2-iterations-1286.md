- **Encrypted PKCS#8 key storage now derives its wrapping key with 600,000 PBKDF2-HMAC-SHA256 iterations, not 10,000.** `pkg/encoding/pkcs8.go` and `pkg/keyprovider/pkcs8/pkcs8.go` each pinned their own `*pkcs8.Opts` with `IterationCount: 10000` — a duplicate that could (and, absent this fix, eventually would) drift out of step, silently giving one caller a weaker iteration count than the other. 10,000 was already below OWASP's 2023 recommendation for PBKDF2-SHA256; a stolen encrypted key blob was cheaper to brute-force than it should be. There is now a single shared value, `encoding.PKCS8EncryptOpts` (`pkg/encoding/pkcs8.go`), at 600,000 iterations — OWASP's 2023 figure, well above `pkg/crypto/kdf.MinPBKDF2Iterations`, enforced by a compile-time assertion — which `pkg/keyprovider/pkcs8` now imports instead of keeping its own copy. No migration is needed: PBES2 records its own iteration count in the encrypted blob, so a key encrypted at 10,000 iterations by an earlier release stays decryptable exactly as before; only newly encrypted keys use the higher count.
  - Files: `pkg/encoding/pkcs8.go`, `pkg/keyprovider/pkcs8/pkcs8.go`.
  - Verified by `pkg/encoding/pkcs8_test.go`'s new `TestEncodePKCS8_IterationCount` (parses the PBES2 parameters out of a freshly encrypted blob and asserts the iteration count is the new shared constant) and `TestDecodePKCS8_LegacyIterationCount` (encrypts a blob at the old 10,000-iteration `*pkcs8.Opts` directly, then confirms `DecodePKCS8` still decrypts it). Raising the iteration count 60x has a measured cost: `pkg/encoding`'s suite went from an estimated ~5.6s to 8.3s (five encrypt/decrypt round trips at ~0.55s each instead of ~0.01s); `pkg/keyprovider/pkcs8`'s 21.8s suite is unaffected within measurement noise, since only one of its tests encrypts a key. Both stay well under the 2x/10s regression bar; no test-only iteration-count override was added.
  - Fixes #1286.
