- **REST, MCP and the ACME admin JSON-RPC no longer send internal error text to clients** (go-xkms#1118). A 500 from REST put the raw service error (storage paths, backend and library messages, barrier state) in the response body, and an MCP tool failure on the internal code returned `KeyOpError.Error()` verbatim. Client-facing errors keep their text: REST 4xx, 501 and 503, and classified MCP errors (InvalidParams, NotFound, Forbidden, ServiceUnavailable, MethodNotFound, and classified conditions such as a sealed barrier that JSON-RPC can only put on the Internal code). Internal errors now carry a fixed message (`internal server error` on REST, `xkms: internal error` on MCP), and the full error is logged server-side with the method, path or tool, and correlation ID. The scrub is central, not per call site. On REST, `writeError`/`writeErrorWithMessage` call `clientErrorText`, and a new `errorLogMiddleware` on both the legacy router and `BindRoute` supplies the request context. The SSH envelope and PKCS#11 state writers call the same function. On MCP, `ClientError` renders the tool result, a new `KeyOpError.Classified` flag separates classified conditions from the unclassified floor, and `InvokeMethod` logs what was withheld. The ACME admin `handleMCP` no longer puts the denial reason or an internal error in `error.data`. `tenantgate.ErrTenantNotFound` no longer embeds the registry lookup error in its text. Status codes are unchanged. Documented in `docs/rbac/api.md` under "Internal error responses".
