- **Remote PKCS#11 tokens no longer lose keys on file storage.** System-scope token records were keyed under an empty path segment (`pkcs11state//<token>/`) that file storage collapses, so a remote-mode module loaded none of its objects and its next key reused handle 1, overwriting an existing key. The system scope is now stored under `pkcs11state/system/<token>/`; existing system-scope remote tokens must be re-provisioned (pre-release, no migration). The service also refuses a token label of `.` or `..` (`ErrPKCS11StateTokenDotSegment`) and a key or list prefix with `.`/`..`, empty interior or leading-`/` segments (`ErrPKCS11StateKeyPath`), which a path-normalizing store would resolve outside the token's namespace.
