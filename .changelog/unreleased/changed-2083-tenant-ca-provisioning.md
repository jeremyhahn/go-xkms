- Tenant login CA keys can now be provisioned by xkms, behind the opt-in `datastore.tenant-login-ca-keys` (default off, so an upgraded deployment keeps the tenant login CAs go-qrdb already stored and the login certificates they issued). Turn it on for a fresh deployment or after re-issuing every tenant's login credentials. With it on, a new tenant gets its key when it is created; if the key cannot be made, the tenant is deleted again and the error says so. At startup every existing tenant, the system tenant included, gets its key before the server serves, and a failure stops startup. The key factory reads the key backends only after they are initialized, which removes a data race at startup (#2083).
- Deleting a tenant now fences provisioning that runs at the same time: no login CA key or certificate outlives the deletion, and a deleted tenant is not provisioned again unless it is created again. If a node dies while making a tenant's key, startup on the other nodes fails with an error naming the claim holder; after fencing that node, list the holder in `datastore.tenant-login-ca-fenced-holders` and restart (#2083).
