- **OIDC credentials on every xkmsd surface, `xkmsctl oidc`, xkey's server mode, the SDKs and the web console.** REST `/api/v1/oidc/credentials` (list, create, and per credential `{scope}/{name}`: get, delete, `import`, `refresh`, `token`, `device`, `device/poll`); gRPC/Unix `OIDCCredential{Create,Import,Get,List,Delete,Refresh,GetAccessToken,DeviceStart,DevicePoll}`; MCP `oidc.credential.*`; the QUIC, MCP, REST, gRPC, Unix and embedded client transports (USB: not served by the phone). Permissions `oidc_credentials:{create,get,list,update,delete,token}`, xkms-owned and ScopeSelf; Admin and Owner hold all, the built-in User role `get`, `list` and `token`. Errors classify through `apierrors.OIDCCredentialClassOf`. xkmsd builds the service (and its scheduler) whenever it has a barrier registry and its qrdb node; an embedding host's module composes it from `Deps.Leases` (the host qrdb client's `Coordination()`), feature `oidc-credentials`. `xkmsctl oidc templates|create|login|import|list|get|token|refresh|delete` (`import --codex-auth`, `token --codex-auth-out`). xkey: with an xkmsd configured the existing `xkey oidc` commands act on server credentials (`providers add/list/remove`, `login --provider`, `token`, `refresh`, new `import`), `providers list` shows both backends, and `--local` keeps the local backend; without an xkmsd, xkey's local OIDC is unchanged. Go SDK: the transport types, `CodexAuthFile`, `ParseCodexAuth`, `BuildOIDCCredentialService`; TS SDK: `client.oidcCredentials` with `waitForDeviceLogin`; the web console's OIDC Credentials view (`#/oidc/credentials`, capability `oidc_credentials`). Docs: `docs/oidc-credentials/`.
