- **A paired phone can no longer plant attestation or TLS trust anchors on the laptop through sync, and the classifier no longer grants `android-hardware` from issuer name strings** (#1304). `remote.syncTrustStore` (and the pull side of `xkey device sync`, and CA sync) imported every certificate through `truststore.AddPEM`, which auto-classifies. `ClassifyCertificate` filed any certificate whose issuer O contained "Google" and whose issuer CN contained "Attestation" as `android-hardware`, the pool `attestation.LoadTrust` verifies Android attestation against, so a phone could push a self-signed "Google ... Attestation" CA and then vouch for any device. A self-signed CA it pushed became `user-ca`, a TLS anchor for `xkey auth`.
  - New purpose `truststore.PurposeSynced` (`synced`): a quarantine no trust decision consumes. It is absent from `tlsAnchorPurposes`, and the new `truststore.IsAnchorPurpose` is false for it; the attestation verifier's pool builder now refuses any non-anchor purpose with `ErrUnsupportedPurpose`. The operator promotes a synced certificate explicitly with `xkey trust classify <fingerprint> --purpose <purpose>`.
  - `sync.TrustStoreAccessor` no longer embeds `backup.TrustStoreWriter` (the auto-classifying `AddPEM`); it requires `ImportPEM(pem, *truststore.AddCertificateOptions)`, reusing the stores' existing caller-chosen-metadata import. `ApplyTrustStoreDelta` and `ApplyCADelta` (certificate and chain) import with `Purpose: synced, Source: sync`. User-initiated imports (`xkey trust add`, GUI import, backup restore) keep auto-classification.
  - `ClassifyCertificate` grants `android-hardware` only for the Android key attestation extension OID or a byte-exact match against the embedded Google Hardware Attestation Roots. The issuer-string heuristic is gone; it also never matched Google's two RSA roots (their DN carries only a serial number), which now classify correctly.
  - The bridge `xkey device listen` and `xkey fido2` build now carries an `audit.NewSlogLogger` audit logger and the paired device's address/name as `DeviceID`/`DeviceName`. Each `remote.syncTrustStore`/`syncOATH`/`syncPasswords` write is audited as the new `audit.OpSyncApplied` (security severity), success or failure, with received/added/updated/skipped counts; a failed audit write fails the call as `ErrSyncFailed` without leaking the local error text to the phone.
