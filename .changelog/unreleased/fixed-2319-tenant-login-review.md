- **Tenant login review fixes (#2319)** — xkmsd reads `webauthn.tenant_hosts` from its config; the SDK REST login (`/api/v1/webauthn/sdk/authentication/*`) applies the same host rule and `X-Tenant-Id` fallback as the browser route, so a mapped host decoys a login naming another tenant; adding a passkey enrols on the signed-in identity's tenant instead of failing with `session_account_mismatch`.
- **TypeScript login finish names the tenant (#2319)** — `AuthClient.webAuthnFinishLogin` takes an optional tenant and sends it as `X-Tenant-Id`, and the svelte-auth LoginPanel passes the organization it sent at begin, so a tenant login on a host without a `tenant_hosts` entry finishes on that tenant's relying party.
- **Tenant add-passkey finish and CORS (#2319)** — add-passkey begin (`/api/v1/webauthn/credentials/begin`) returns the signed-in tenant in `X-Tenant-Id`, the public `/api/v1/webauthn/registration/finish` route uses that header to finish on the tenant's relying party, `AuthClient.webAuthnAddCredentialBegin` returns it as `tenantId` and `webAuthnRegisterFinish` echoes it, and the REST CORS policy allows and exposes `X-Tenant-Id`.
