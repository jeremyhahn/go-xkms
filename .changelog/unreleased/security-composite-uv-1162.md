- **The xkey FIDO2 authenticator no longer claims user presence or user verification for credentials whose backend performed neither** (#1162). The composite key backend OR-merged `HandlesUserPresence` and `HandlesUserVerification` across its members. In a composite that also held a phone, credentials whose key was in the software or TPM member were affected in two ways. First, `getAssertion` and `makeCredential` skipped the local presence check and still set the UP flag. Second, both set the UV flag even though no verification happened. Relying parties therefore received false UP and UV claims.
  - Both answers now come from the backend that owns the credential key, through the new `FIDO2KeyBackend.HandlesUserPresenceFor(backendID)` and `HandlesUserVerificationFor(backendID)`. The composite routes each question to the member that owns the key, and answers false for an empty or unregistered backend ID.
  - `getAssertion` skips its local presence check only when the owning backend collects presence. It sets UV without a `pinUvAuthParam` only when the owning backend verifies.
  - `makeCredential` sets UV only when the backend that created the key verifies.
  - The composite's `Capabilities()` flags are now the AND across its members. They apply where the owning backend is not known yet:
    - `makeCredential`'s presence check runs before the key exists. A mixed composite therefore always runs the local check, even with a phone as the default.
    - The pre-generation `excludeList` credProtect check does not assume a verification that a software default will not perform.
    - `getInfo` does not advertise `uv=true` for a mixed composite.
  - A composite containing only a phone behaves as before.
  - Files: `xkey/pkg/authenticator/keybackend/{keybackend,composite,adapter}.go`, `xkey/pkg/authenticator/{cmd_makecredential,cmd_getassertion,cmd_getinfo}.go`, `xkey/pkg/phone/phone.go`, `xkey/docs/fido2/engineering.md`.
  - Verified by these tests:
    - `TestCompositeUV_FlagComesFromOwningMember`: a software plus phone composite over CTAP. Software-created and software-owned credentials get UV=false; phone ones get UV=true.
    - `TestCompositeUP_LocalCheckUnlessOwnerCollectsPresence`: the local presence check runs for an assertion from a software-owned credential and is skipped for a phone-owned one.
    - `TestCompositeUV_UnknownOwnerClaimsNothing`, `TestCompositeUP_UnknownOwnerRunsLocalCheck` and `TestCompositeUV_GetInfoDoesNotAdvertiseUV`.
    - `TestCompositeBackend_Capabilities_UserGesturesAreAND` and `TestCompositeBackend_HandlesUserGestureFor`.
