- **The software PIV certificate store persists as go-qrdb DAO records** -- `pkg/pivcert/file`'s `NewFileBackend` takes `FileStorageConfig{DAOs}`, the injected go-qrdb DAO factory, instead of a `storage.Backend`, and keeps one `piv_certificates` record per slot in the `pivcert` database (ID derived from the slot, lookups by it). The per-slot DER/PEM files and the `slots.json` metadata index are gone: PEM is produced on export and `List` derives slot metadata from each certificate. The `DEREnabled`/`PEMEnabled` fields and `ErrNoFormatEnabled` are removed, `ErrMissingBackend` is now `ErrMissingDAOFactory` (SDK: `ErrPIVMissingDAOFactory`), and `Delete` returns the new `ErrConflict` (SDK: `ErrPIVConflict`) when a concurrent store replaced the slot. `Close` no longer closes the underlying storage; its owner does. Certificates written by the old layout are not read.
