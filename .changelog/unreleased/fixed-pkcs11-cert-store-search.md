PKCS#11: concurrent reads on the certificate store no longer fail with `CKR_OPERATION_ACTIVE`, and a renewal read after concurrent saves no longer fails. Before, when `C_FindObjectsInit` failed, both `SessionPool.WithSearch` and the store's own search path returned without calling `C_FindObjectsFinal`. SoftHSM2 marks the session as searching before such an Init fails, so the session stayed poisoned for every later read. Both paths now finalize after a failed Init. The store's fallback path serializes searches per session. The store also serializes token writes against reads, because SoftHSM2 can persist an unreadable object when a write races other operations. The PKCS#11 certificate integration test now requires every concurrent save and read to succeed (DS-3754).
