- **A WebAuthn credential ID could be registered to a second account, overwriting the first account's credential record; the stores now refuse a credential ID that already exists** (#1295). `qrdbCredentialStore.Save` wrote the credential with an unconditional `kv.Put`, and `BackendCredentialStore.Save` with an unconditional `backend.Put`; only `MemoryCredentialStore` refused a duplicate. A registration whose authenticator reported an already-registered credential ID therefore replaced the owner's public key and user handle. `Save` now creates only: the qrdb store uses `PutIfAbsent`, the backend store `storage.Backend.PutIfAbsent`, and all three return `ErrCredentialAlreadyExists` with the stored record untouched (REST browser finish: 409 `credential_exists`). `Update` — the path a login's sign counter, clone flag and last-used time take — now also requires the stored credential to belong to the user the update names (`ErrCredentialOwnerMismatch`); the qrdb store's `Update` is a `CompareAndSwap` against the record it checked, so a credential deleted or replaced concurrently is never resurrected (`ErrCredentialUpdateConflict`). The backend store's `Update` no longer routes through `Save` (which would now refuse it).
  - `NewQRDBUserStoreAdapter` now requires a `qrdbtransport.GuardedKVClient` and fails construction with `*GuardedKVUnsupportedError` otherwise — the same capability `token.NewQRDBRefreshStore` already requires; there is no degraded read-then-write path. `pkg/testutil.QRDBFakeTransport` gained the three guarded verbs (and a compile-time `GuardedKVClient` assertion) so host-composition tests exercise them.

  - Verified by: `pkg/webauthn/credential_uniqueness_test.go`, table-driven over the memory, backend and qrdb stores (a duplicate ID under another user is refused and the owner's record survives; a sign-count/clone-flag update still works; an update naming another owner is refused; an update never creates), plus a lost-`CompareAndSwap` race, the guarded-KV construction requirement, and an end-to-end ceremony in which a second account presents the first account's credential and is refused. Existing login tests (sign counter update after `FinishLogin`) pass unchanged.
