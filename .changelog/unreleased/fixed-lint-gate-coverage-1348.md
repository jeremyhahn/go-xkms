- **`make lint`/`make vet` now cover the pkcs11/awskms/azurekv/gcpkms/vault/raft-tagged root-module code, and every `//nolint` in the codebase now names its linter and carries a reason** (#1348). `LINT_TAGS_root` only ever carried `TEST_TAGS`, so every file behind the hardware/cloud KMS backend tags and the raft clustering tag compiled (via `go build`/`go test`) but was never linted — the same "a tag nobody passes is a directory the toolchain never opens" gap #650/#682 already closed for test/integration and for xkey.
  - Two new root-module passes, `LINT_TAGS_root_backends` (`pkcs8,tpm2,awskms,gcpkms,azurekv,pkcs11,vault` unioned with the default set) and `LINT_TAGS_root_raft` (the default set plus `raft`), wired into both `make vet` and `make lint`. Each tag combination is one CI already proves compiles (the ci.yml `build`/`race`/`build-raft` jobs), verified locally with `go build`/`go vet` before being added to the gate.
  - Fixing what the new passes found surfaced real defects, not just style: `awskms.Decrypt` ignored the caller's OAEP hash choice (both branches of an `if opts != nil` set the same algorithm) and now honors an explicit SHA-1 request; `azurekv`'s symmetric decrypt appended a GCM tag directly onto the caller's ciphertext slice, risking a silent write into its spare capacity, and now allocates its own backing array; `pkcs11.DeriveKeyECDH` accepted a `ctx` parameter it normalized but never consulted, and now checks `ctx.Err()` before doing HSM work, matching `Backend.AttestKey`; two `SA4023` "comparison never true" findings in `azurekv.Sign`/`Verify` were dead `opts == nil` checks against a `crypto.Hash` value that can never be a nil interface; two `SA9003` empty-branch findings (`vault.DeleteKey`, `gcpkms.DeleteKey`) silently discarded a config/metadata cleanup error with no code in the branch at all, and now log or explicitly discard with a reason.
  - `nolintlint` is enabled with `require-explanation: true` and `require-specific: true`. Enabling it surfaced 76 pre-existing `//nolint` directives repo-wide that were either missing a reason or no longer doing anything (the underlying linter never fires there — most commonly `//nolint:errcheck` in a `_test.go` file, which `.golangci.yml` already excludes from errcheck, or a `//nolint:staticcheck` written against `key.PublicKey.X`-style deprecated-field access that a later `QF1008` rewrite simplified to the promoted `key.X` form staticcheck's `SA1019` check does not follow through embedding). Genuine suppressions (raw ECDSA/RSA coordinates for wire-format compatibility, PKCS#1 v1.5 support gated behind a documented reason, etc.) kept their `//nolint` with an accurate reason added; directives with nothing left to suppress were removed, in some cases exposing dead code (`pkg/backend/pkcs11/pkcs11_mock_test.go`'s unused `mockSigner`, `pkg/backend/pkcs11/signer_rsa.go`'s unused `rsaOID`, four unused test helpers in `pkg/backend/pkcs11/pkcs11_importexport_test.go`, one in `pkg/backend/vault/transit_double_vault_test.go`) that was deleted rather than re-suppressed.
  - `errcheck` v1.9.0 at `/usr/local/bin/errcheck` crashes on Go 1.27 export data, but nothing in this repository pins or invokes that standalone binary — `make lint`/CI use golangci-lint's bundled errcheck exclusively — so no version pin needed changing.
  - Files: `Makefile`, `.golangci.yml`, and the fixes/nolint reasons above span `pkg/backend/{awskms,azurekv,gcpkms,pkcs11,vault}`, `pkg/crypto/rand`, `pkg/pivcert/pkcs11`, `pkg/auth/token`, `pkg/acme/client`, `pkg/ca`, `pkg/certstore`, `pkg/tpm2`, `pkg/ssh/session`, `pkg/api/grpc`, `pkg/trust/resolver`, `cmd/xkmsd`, `examples/certificates/hardware/hybrid`, and `xkey/pkg/{ipc,gui/services}`.
