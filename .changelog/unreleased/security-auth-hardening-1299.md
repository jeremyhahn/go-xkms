- **Four independent bearer/session-auth gaps closed: a JWT with no `exp` claim, an OIDC ID token that failed audience validation salvaged through the userinfo endpoint, the Unix socket gRPC listener trusting file mode alone with no kernel peer-credential check, and an xkey SSH console ticket that never expired** (#1299).
  - `pkg/auth.JWTAuthenticator.validateToken` now parses with `jwt.WithExpirationRequired()`, so a token that omits `exp` entirely — which jwt/v5 otherwise treats as never expiring — is refused rather than accepted as a permanent credential. Operator key-file mode (`auth.jwt.public_key_file`) now refuses to start with the new typed sentinel `server.ErrJWTKeyFileIssuerAudienceRequired` unless both `issuer` and `audience` are configured; without them `JWTAuthenticator` skips both checks and accepts a token from any issuer for any audience so long as it is signed by the configured key. The internally-issued-token path (`pkg/auth/token.Issuer`) was already stamping `exp`/`iss`/`aud` on every access and refresh token and needed no change.
  - `pkg/auth.OIDCAuthenticator.validateToken` no longer falls back to the userinfo endpoint whenever ID-token validation failed for any reason (bad signature, wrong issuer, or — most dangerously — a mismatched audience); it falls back only when the token does not parse as a JWT at all (`jwt.ParseUnverified` fails), which is the only case that legitimately belongs to the opaque-access-token flow. Both `validateIDToken` and `validateAccessToken` now also refuse an empty `sub` claim (the existing but previously unused `ErrOIDCMissingSubject` sentinel), so neither an ID token nor a userinfo response can mint an `Identity` for nobody. RFC 7662 token introspection was not added for opaque access tokens — this authenticator's `OIDCConfig` carries no client secret to authenticate an introspection call with, and adding one is config/discovery plumbing of its own, tracked as a follow-up; the userinfo endpoint remains the opaque-token verification path.
  - `pkg/api/unix.GRPCServer` registers its keystore service with `WithLocalTrust` (RBAC off), trusting only the Unix socket's file mode and directory permissions — but had no check on who was actually on the other end of an accepted connection, and no check that a pre-existing socket directory hadn't been left group- or world-writable. `Start` now validates the socket directory (new `validateSocketDir`, mirroring `pkg/ssh/agent`'s own work-directory check: not a symlink, not writable by group or other, owned by this process) before binding, and installs `grpc.Creds` with a new accept-time transport credential (`peerCredentialTransport`) that reads the kernel-verified peer UID/GID via `pkg/peercred` and refuses any peer that is not the daemon's own uid, root, or an entry in the new `GRPCConfig.AllowedUIDs`/`AllowedGIDs` allowlist. The kernel peer-credential syscalls (`SO_PEERCRED` on Linux, `LOCAL_PEERCRED`/`LOCAL_PEEREPID` on Darwin) were previously duplicated in `pkg/acme/api/server`; both listeners now share the one implementation in the new `pkg/peercred` package, and `Start` refuses to run at all on a platform `pkg/peercred.CheckSupport` has not verified one for.
  - `xkey/pkg/gui/services.SSHConsoleService.resolve` redeemed a stored console ticket regardless of its age. It now refuses (and deletes) a ticket older than `consoleTicketTTL`, closing the case of a browser tab left open long after the connect dialog it belonged to was abandoned redeeming a ticket whose signer(s) and host-key policy were captured under stale conditions. A new clock seam (`SSHConsoleService.now`, defaulting to `time.Now`) makes the expiry path hermetic to test without a real 2-minute sleep.
  - Files: `pkg/auth/jwt.go`, `pkg/auth/oidc.go`, `pkg/server/server.go`, `pkg/server/errors.go`, `pkg/peercred/*` (new), `pkg/api/unix/grpc_server.go`, `pkg/api/unix/peercred.go` (new), `pkg/api/unix/sockdir*.go` (new), `pkg/acme/api/server/peercred_{linux,darwin,unsupported}.go`, `xkey/pkg/gui/services/ssh_console_service.go`.
  - Verified by: `pkg/auth`'s existing JWT/OIDC suites plus new cases (`TestJWTAuthenticator_AuthenticateHTTP/missing_exp_claim`, `TestOIDCAuthenticator_AudienceMismatchNotSalvagedByUserinfo`, `TestOIDCAuthenticator_EmptySubjectRefused_{IDToken,AccessToken}`); `pkg/server`'s `TestServer_CreateJWTAuthenticator_KeyFileRequiresIssuerAndAudience`/`_KeyFileWithIssuerAndAudience`; `pkg/peercred`'s own suite plus `pkg/acme/api/server`'s existing peer-credential tests (unchanged, now exercising the shared implementation); `pkg/api/unix`'s new `TestPeerCredentialPolicy_Allowed`, `TestGRPCServer_PeerCredential_SameUIDAccepted`, `TestValidateSocketDir_*`, `TestGRPCServer_Start_RefusesGroupWritableSocketDir`; `xkey`'s new `TestSSHConsole_Resolve_ExpiredTicketRefused`/`_UnexpiredTicketAccepted`. `go vet` and `gofmt` clean under `codec_cbor codec_json codec_msgpack tpm_simulator frost` (root) and `codec_json tpm_simulator ble` (xkey).
  - **Breaking:** operator key-file JWT mode (`auth.jwt.public_key_file`) now requires both `auth.jwt.issuer` and `auth.jwt.audience` to be set; a deployment that configured only `public_key_file` refuses to start until both are added.
  - Fixes #1299.
