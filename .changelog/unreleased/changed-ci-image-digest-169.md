CI: a new `ci-images` job hands the toolchain and integration images to the nine jobs that use them (ruling 169, the go-qrdb #1135 pattern). On a push to main it publishes them from the release runner with that runner's `RELEASE_REGISTRY*` credential (ruling 173). On other events, consumers pull main's image by digest when main published the same content hash, and otherwise build it locally with no push. Before this change, every job built its own image (17.5 min per PR). Each pulled image is held until the job's teardown; the reaper also removes stale registry-named CI images and keeps held ones; `internal/buildgates/ci_image_digest_test.go` enforces the handoff.
