- **Passkeys work for non-system tenants on xkmsd's public routes.** The refresh re-check binds the validated token's tenant before it looks a user handle up; public WebAuthn registration creates, reads and updates the account in the configured WebAuthn tenant; and invite enrolment starts the FIDO2 ceremony for the invite's own account in the invite's validated tenant instead of re-resolving its email in the system scope.
- **WebAuthn credential reads and writes no longer carry a non-system tenant binding.** The credential store is system bookkeeping run as the system service principal; it now clears the tenant the user store or an invite route bound, so qrdb's RBAC no longer refuses non-system registration and invite enrolment before the ceremony starts.
- **Invitation create, lookup and redemption run on a system context.** Invitations live in system storage; the invite's tenant binding no longer reaches them, so an RBAC-enforcing node completes the enrolment instead of refusing the invite store ("identity not in target tenant").
- **Passkey enrolment through an invitation outside the relying party's tenant is refused.** Begin and finish answer `ErrInviteTenantNotServed` (REST 403) instead of enrolling a passkey the login ceremony, which resolves accounts in the relying party's configured tenant only, could never sign in with. Tenant-aware passkey login follows as its own SPEC row.
- **An unknown invitation no longer reveals which tenant the relying party serves, and a user store without a tenant is refused.** Invite enrolment checks the served tenant only after the invitation is found, so an unknown invitation answers the same error for every tenant. The WebAuthn `UserStore` interface now requires `TenantID()`; a store that names no tenant is a typed error and is never treated as the system tenant. The refresh-token store runs as the embedded node's service principal on public routes (ruling 1041).
