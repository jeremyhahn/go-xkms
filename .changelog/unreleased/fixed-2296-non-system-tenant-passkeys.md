- **Passkeys work for non-system tenants on xkmsd's public routes.** The refresh re-check binds the validated token's tenant before it looks a user handle up; public WebAuthn registration creates, reads and updates the account in the configured WebAuthn tenant; and invite enrolment starts the FIDO2 ceremony for the invite's own account in the invite's validated tenant instead of re-resolving its email in the system scope.
- **WebAuthn credential reads and writes no longer carry a non-system tenant binding.** The credential store is system bookkeeping run as the system service principal; it now clears the tenant the user store or an invite route bound, so qrdb's RBAC no longer refuses non-system registration and invite enrolment before the ceremony starts.
