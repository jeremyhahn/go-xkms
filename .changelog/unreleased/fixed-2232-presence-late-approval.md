- **A late touch-dialog approval can no longer authorize a different FIDO2 request.** Under sudo, the zenity dialog opened for a presence request kept running after that request ended (for example when a hardware key won an authenticatorSelection), and approving it ran a plain `xkey touch` that approved whatever request was pending next. Each presence request now carries an ID and a lifetime: the dialog is stopped when its request ends, and its `xkey touch --request-id` approves only the request it was opened for.
