- **TPM symmetric keys are now sealed under the Platform SRK and need the USER PIN or the platform PCR policy to be used.** Before this change, `pkg/tpm2`'s `GenerateSymmetricKey` sealed every AES key under the Shared SRK, with no `userAuth`, no policy and `NoDA` set, and `SymmetricEncrypter` unsealed it with an empty password. Any process that could open `/dev/tpmrm0` and read the key blobs could recover the AES key without a PIN and in any PCR state. That covered every TPM2-backend symmetric key reachable through xkmsd, the PKCS#11 TPM2 backend and `C_DeriveKey`. Symmetric keys now go through the same `sealKeyInternal`/`unsealKeyInternal` path as every other secret sealed under the Platform SRK. `TPM2_Create` and `TPM2_Load` are authorized by the Platform SRK's USER PIN (a salted session) or, without it, by the PCR branch of its platform policy. The key object's own authorization is `attrs.Password` and, with `attrs.PlatformPolicy`, the platform policy, as for sealed data. `NoDA` is clear, so wrong passwords count toward DA lockout. The AES key crosses the TPM bus only inside salted, encrypted sessions. A parent other than the Platform SRK is refused with `ErrSymmetricKeyParent`. AES-GCM still runs in Go. **Breaking, no migration:** keys written by earlier releases are refused with `ErrUnprotectedSymmetricKey` rather than loaded. Delete each such key and generate a new one. Deleting a key does not remove its old `<CN>.priv` file, which still holds the unprotected key, so remove those files from the TPM2 key directory by hand. New keys are stored as `<CN>.blob`/`<CN>.pub` (plus `<CN>.policy` for platform-policy keys). `sealKeyInternal` now also wipes its copy of the sealed secret. Verified by `pkg/tpm2/symmetric_psrk_simulator_test.go`, which runs on the TPM simulator. It covers a round trip with the USER PIN, refusal with no PIN or a wrong PIN (`TPM_RC_AUTH_FAIL`) and both platform-policy branches. It checks that every `TPM2_Create`/`TPM2_Load` names the Platform SRK handle and that Shared SRK parents and pre-change blobs are refused. The #1147 bus recorder shows that neither the AES key nor the PIN crosses the bus. Documented in `docs/tpm2/engineering.md` §"Symmetric keys" (go-xkms#1148).
