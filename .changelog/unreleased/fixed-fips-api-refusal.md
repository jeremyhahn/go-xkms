- **A FIPS GCM refusal is no longer reported as a server fault.** Under `GODEBUG=fips140=only`, an AES-GCM request with a caller-supplied nonce or a truncated tag is refused (`ErrArbitraryIVGCMUnavailable`), and so is a tag size outside NIST SP 800-38D §5.2.1.2 in any mode. These refusals now reach the caller as a client-correctable error on every transport: gRPC `InvalidArgument`, REST `400`, MCP Invalid params. Before, gRPC and MCP returned `Internal` and REST returned `500`. All three read one classification, `apierrors.AEADSentinelClasses`. See `docs/fips/gcm-sites.md` (part of #23).
