- **An mTLS challenge no longer tells a real holder from a decoy** (#1517) -- `Challenge` put the enrolled certificate in `MethodData["enrolled_cert_pem"]`. For a CA-issued enrollment that certificate verifies under the CA, while a decoy's (#1402) is signed by a derived key, so anyone with the CA certificate could tell which users hold an mTLS enrollment. `Challenge` now carries only the certificate's public key, `MethodData["enrolled_public_key_der"]` (standard base64 PKIX DER, as PKCS#11 does), and `Verify` reads the key from there. `enrolled_cert_pem` is gone from the mTLS challenge.
