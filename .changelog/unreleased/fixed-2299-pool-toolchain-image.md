- **A same-repo pull request builds its CI images once, on the pool, and a hung apt fetch fails in minutes.** When main has not published the toolchain image for a pull request's content, `ci-images` now builds it once on the self-hosted docker pool and pushes it to the in-network pool registry (`scripts/ci-registry.sh pool`); consumer jobs pull it by digest instead of each running `make docker-build-toolchain`. Every Dockerfile `apt-get` runs under `timeout 300`, and each "Take the toolchain image" step is bounded at 30 minutes, so a stalled fetch from the apt cache no longer holds a job for hours (#2299). Main and fork pull requests keep the GHCR path.
- The pool handoff happens only when preflight puts every consumer on the self-hosted pool; when it picks GitHub-hosted runners, which cannot reach the pool registry, the consumers build the image themselves as before, and `scripts/ci-registry.sh use` refuses a pool reference on a hosted runner with a clear message (#2302).
- On the self-hosted forge, where every consumer keeps its fixed pool label, the pool step now always builds the image for a same-repo pull request, so `use` no longer fails on an unpublished toolchain hash (#2302).
