- **authenticatorSelection waits for user presence (#2345).** A browser sends CTAP 2.1 authenticatorSelection to every connected authenticator and uses the one the user touches; xkey answered at once, so it always won and a hardware key was never offered. Selection now asks for presence through the configured touch handler (honoring `--require-touch` and `--notify`) with UP_NEEDED keepalives, and answers OPERATION_DENIED on decline, USER_ACTION_TIMEOUT when nobody answers, and KEEPALIVE_CANCEL when the browser cancels after another key was touched. The CTAP 2.0 idiom (MakeCredential with a zero-length pinUvAuthParam) waits for the touch before its PIN_INVALID / PIN_NOT_SET answer. The prompt names the authenticator (`display-name`, default `xkey`) and the relying party when known. An approved Selection satisfies the presence check of the next MakeCredential or GetAssertion on the same CTAPHID channel within 30 seconds, once, so choosing xkey costs one touch.
