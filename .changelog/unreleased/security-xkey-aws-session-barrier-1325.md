- **The `xkey oidc aws` session -- the AWS DPoP private key and refresh token -- was always written unencrypted to `--session-store`, the one xkey secret store that never moved behind the barrier-first decision every other one already makes** (#1325).
  - `storeAWSSession`/`loadAWSSession` (`xkey/cmd/xkey/cmd/oidc_aws.go`) called `os.WriteFile`/`os.ReadFile` directly against `--session-store` (default `~/.xkey/aws-session.json`, non-atomic, mode `0600`) regardless of whether `xkey barrier init` had been run, so an initialized barrier protecting every other CLI secret (`xkey oath`, the OIDC RP token store, `xkey fido2 --storage barrier`) left the AWS refresh token and DPoP signing key in the clear. A new `awsCLISessionStore` (`oidc_aws_session_store.go`) closes the gap through the identical decision `openOIDCTokenStore` already makes for the standard OIDC session (go-xkms#4): barrier-encrypted when a barrier is initialized, the historical unencrypted file with one logged warning otherwise, and an explicit `--session-store` (directly, or saved on an AWS provider via `xkey oidc providers add --session-store`) bypassing barrier auto-detection entirely for a plain file at exactly that path. The background refresh worker forwards `--barrier-password-file` to the detached process the same way the OIDC RP auto-refresh loop already does; a `--barrier-password` value is never put on argv.
  - `dpopKey.SerializePrivateKey()`'s error was discarded (`dpopKeyPEM, _ := ...`), so a serialization failure silently stored a session with no usable DPoP key; it is now a typed `ErrAWSDPoPKeySerializationFailed` refusal. Two discarded `tokenResp.GetExpirationTime()` calls are handled the same way (`ErrAWSExpirationParseFailed` at login; a logged, non-fatal tick error in the auto-refresh loop).
  - `xkey/pkg/oidc.FileTokenStore` -- the GUI's pre-go-xkms#1203 fixed-key file store -- had no production caller left since #1203 replaced its only caller with `MemoryTokenStore`; it is deleted outright along with its dedicated tests and its now-unused `ErrEncryptionFailed`/`ErrDecryptionFailed`/`ErrInvalidEncryptionKey` sentinels, closing off a fixed-key file store a future caller could otherwise have reached for by mistake.
  - Files: `xkey/cmd/xkey/cmd/oidc_aws.go`, `xkey/cmd/xkey/cmd/oidc_aws_session_store.go` (new), `xkey/cmd/xkey/cmd/oidc.go`, `xkey/pkg/oidc/store.go`, `xkey/pkg/oidc/errors.go`.
  - Verified by `oidc_aws_barrier_test.go` (no-barrier warning + plain-file fallback, barrier-encrypted round-trip across two independent `openAWSSessionStore` calls proving neither the refresh token nor the DPoP key PEM appears in the on-disk ciphertext, wrong-password and no-password typed refusals, explicit `--session-store` bypassing the barrier) and the updated `oidc_aws_test.go`/`oidc_aws_cmds_test.go`; `go vet` clean on `xkey/cmd/xkey/cmd` and `xkey/pkg/oidc`.
