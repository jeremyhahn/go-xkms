- **An interrupted PKCS#8 key delete no longer leaves metadata a new key inherits.** A delete of a key whose blob is already gone still removes its metadata record, so a retry clears what an interrupted delete left. A key generation whose metadata write fails also drops any stale record under the identifier. Before, a delete that removed the blob but not the record made every retry answer key-not-found, and a later key of the same identifier inherited the orphan's tenant and Exportable flag (#2231).
- **A failed PKCS#8 key delete keeps the key's tenant ownership, and a failed generation rollback keeps the blob of a stale record.** `DeleteKey` removes the blob before the metadata record, so a tenant key stays listed for its tenant and its delete can be retried; a generation rollback whose metadata cleanup fails now keeps the blob and returns both errors (#2231).
