- **Another local user could plant xkey's IPC socket and receive the victim's user PIN from `xkey unlock`. The socket directory is now checked on both ends, the client checks who is listening, and there is no shared `/tmp` fallback.** With `XDG_RUNTIME_DIR` unset (typical on macOS and under cron, ssh or sudo), `xkey/pkg/ipc/socket.go` fell back to `/tmp/xkey-<uid>/xkey.sock`. `NewServer` accepted an existing directory at that path without checking its owner or mode, the GUI unlinked and took over a live socket, and every client dialed without checking the peer. Any user could create the directory first, listen in it, and collect PINs, passwords being saved by the browser extension, and PKCS#11 signing requests. Five changes close this. First, `runtimeDirFor` picks a per-user directory: `$XDG_RUNTIME_DIR`; on macOS `$TMPDIR`, then `~/Library/Caches`; elsewhere `~/.xkey/run`. Under sudo it uses the invoking user's home. It never picks `/tmp`, and it yields no path, refused with `ErrSocketPathUnresolved`, when no home can be resolved. Second, `NewServer` creates each missing component with `Mkdir(0700)` and re-validates it straight away. It refuses (`ErrSocketDirInsecure`) a directory that is a symlink, is owned by anyone other than the user, root or the sudo user, or has any bit beyond `0700`, and it never chmods or chowns a directory it did not create (`xkey/pkg/ipc/socketdir.go`). Third, every IPC client goes through the new `ipc.Dial`, which validates the directory, connects, and then checks the listener's kernel-reported uid. That client set is `ipc.Client`, the PKCS#11 module transport (`xkey/pkg/pkcs11/ipc_transport.go`) and the native-messaging host (`xkey/pkg/nativemsg/host.go`). The uid comes from `SO_PEERCRED` on Linux and `LOCAL_PEERCRED` on macOS and FreeBSD. Other platforms fail closed with `ErrPeerCredentialsUnsupported`. Fourth, a stale socket is unlinked only if it is a socket owned by a trusted uid in a valid directory (`ipc.ReclaimSocket`). The GUI takes over a live socket only on `ErrSocketInUse`, and only through `ReclaimSocket`. A regular file at the socket path is never deleted. Fifth, handler failures no longer echo their wrapped detail to the client. The server logs the detail and the client receives `ipc: handler returned error`, or the bare sentinel for an invalid message, a sealed barrier or a disabled browser extension. Root and the sudo user are trusted because `sudo xkey fido2` runs as root on the invoking user's behalf. **Behaviour change:** a `--socket` directly under `/tmp` or any other shared or group-writable directory is now refused. Point `--socket` / `XKEY_IPC_SOCKET` at a `0700` directory you own (go-xkms#1117).
