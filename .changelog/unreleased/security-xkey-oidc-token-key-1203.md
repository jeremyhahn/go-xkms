- **The xkey GUI no longer "encrypts" OIDC tokens with a key compiled into the binary, and no longer falls back to writing them in plaintext.** `xkey/pkg/gui/services/oidc_service.go`'s no-barrier fallback (`SetDataDir`, wired from `app.go` when `initializeDataDir` finds no barrier backend) opened `tokens.json` through `oidc.NewFileTokenStore` with the constant `oidcTokenEncKey = "xkey-oidc-token-store-encryption"` — a key anyone with the binary can read out of it, so `tokens.json` gave no real confidentiality — and, on any store error, silently reopened the same path with a `nil` key, writing the access and refresh tokens in the clear. `oidcTokenEncKey` and the nil-key fallback are both deleted. `oidc.NewFileTokenStore` now refuses to construct a store at all without a real key: a `nil` or empty `encryptionKey` returns `oidc.ErrInvalidEncryptionKey`, and `FileTokenStore.encryptToken`/`decryptToken` lose their plaintext branches entirely, so there is no remaining code path that can write an unencrypted token to disk. Without a barrier, the GUI now keeps OIDC tokens in an `oidc.MemoryTokenStore` for the life of the process — never on disk — and logs one `slog.Warn` naming the exposure ("OIDC tokens are kept in memory only and will not survive a restart") the same way the FIDO2 passkey store warns on its own no-barrier fallback (#181). With a barrier, `SetBackend`/`oidc.NewBackendTokenStore` are unchanged: tokens are barrier-encrypted and persist as before.
  - Files: `xkey/pkg/oidc/store.go`, `xkey/pkg/oidc/errors.go` (reuses existing `ErrInvalidEncryptionKey`), `xkey/pkg/gui/services/oidc_service.go`, `xkey/pkg/gui/app.go`.
  - Verified by `xkey/pkg/oidc/store_test.go` (`NewFileTokenStore` refuses a `nil` and an empty key; `TestFileTokenStore_NeverWritesPlaintext` proves every on-disk entry carries a GCM nonce and never contains the plaintext token strings; the decrypt-invalid-JSON and wrong-nonce-length tests now exercise the always-encrypted path), `xkey/pkg/gui/services/oidc_token_store_security_test.go` (no barrier: no file named `tokens*` is ever written, the in-memory store round-trips within the session, `svc.tokenStore` is an `*oidc.MemoryTokenStore`, and the warning logs exactly once; with a barrier: `SetBackend` still round-trips through the storage backend), and `xkey/pkg/gui/oidc_token_store_warning_test.go` (the same behavior through `app.initializeDataDir()`, mirroring `fido2_passkey_store_warning_test.go`). go-xkms#1203.
