- **Every `types.Sealer` now tells forged sealed data from an outage** -- new sentinel `types.ErrSealedDataAuthentication` (re-exported by the SDK, built with `types.SealedDataAuthenticationError`) is matched by `Unseal`, `UnsealInto` and `PlaintextLen` exactly when the sealed data is at fault -- tampered, truncated, extended, from another key or backend, malformed, or sealed under different AAD -- and never for an unreachable device or KMS, throttling, a permission failure, a missing key, a cancelled context or a TPM PCR/UserAuth failure; the native cause stays reachable with `errors.Is`/`errors.As`. Mappings: AWS KMS `InvalidCiphertextException`/`IncorrectKeyException` and blobs outside 1..6144 bytes; GCP KMS `InvalidArgument` from `Decrypt` (except a request CRC32C mismatch, which is transit corruption); Azure Key Vault `azurekv.ErrCiphertextRejected` from the local AES-GCM open; Vault Transit `400` "cipher: message authentication failed"/"invalid ciphertext…"; PKCS#11 `pkcs11.ErrCiphertextRejected` for `CKR_ENCRYPTED_DATA_INVALID`/`_LEN_RANGE`/`CKR_AEAD_DECRYPT_FAILED` only -- `CKR_GENERAL_ERROR` is never promoted, so on SoftHSM before 2.7.0, which answers a GCM tag mismatch with it, a tampered ciphertext fails without the sentinel (2.7.0 answers `CKR_ENCRYPTED_DATA_INVALID` and is classified) -- the sentinel's presence is conclusive, its absence is not; TPM 2.0 parameter-scoped `TPM2_Load` codes (`TPM_RC_INTEGRITY`, `_SIZE`, `_INSUFFICIENT`, `_BINDING`) and `TPM_RC_SENSITIVE` as `tpm2.ErrSealedObjectRejected`, plus a half-present public/private pair (`tpm2.ErrSealedObjectIncomplete`), areas over 2048 bytes each or 3072 together (`tpm2.ErrObjectAreaTooLarge`, refused before the TPM) and a loaded object `TPM2_Unseal` rejects as not sealed data (`TPM_RC_TYPE`/`_ATTRIBUTES` on the item handle); software/PKCS#8, the secret sealer, the platform sealer (missing or unknown strategy tag) and the composite key store (`ErrSealBackendMismatch`) likewise; the platform-store adapters now pass the caller's AAD through instead of dropping it. Every `Unseal` reports a cancelled context before classifying. **AAD is now actually bound on two backends that silently dropped it:** Vault Transit sends AAD as `associated_data` (it went as `context`, which Transit ignores for non-derived keys, so a wrong AAD decrypted) and fails closed with `vault.ErrAssociatedDataIgnored` on a server that ignores the parameter; TPM 2.0 seals carry `magic ‖ SHA-256(AAD) ‖ data` inside the integrity-protected secret, limiting AAD seals to 80 bytes (`tpm2.ErrSealAADTooLarge`); a nil-data seal binds the preset `SealData` rather than replacing it. The secret sealer binds `opts.AAD` too. Breaking: a value sealed on `vault` or `tpm2` with AAD by an earlier release was never bound and now fails to unseal with that AAD -- unseal it without AAD and seal it again; PKCS#8/software unseal now requires a 16-byte tag. Mapping per backend in `docs/sealing-and-barrier/engineering.md`. Closes #1414.
