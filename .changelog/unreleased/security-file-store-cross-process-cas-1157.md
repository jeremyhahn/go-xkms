- **File-backed guarded writes (`PutIfAbsent`, `CompareAndSwap`, `CompareAndDelete`) are now atomic across processes sharing one store directory, not only within a single process** (#1157). `pkg/storage/file.FileStorage` — the constructor the PKCS#11 module's `StorageTypeFile` opens directly — previously relied solely on `pkg/storage/engine.go`'s `engineBackend`, whose guard is a Go `sync.Mutex` invisible to a second process. Two module instances sharing one file-token directory could interleave a guarded read-compare-write on the PIN failed-attempt counter (#1144) and both report success, undercounting the shared lockout budget — a bypass reachable by running two processes against the same token instead of one.
  - `pkg/storage/file` now holds an advisory `flock` (`golang.org/x/sys/unix`) on a `.lock` file in the store root across every write this package performs — `Put`, `Delete`, `PutIfAbsent`, `CompareAndSwap`, `CompareAndDelete` — not only the guarded verbs, for the same reason `writeMu` covers unconditional writes in-process: an unguarded write from another process landing inside a guarded operation's critical section would defeat the guard exactly as it would locally. A fresh file description is opened and locked per call rather than held for the store's lifetime, since `flock(2)` locks are scoped to the open file description; this single mechanism serializes concurrent goroutines in one process and every other process with no separate in-process mutex to keep paired with it.
  - The lock file never collides with a stored key: `encodeKeyToPath` already percent-escapes a segment's leading `.`, and the go-qrdb file engine's own `List`/`Scan` already skip dot-prefixed entries.
  - Verified with `TestFileStorage_CompareAndSwap_ConcurrentAccumulates` (single-process, many goroutines) and `TestFileStorage_CompareAndSwap_CrossProcessAccumulates` (re-execs the test binary as several real OS processes racing a compare-and-swap retry loop against one shared counter) in `pkg/storage/file/crosslock_test.go`, and `TestModuleStorage_FailedAttemptCounter_CrossProcessAccumulates` in `pkg/pkcs11/module/storage_crossprocess_test.go`, which exercises the actual #1144 PIN attempt counter across real processes sharing a `StorageTypeFile` token and asserts the durable count is exact. All three fail deterministically when the lock is removed.
  - Files: `pkg/storage/file/lock.go` (new), `pkg/storage/file/storage.go`, `storage_putifabsent.go`, `storage_compareandswap.go`, `storage_compareanddelete.go`, `keypath_test.go`, `coverage_gaps_test.go`, `crosslock_test.go` (new); `pkg/pkcs11/module/storage_crossprocess_test.go` (new).
  - Verified by `go test -race` on `pkg/storage/...` and `pkg/pkcs11/module/...`, `go vet`, and `golangci-lint run` (0 issues) on both packages and `cmd/pkcs11-module`.
