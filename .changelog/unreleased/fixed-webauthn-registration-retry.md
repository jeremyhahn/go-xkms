- **An abandoned public WebAuthn registration no longer blocks the email.** Public `BeginRegistration` used to create the account at begin, so a ceremony that was never finished left an account behind and every later begin for that email was refused. Begin now creates nothing: the ceremony runs under a random 64-byte user handle drawn per registration, and the session carries the email and display name. Finish verifies the attestation, refuses if an account appeared for the email meanwhile, then creates the account under its own ID and stores the credential with the registration's handle. A passkey login resolves the account through the credential, so the token subject stays the account's ID (ruling 417(2)). Invite registration and adding a credential keep the account's ID as the handle. `SessionStore` gains `SaveRegistration` and `TakeRegistration`, which carry the pending email and display name as an exported `PendingRegistration`, so a store that cannot carry them fails to compile instead of refusing every signup.
