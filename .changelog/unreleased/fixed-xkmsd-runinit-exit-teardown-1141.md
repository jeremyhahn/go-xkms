- **`xkmsd init` now reaches the process's protected-memory teardown on every exit path, and `run()`'s live-server graceful-shutdown path is now covered by tests that never touch the test process's own signal handling** (#1141). #1153 first split `runProcess()` (which arms go-qrdb's `secure.CatchInterrupt()` and, on return, purges `secure.Purge()`/`enclave.WipeAll()`) from `run()`. This finishes that split for the `init` subcommand: `runInit` and its internal `exitInit` helper used to call `os.Exit` directly on every failure path, which — like any `os.Exit` — terminated the process immediately and skipped `runProcess`'s deferred purge, so a failed (or even a successful) `xkmsd init` never actually wiped the protected-memory buffers `runProcess` exists to guarantee are wiped. Both now return an exit code instead; `subcommands` (the `os.Args[1]` dispatch table `run()` uses) changed from `map[string]func([]string)` to `map[string]func([]string) int` so the code flows back through `run()` → `runProcess()` → `main()`'s single `os.Exit(runProcess())`, and the purge now runs unconditionally.
  - `run()`'s own live-server section — `srv.Start()` through the ACME/server graceful shutdown — is extracted into `serve(shutdownCtx context.Context, srv *server.Server, cfg *config.Config, logger *slog.Logger) int`, which takes its shutdown trigger as an ordinary context parameter. A test drives it with a context it cancels itself, instead of a real SIGTERM racing `secure.CatchInterrupt`'s process-wide `os.Exit` handler (which is what made this path untestable before: `run()` no longer arms that handler, only `runProcess` does).
  - No externally observable behavior changes for a real deployment: exit codes are unchanged, and the purge now runs where it always should have.
  - Files: `cmd/xkmsd/main.go`, `cmd/xkmsd/init.go`, and new tests in `cmd/xkmsd/serve_test.go`, `cmd/xkmsd/runinit_test.go`, `cmd/xkmsd/run_lifecycle_test.go`.
  - Verified by `go test -race ./cmd/xkmsd/...` and `golangci-lint run ./cmd/xkmsd/...`; `cmd/xkmsd` package statement coverage went from ~76.8% to ~90.3%.
