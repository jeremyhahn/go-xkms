- **PIV login enforces strict attestation when `attestation_roots` is set** -- before this change, `POST /api/v1/auth/login/piv` accepted a login certificate that itself chained to the attestation roots, checked no attestation claims, let a recorded enrollment level stand in for evidence, and fell back to `unattested` under `allow_unattested`. Now it requires a separate attestation certificate for the login key that chains to the roots and carries the Yubico PIV attestation claims (firmware, serial, known PIN and touch policy). An optional `PIVLoginOptions.AttestationPolicy` hook adds site rules. Refusals are audited with a stable reason code (`no_attestation_evidence`, `attestation_chain_untrusted`, `attested_key_mismatch`, `attestation_profile_mismatch`, ...), and the client response is unchanged. `allow_unattested` together with `attestation_roots` is now a configuration error. Clients must present the slot attestation certificate after the login certificate. Files: `pkg/api/rest/handlers_auth.go`, `pkg/config/config.go`.
