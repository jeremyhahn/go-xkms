- **A tenant user could read, overwrite and delete another tenant's PKCS#11 remote token state, and a tenant Admin could read every tenant's audit events. Both now take the tenant from the caller's identity.** The authorizer always checks a permission against the caller's own tenant, so a self-scope grant such as `keys:get` or `audit:read` could not stop a handler from acting on a tenant named in the request. Tenant Admins hold both grants. **PKCS#11 remote state (go-xkms#1114):** the REST, QUIC, gRPC and Unix `PKCS11State*` handlers used the body's `tenant_id` as the key prefix in one store shared by all tenants (`pkcs11state/<tenant>/<token>/<key>`). A caller could therefore read, overwrite, compare-and-swap or delete another tenant's token records and lockout counters. `pkg/xkms/servicer_pkcs11state.go` now derives the namespace from the authenticated identity (`pkcs11StateScope`). A `tenant_id` is accepted only when it is empty or names the caller's own tenant, with `system` and empty treated as the same namespace, because the module sends its configured tenant on every call. Any other value is refused with `ErrPKCS11StateTenantMismatch`. A token label containing `/` could alias another token's keys, so it is refused with `ErrPKCS11StateTokenSeparator`. Keys stay hierarchical. Every transport answers these errors, and a missing token, with 400 / `InvalidArgument` instead of 500 / `Internal` (`xkms.IsPKCS11StateRequestError`). The comments saying the store had per-tenant barrier encryption were wrong and have been corrected: it is one store with key-prefix separation. **Audit queries (go-xkms#1115):** REST, gRPC/Unix, QUIC and MCP passed the caller's `tenant_id` filter to the audit chain, where an empty filter matches every tenant. `pkg/xkms/servicer_audit.go` now replaces it (`auditTenantFilter`). A tenant caller reads its own tenant. A system-tenant caller reads the filter as sent only when the Authorizer admits qrdb's `audit:read:cross`, and otherwise reads the `system` tenant. qrdb grants that permission to Admin but not to Auditor, so a system-tenant Auditor now sees only the system tenant's events. The service reaches the Authorizer through the new `XKMSService.SetAuthorizer`, which xkmsd wires with the transports' Authorizer. `auth.ActionReadCross` restates the permission string because the qrdb SDK does not export it, and `pkg/auth/permissions_test.go` pins it to qrdb's registry. Tests: `pkg/xkms/servicer_pkcs11state_tenant_test.go` covers all seven operations for foreign, own and slashed input and for isolation, `pkg/xkms/servicer_audit_tenant_test.go` works from qrdb's real grant table, and there is one transport test per surface for REST, gRPC and MCP.
