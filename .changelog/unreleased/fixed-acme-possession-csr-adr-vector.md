- **The DICE possession CSR matches the ADR vector.** The device-attest-01 possession template carried a nonce-only, non-critical UCCS extension and named the device by a caller-supplied DeviceID, so the host and a template-minting device wrote different bytes. `BuildPossessionCRI(pub, claims, nonce)` and `SignPossessionCSR(signer, claims, nonce)` now take the alias certificate's claims set: the UCCS extension is critical and carries `{10: b, 256: ueid, 273: measurements}`, the SAN is the hex of that `ueid`, and a claims set without a ueid or measurements, or with any other claim, is `ErrPossessionCSRMalformed`. The ACME client reads the claims from the alias certificate it presented. `TestPossessionVector` pins the ADR's 365-byte CertificationRequestInfo. SPEC: acme-issuance.
