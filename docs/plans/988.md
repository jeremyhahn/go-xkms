# Plan 988: xkey fido2 TPM2 backend opens the TPM with the shared tpm config

Tenant Agent ruling 988 (owner-blocking defect).

## Objective

After `xkey tpm install`, `xkey fido2 --backend tpm2` fails with
"failed to get SRK attributes: tpm: SSRK config is nil":
createFIDO2TPM2KeyBackend (xkey/cmd/xkey/cmd/fido2.go) opens the TPM with a
bare `xkms.TPMConfig{Device: ...}` holding no SSRK, EK, IAK, IDevID or LAK.
The fido2 tpm2 backend must open the TPM with the configuration every `tpm`
command uses (newTPMConfig + newTPMParams), so it finds the keys
`tpm install` provisioned.

## Slices

1. test(xkey/fido2): fido2_tpm2_backend_simulator_test.go (tpm_simulator tag)
   provisions the simulator through the `tpm install` path
   (withProvisionedSimulatorTPM), calls createFIDO2TPM2KeyBackend, and asserts
   no error and a backend that generates a credential key. Fails at
   e5fbfd5ca with "SSRK config is nil".
2. fix(xkey/fido2): a device-parameterized opener seam in tpm.go
   (openTPMForDevice, built on newTPMConfig with ekCertHandleRSA and
   newTPMParams); createFIDO2TPM2KeyBackend opens through it;
   shareProvisionedSimulatorTPM routes it to the shared simulator.
3. Changelog entry (.changelog/unreleased/fixed-988-xkey-fido2-tpm-config.md).

## Out of scope

- No change to newTPMConfig's handles or algorithms.
- No simulator flag on `xkey fido2` (the test routes the opener seam).
- No fallback to the bare config.
