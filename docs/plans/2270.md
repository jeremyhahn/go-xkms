# Plan: invite activation as one conditional pending-to-active commit (#2270)

## Objective

Invitation activation (PIV `ActivateInvitePIV` and WebAuthn
`FinishInviteRegistration`) must bind exactly one credential and move the
account pending -> active in one conditional store commit, so that:

- two concurrent redemptions of one invite bind once, and every loser gets
  `ErrInviteUnusable`;
- an admin disable that lands before the activation write wins (the account
  stays disabled and keeps no new binding).

## Slices, in order

1. iv2270b + iv2270c (done): tests first, against a real qrdb user store
   (`pkg/xkms/servicer_invite_qrdb_test.go`):
   - `TestActivateInvitePIV_QRDB_ConcurrentRedemptionBindsOnce`
   - `TestActivateInvitePIV_QRDB_AdminDisableBeforeWriteWins`
   - `TestFinishInviteRegistration_QRDB_AdminDisableBeforeActivateWins`
   The qrdb test node is sealed so PIV activation reaches the race.
2. Merge main (this lane): keep the row branch current with main.
3. Fix (blocked): call go-qrdb sdk/go
   `transport.UserClient.ActivateWithCertBinding(ctx, userID, thumbprint,
   notAfterUnix)` and the conditional pending -> active activate from the
   invite servicer; the three tests above turn green. Needs the go-qrdb
   tag carrying jeremyhahn/go-qrdb#1764 and #1765 (sdk/go up to
   v0.58.5-alpha lacks both), then a go.mod bump to that tag.

## Out of scope

- The embedded node's certificate target guard without the seal, or on a
  remote datastore (pkg/embeddednode/embedded_node.go:146, :353, :370):
  reported as a finding, not fixed here.
- Any `replace` or branch pin of go-qrdb: tagged releases only.
