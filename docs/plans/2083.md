# Plan: qrdb-crypto-provider-seam (#2083)

SPEC row `qrdb-crypto-provider-seam` (docs/SPEC.md:118), PR #2106.

## Objective

go-xkms supplies its hardware-backed signer and key providers to the
go-qrdb node it embeds, passed only at node construction
(`initEmbeddedQRDBNode`, `pkg/server/qrdb_node.go`) as `go-qrdb/sdk/go/node`
options, never through `go-qrdb/pkg/*`.

## Slices, in order

1. Tenant CA key provider factory (lane sqcpsa, landed on the branch):
   `pkg/server/tenant_ca_keyprovider.go` resolves each tenant's CA key on
   the configured backend (software, PKCS#11, TPM 2.0) and passes it to the
   node as its cert key provider factory; `tenant_ca_provisioning.go`
   provisions the key and undoes a half-done provisioning. Reserved key IDs
   in `pkg/xkms/reserved_keys.go` keep tenants off the CA key names.
   Tests: `tenant_ca_keyprovider_test.go`, `_pkcs11_test.go`,
   `_tpm_simulator_test.go`, `tenant_ca_provisioning_test.go`,
   `tenant_ca_provisioning_undo_test.go`, `pkg/xkms/reserved_key_test.go`.
2. PKCS#11 tenant key resolution on a real token: a tenant key resolves
   under its existing token ID, and a tenant login CA key never falls back
   to the unscoped object (test on the branch).
3. Main merged in (this slice): `origin/main` merged with a merge commit;
   `make test-server` and `make test-xkms` pass.

## Out of scope

- The verifiable-log head-signer seam and the other seams go-qrdb still
  owes (go-qrdb item 144); they need a go-qrdb release first.
- `WithDEKProvider`, `WithKeyDeliveryDecrypter`, `WithVolumeKeyProvider`,
  `WithVolumeProvider` wiring.
- SPEC status flip to shipped: done when the open go-qrdb seams land.
