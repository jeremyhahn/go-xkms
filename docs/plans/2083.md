# Plan: qrdb-crypto-provider-seam (#2083)

SPEC row `qrdb-crypto-provider-seam` (docs/SPEC.md:118), PR #2106.

## Objective

go-xkms supplies its hardware-backed signer and key providers to the
go-qrdb node it embeds, passed only at node construction
(`initEmbeddedQRDBNode`, `pkg/server/qrdb_node.go`) as `go-qrdb/sdk/go/node`
options, never through `go-qrdb/pkg/*`.

## Slices, in order

1. Tenant CA key provider factory (lane sqcpsa, landed on the branch):
   `pkg/server/tenant_ca_keyprovider.go` resolves each tenant's CA key on
   the configured backend (software, PKCS#11, TPM 2.0) and passes it to the
   node as its cert key provider factory; `tenant_ca_provisioning.go`
   provisions the key and undoes a half-done provisioning. Reserved key IDs
   in `pkg/xkms/reserved_keys.go` keep tenants off the CA key names.
   Tests: `tenant_ca_keyprovider_test.go`, `_pkcs11_test.go`,
   `_tpm_simulator_test.go`, `tenant_ca_provisioning_test.go`,
   `tenant_ca_provisioning_undo_test.go`, `pkg/xkms/reserved_key_test.go`.
2. PKCS#11 tenant key resolution on a real token: a tenant key resolves
   under its existing token ID, and a tenant login CA key never falls back
   to the unscoped object (test on the branch).
3. Main merged in (this slice): `origin/main` merged with a merge commit;
   `make test-server` and `make test-xkms` pass.
4. Codex round 1 on a35dc048d (lane af2106c):
   - Teardown vs provisioning: `RemoveTenant` tombstones the claim first
     (refused while a generate is in flight), every `EnsureTenant` checks
     the tombstone after its last write and undoes late writes;
     `CreateTenant` revives a tombstoned ID (`ReviveTenant`). Tests
     `TeardownFencesLateProvisioningWrites`,
     `TeardownWaitsForGenerateInFlight`, `RemoveTenantTombstonesClaim`.
   - Lost-host generating claim: the held-claim error names the holder;
     after fencing that host the embedder passes it to
     `WithTenantLoginCAFencedHolders` and the boot pass takes the claim
     over. Test `FencedHolderReleasesLostHostClaim`.
5. Main merged again; Codex round 1 follow-up (lane af2106d):
   - Undo order: a failed create removes the login CA material before it
     undoes the tenant, so the ID stays fenced until the CA is gone; a
     failed CA cleanup keeps the tenant for DeleteTenant. Tests
     `UndoFencesIDUntilCACleanup`, `UndoKeepsTenantWhenCACleanupFails`.
   - The docs/SPEC.md:108 ota-image-keys finding is not this branch's
     change (docs/SPEC.md is not in its diff against main).
6. Codex round 1, remaining items (lane af2106e):
   - SPEC authorization: the unapproved settings
     `datastore.tenant-login-ca-keys` and `-fenced-holders` are removed; the
     seam is enabled only by the server construction options
     `WithTenantLoginCAKeys` / `WithTenantLoginCAFencedHolders`, the
     node-construction wiring SPEC.md:118 describes.
   - Revive fence: each provisioning pass carries the claim generation it
     started under; a revive bumps it, so an old pass that resumes after a
     remove/revive/reprovision refuses its writes.
   - Absence needs complete enumeration: a backend that skipped an object
     while listing keys reports it, and the CA key lookup treats that as a
     lookup failure, not absence.
7. Codex round 2 (lane af2106f):
   - Late cleanup holds a cleanup lease on the tombstone; ReviveTenant
     clears only a plain tombstone or a stopped holder's lease. Tests
     `LateCleanupSparesRevivedTenant`, `ReviveRefusesLiveCleanupLease`.
   - AWS KMS Signer maps GetPublicKey NotFoundException to
     backend.ErrKeyNotFound (awskms_signer_notfound_test.go).
   - Native go-qrdb deletion: `ReclaimWithdrawnTenants` (boot pass and each
     native onboarding) removes material of tenants a complete ListTenants
     omits. Tests `NativeDeletionReclaimed`, `ReclaimNeedsCompleteListing`.
   - Open (next slice): factory test on the awskms mock backend; real-node test, server.New with
     WithTenantLoginCAKeys and the cluster CA as TrustedCA (harness like
     tenant_node_barrier_test.go qrdbBarrierConfig), onboarding through
     go-qrdb, certificate login, restart keeping the same CA.
7. Slice sx2106a (af2106f verify refusal + PR #2106 Codex round 1). Done:
   AWS Delete schedules deletion first and propagates non-NotFound failures
   (awskms_delete_failure_test.go); reclaim confirms each candidate with a
   typed GetTenant not-found (tenant_ca_reclaim_confirm_test.go); the CA
   certificate is published through PutIfAbsent/CAS in claims storage and a
   losing pass adopts the winner (tenant_ca_cert_publish_test.go); teardown
   waits for a generate in flight and a pass re-checks its generating claim
   before generating (tenant_ca_teardown_race_test.go). Open (next slice):
   durable RecoverLostClaim(ctx, tenantID, holder) with operator procedure
   doc; real-node restart test (item 6 above); changelog line.
8. Slice sx2106b (PR #2106 Codex round 2). Done: repair of a revived
   tenant restores the published login CA certificate
   (TestTenantCAKeyFactory_LateLoginCACertSaveAfterReviveRestoresPublished);
   AWS Delete releases alias/<cn> when it targets the deleted key
   (awskms_alias_release_test.go, tag awskms); changelog. Open: the real
   embedded-node test (item 6) in tenant_ca_node_e2e_test.go. go-qrdb
   v0.51.0-alpha path: New(cfg, WithTenantLoginCAKeys()) with
   qrdbBarrierConfig; s.qrdbNode; xkmsService.CreateTenant; create an
   account (Node.UserService); Node.Client().Certs().IssueCert(CSR) under a
   tenant-admin context; authenticate via Node.AuthMiddleware()
   .AuthenticateHTTP with r.TLS.PeerCertificates; Shutdown, New on the same
   Datastore.Path, same login CA DER and same credential authenticate.
