# 1817: SPEC row device-security-event-evidence

Objective: a device's tamper-response record reaches go-xkms as RFC 9334
Evidence. It is one CBOR Claims-Set, bound by owner ruling 7dbbb72 item 181 (b)
as a Detached Submodule Digest (RFC 9711 §4.2.18.2) inside device-signed EAT
evidence over the Verifier's `eat_nonce`, and handed over through one optional
backend capability.

## Slices, in order

1. Fold PR #2105 (`row/1765-device-security-event-evidence`) with a merge
   commit. It brings `pkg/attestation/securityevent` (`Record`, `Entry`,
   `Encode`, `Decode`, typed refusals) and `types.SecurityEventProvider`
   (`AttestSecurityEvents(ctx, nonce)`), with its tests
   (`claims_test.go`, `types_securityevent_test.go`). Its plan is
   `docs/plans/1765-security-event-claims.md`.
2. Test commit: `digest_test.go`. It pins the SHA-256 vector
   (`82 2F 58 20 || SHA-256(Claims-Set)`), round-trips SHA-256/384/512, accepts
   a text algorithm name, and covers each refusal: a changed record, a changed
   digest, a wrong length, a non-hash algorithm, three elements, a non-bstr
   digest, non-CBOR, empty input, and a matching digest over an invalid
   Claims-Set.
3. Feat commit: `digest.go` (`DetachedDigest`, `VerifyDetached`, `AlgSHA*`,
   `ErrMalformedDigest`, `ErrUnsupportedAlgorithm`, `ErrDigestMismatch`), the
   architecture.md binding section changed to the ruling, and a changelog
   entry.
4. docs/SPEC.md: the row's Binding text changed to (b), its Hook to
   `types.SecurityEventProvider`, and its status set to shipped. Done in
   eb9d90866 (a resume with LANE_POLICY_ALLOW for docs/SPEC.md).

## Review findings

- Codex P1, `pkg/attestation/securityevent/digest.go:115`: the digest was
  decoded into `[]byte`, which fxamacker/cbor also fills from an array of
  unsigned integers, so `[-16, [b0, ..., b31]]` with the correct SHA-256 bytes
  passed. Test commit 18b88f3ca adds the integer-array refusal; fix commit
  77c44bc7f requires CBOR major type 2 (byte string) before taking the bytes
  and refuses anything else with `ErrMalformedDigest`.
- Codex P1, `pkg/types/types.go:1967`: the `SecurityEventProvider` comment
  let a backend ignore the nonce because the binding was undecided, and
  `securityevent/doc.go` still described the open binding. Fix commit
  a12d7b9f3 requires the ruled (b) binding (detached digest inside
  device-signed evidence carrying the given `eat_nonce`), says the Claims-Set
  alone is unauthenticated, and updates doc.go to match. No test commit: the
  change is comment-only. An absent digest is already refused by the
  existing `TestVerifyDetached_Refusals` case "empty" (nil digest,
  `ErrMalformedDigest`). The `eat_nonce` check is not `VerifyDetached`'s by
  design: it runs on the signed evidence, which the caller verifies
  (signature and `eat_nonce`) before it passes the digest, so no
  `VerifyDetached` test can cover it.
- Codex P1, `pkg/types/types.go:1977`: `AttestSecurityEvents` returned only
  the unsigned Claims-Set, so no path carried the signed evidence to the
  Verifier. Test commit 57ca4e85c, fix commit b3f60d9fa: the method returns
  `types.SecurityEventEvidence` (Claims-Set plus signed evidence), and
  `securityevent.Verify` checks the evidence signature (through an
  `EvidenceVerifier`), its `eat_nonce` against the challenge and the digest
  over the record together. `TestVerify_*` covers each refusal: another
  device's signature, tampered evidence, a stale or prefix nonce, evidence
  over another record, and no nonce or verifier.
- Codex security finding (lane-verify), `securityevent/verify.go:51`: `Verify`
  refused only an empty challenge, so short nonces could recur and be replayed.
  Test commit fd5f391ed covers matching one- and seven-byte nonces and the
  eight-byte boundary. The fix commit refuses challenges shorter than
  `MinNonceLen` (8, RFC 9711 §4.1), the minimum `dice/uccs.go` already
  enforces.

## Out of scope

- A backend that implements `SecurityEventProvider`. The trusted-firmware
  adapter is theirs (trusted-firmware#335).
- Putting the digest in the device's signed evidence (a trusted-firmware
  change), and a submodule field on `dice.Evidence`.
