# 1817: SPEC row device-security-event-evidence

Objective: a device's tamper-response record reaches go-xkms as RFC 9334
Evidence. It is one CBOR Claims-Set, bound by owner ruling 7dbbb72 item 181 (b)
as a Detached Submodule Digest (RFC 9711 §4.2.18.2) inside device-signed EAT
evidence over the Verifier's `eat_nonce`, and handed over through one optional
backend capability.

## Slices, in order

1. Fold PR #2105 (`row/1765-device-security-event-evidence`) with a merge
   commit. It brings `pkg/attestation/securityevent` (`Record`, `Entry`,
   `Encode`, `Decode`, typed refusals) and `types.SecurityEventProvider`
   (`AttestSecurityEvents(ctx, nonce)`), with its tests
   (`claims_test.go`, `types_securityevent_test.go`). Its plan is
   `docs/plans/1765-security-event-claims.md`.
2. Test commit: `digest_test.go`. It pins the SHA-256 vector
   (`82 2F 58 20 || SHA-256(Claims-Set)`), round-trips SHA-256/384/512, accepts
   a text algorithm name, and covers each refusal: a changed record, a changed
   digest, a wrong length, a non-hash algorithm, three elements, a non-bstr
   digest, non-CBOR, empty input, and a matching digest over an invalid
   Claims-Set.
3. Feat commit: `digest.go` (`DetachedDigest`, `VerifyDetached`, `AlgSHA*`,
   `ErrMalformedDigest`, `ErrUnsupportedAlgorithm`, `ErrDigestMismatch`), the
   architecture.md binding section changed to the ruling, and a changelog
   entry.
4. docs/SPEC.md: the row's Binding text changed to (b) and its status set to
   shipped. This is a protected path for lanes and needs LANE_POLICY_ALLOW
   (open, see below).

## Out of scope

- A backend that implements `SecurityEventProvider`. The trusted-firmware
  adapter is theirs (trusted-firmware#335).
- Putting the digest in the device's signed evidence (a trusted-firmware
  change), and a submodule field on `dice.Evidence`.
