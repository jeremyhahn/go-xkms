# Plan: confidential-vm-provider (#2380, ruling 1234)

## Objective

Owner ruling 1234 moves go-enclave's `backends/confidentialvm` into go-xkms
with its history. It lands as `pkg/enclaveprovider/confidentialvm`: an
Attester for SEV-SNP and TDX guests over the Linux configfs-tsm report
interface, and an SEV-SNP derived-key KeyProtector over /dev/sev-guest that
implements go-enclave's `enclave.KeyProtector` for `ModePerOperation`.

## Slices, in order

1. History: the six go-enclave commits replayed verbatim (signed, original
   author, date and message, each with a Moved-from line). Never rewritten.
2. Test commit: the tests use the package's own `Evidence` and
   `ErrInvalidNonce` and assert the unexported `attester` interface; the two
   `enclave.Backend` negative checks go (go-enclave v0.8.0-alpha has no
   `Backend`); `hardware_linux_amd64_test.go` adds the SNP-guest tests.
3. Fix commit: the nested go.mod/go.sum go and the package joins the root
   module, adapted to go-enclave v0.8.0-alpha (table below).
4. Docs: SPEC row, ROADMAP bullet, this plan, changelog entry.

## Module decision

The package joins the root module. go-xkms keeps nested modules only for
separately consumed deliverables (`xkey/`, `sdk/go/`, `web/desktop/`); every
backend and provider (`pkg/backend/*`, `pkg/enclaveprovider/opteeblob`) is a
root-module package. go-enclave used a nested module only to keep
golang.org/x/sys out of its core; go-xkms's root module already requires
golang.org/x/sys directly, so joining adds no dependency. Nothing imports the
package and importing it registers nothing, so the package boundary keeps it
optional: no feature build tag.

## Hardware tests

`hardware_linux_amd64_test.go` carries
`//go:build linux && amd64 && confidentialvm_hardware`. Inside an SEV-SNP
guest:

    go test -count=1 -tags confidentialvm_hardware -run Hardware ./pkg/enclaveprovider/confidentialvm/

It round-trips a 32-byte key through Protect/Unprotect, refuses a blob with
one flipped byte with `enclave.ErrSealedAuthentication`, and checks that
Attest with 32- and 48-byte nonces returns 1184-byte `sev-snp-report`
evidence whose REPORT_DATA (offset 0x50) is each nonce plus zero padding.
No Makefile target or CI job sets the tag (like `yubikey_hardware`).

Review round 1: Unprotect stages the plaintext and copies it to the caller
only after the derived-key memory's Destroy succeeded; `newLockedMemory` and
`deriveFn` are the seams `TestUnprotect_LeavesTheKeyUnchangedWhenCleanupFails`
uses to drive a failing cleanup without hardware.

## TPM-equivalence proof (go-enclave#504)

Ruling 1234 lets go-enclave#504 delete `backends/tpm` only against written
proof that go-xkms's provider is equivalent. The proof is
[`docs/enclaveprovider/tpm-equivalence.md`](../enclaveprovider/tpm-equivalence.md):
EQUIVALENT 17, GAP 7, N/A 7, so it is PARTIAL. This lane adds
`FuzzDecodeEnvelope` (row 5), the provider's no-handle-residue (row 17) and
TPM-refused tampering (row 12) simulator tests, cancellation between TPM
commands in seal and unseal with its test (row 18, fix in `pkg/tpm2`), and
conformance over the `pkg/backend/tpm2` Backend (row 31). The GAP rows are:
row 7 sealed-object attributes (no NoDA, no template test), row 14 TPM_RC_RETRY
retry, row 15 locked/dump-excluded transients, row 16 no plaintext copy below
`pkg/tpm2`, row 19 interrupt of an in-flight command, row 20 failed flush
fails the call, row 22 serialized calls with a ctx-aware wait.
