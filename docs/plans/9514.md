# DS-9514: bound the LAN apt-cache wait in the pool image builds

## Objective

Main is red: CI run 44533723130's "Integration [integration image]" job hung
3 h in `apt-get $p update` because #2273 (ruling 886) routes apt through the
LAN cache with `-o Acquire::http::Proxy=$APT_PROXY` and no timeout. Every
proxied apt-get must fail fast and retry instead of hanging (ruling 742 item 4).

## Slices (one lane)

1. test(buildgates): `internal/buildgates/pool_build_caches_test.go` requires
   every RUN that sets `Acquire::http::Proxy` from `APT_PROXY` to carry
   `-o Acquire::http::Timeout=30 -o Acquire::Retries=3` in the same `p=`
   option string; a regression case without the timeout must be caught.
   Fails at e5fbfd5ca.
2. fix(build): add the options to each `p=${APT_PROXY:+...}` line in
   Dockerfile, build/docker/devcontainer/Dockerfile and Dockerfile.softfido.
   The alpine images (softhsm, swtpm) fetch through scripts/apk-mirror.sh, a
   ci-template file (rulings 899/901); it is not changed here.
3. changelog: `.changelog/unreleased/fixed-9514-apt-cache-timeout.md`.

## Out of scope

- A direct-fetch fallback, the apt_proxy secret, .github/workflows/, the
  compose files, the image build itself (lanes have no Docker; the buildgates
  test is the proof, CI's Integration tier builds the images).
