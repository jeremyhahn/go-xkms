# Row 2252: qrdb-durable-writes

Defect (ruling 814, i.MX 95 deploy): in standalone mode, key writes that
xkmsd has acknowledged are lost when the process is killed with SIGKILL.
Cause: the embedded store (newEmbedded) applied writes in the background
after the ack, and go-qrdb v0.51.0-alpha did not fsync before ack.
Fix: c6e6c49e5 (synchronous apply, pebble SyncWrites) plus the bump to
go-qrdb v0.58.5-alpha (go-qrdb #1621, #1622: fsync before ack by default),
go-enclave v0.11.1-alpha, go-quicraft v0.24.3-alpha (ruling 849).

## Objective

Every key write xkms acknowledges survives SIGKILL of the process, in
standalone mode and in a 3-node cluster.
