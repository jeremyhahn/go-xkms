# Row 2252: qrdb-durable-writes

Defect (ruling 814, i.MX 95 deploy): in standalone mode, key writes that
xkmsd has acknowledged are lost when the process is killed with SIGKILL.
Cause: go-qrdb v0.51.0-alpha acknowledges a write before it is fsynced.
go-qrdb v0.58.5-alpha (go-qrdb #1621, #1622) fsyncs before ack by default.
Ruling 849 orders the bump.

## Objective

Every key write xkms acknowledges survives SIGKILL of the process, in
standalone mode and, where it can run without Docker, in a cluster.

## Slices, in order

1. test(storage): standalone SIGKILL round trip. The test re-execs its own
   binary as a child (env marker); the child opens the standalone store at
   a temp path, writes a key through the storage seam, prints "acked" and
   blocks; the parent sends SIGKILL, reopens the store and reads the key
   back (same bytes). Must fail on v0.51.0-alpha.
2. test(storage): the clustered case (3 members on loopback, kill the
   leader after "acked", read from a survivor and after restart). Under
   the integration build tag in test/integration if it needs Docker.
3. chore(deps): go-qrdb and go-qrdb/sdk/go v0.58.5-alpha in the root; tidy
   sdk/go, web/desktop and xkey; drop the held go-enclave v0.8.0-alpha
   replace if v0.11.1-alpha is required by the new graph. Compile breaks
   are fixed in separate fix commits. Slice 1 passes after it.
4. A durable-write setting through the seam only if go-qrdb v0.58.5
   exposes a sync option; otherwise record here that fsync-before-ack is
   unconditional upstream.
5. docs(plan): this file updated with results, commit hashes, date, HEAD.
