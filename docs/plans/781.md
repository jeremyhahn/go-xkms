# #781 row ca: xkey CA in both modes

## Objective

docs/SPEC.md row ca (the xkey table, l.156). Owner rulings m677 item 2 and
m956 (rulings 116-119): xkey keeps every feature in both modes, standalone on
its local store and remote against an xkms server, both through
go-xkms/sdk/go.

## Evidence at e0d8ce46

- Remote CA exists for the CLI only: `xkey ca` resolves a remote client
  (`getSDKClient`, xkey/cmd/xkey/cmd/ca.go l.87-95).
- The GUI `CAService` (xkey/pkg/gui/services/ca_service.go l.69-77) holds a
  fixed client from `NewCAService(client)`, has no production caller in
  xkey/pkg/gui/app.go, is not in the Wails bindings and has no
  xkey/frontend/wailsjs/go/services/CAService.* files.
- Services that follow the connection take `SetClient` in
  `applyConnectionEvent` (app.go); `CertificateService` is the pattern
  (certificate_service.go l.51-78).

## Slices (in order, one lane each on row/781-xkey-ca)

1. ca781a: remote CA in the GUI. `CAService` gets an atomic client with
   `SetClient`; the App constructs it, sets it on connect, clears it on
   disconnect/error and binds it (wailsjs regenerated).
   Tests: `TestApplyConnectionEvent_CAFollowsTheConnection`,
   `TestCAService_SetClient`.
2. ca781b (done): standalone CA in the CLI. `xkey ca --local` (a
   persistent flag on caCmd) makes `getSDKClient` return
   `newLocalCAClient()`: sdk/go's embedded client over
   `EmbeddedServiceConfig{KeyDir: <data dir>/ca, CA:
   DefaultMultiIdentityCAConfig()}`. The new sdk/go field
   `EmbeddedServiceConfig.CA` makes `NewEmbeddedService` build the CA with
   `compose.BuildCA` on file stores under KeyDir/ca (loading it on reopen)
   and wire it with `Stores.Wire` (`SetCA`). A barrier-encrypted store is
   refused with `ErrCALocalStoreBarrierEncrypted`. Tests:
   `TestNewEmbeddedClient_WithCA`, `TestNewEmbeddedService_NoCA`,
   `TestRunCAInfo_Local`, `TestRunCAIssue_Local`,
   `TestGetSDKClient_LocalRefusesBarrierStore`.
3. ca781c: standalone CA in the GUI. With no server connected `CAService`
   gets the local embedded client from ca781b; a CA view in
   xkey/frontend/src with vitest and the Playwright mock tier.
4. ca781d: fold open PR #2166 ("refactor(xkey): CA profile tests reach the
   registry through sdk/go") into this row; xkey/docs/ca/ feature folder;
   docs/SPEC.md row ca rewritten to the decision (both modes, rulings
   m677/m956) with file:line evidence, status shipped.

## Out of scope

- Any CA feature outside xkey (server-side CA is its own rows).
- New transport APIs: one sdk/go field (`EmbeddedServiceConfig.CA`) is
  added in ca781b; no new transport API.
