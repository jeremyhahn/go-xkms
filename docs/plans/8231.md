# Plan 8231: deps-check passes

## Objective

`make deps-check` (scripts/deps-check.sh) fails on main and on every PR: direct
dependencies of the root module, `sdk/go` and `xkey` are behind a release that
is 7 days old or older. This row brings them to their newest release, so the
`Devcontainer image [... deps-check ...]` job and the CI Gate turn green.

## Slices

One commit per module directory, in this order. Each is `go get` of the listed
modules at the listed versions and `go mod tidy`, with the CI module setup
(fresh GOMODCACHE, GOWORK=off, -mod=mod, GOPROXY=https://proxy.golang.org).

1. `.`: github.com/zmap/zcrypto v0.0.0-20261025225231-4cf7949d2321,
   github.com/zmap/zlint/v3 v3.7.3, golang.org/x/net v0.62.0,
   google.golang.org/grpc v1.85.0.
2. `sdk/go`: github.com/jeremyhahn/go-truststrap v0.7.1-alpha,
   github.com/mark3labs/mcp-go v1.5.0, github.com/quic-go/quic-go v0.65.0,
   google.golang.org/grpc v1.85.0.
3. `xkey`: github.com/Azure/azure-sdk-for-go/sdk/azcore v1.24.0,
   github.com/fxamacker/cbor/v2 v2.10.0, github.com/jeremyhahn/go-luks2
   v1.0.2-alpha, github.com/quic-go/quic-go v0.65.0, github.com/spf13/pflag
   v1.1.0, github.com/wailsapp/wails/v2 v2.17.1, google.golang.org/grpc
   v1.85.0, tinygo.org/x/bluetooth v0.17.0.

A bump that breaks the build is fixed at its call sites when the fix is under
40 lines; otherwise that one module stays at its version and the report names
it.

## Tests

No new tests: the row changes versions only. Per module directory:
`go build ./...`, `go vet ./...`, `go mod verify`; `go test -count=1 ./...` in
`sdk/go`; in `.` and `xkey` the packages that import a bumped module;
`scripts/deps-check.sh` run directly prints no "7 days old or older" line.

## Out of scope

- The go directive (stays 1.27.2), replace directives, `// held:` comments.
- `.github/workflows/`, the Makefile, docs/SPEC.md, ROADMAP.md.
- Dependencies that are behind a release younger than 7 days, unless a
  required bump pulls them.
