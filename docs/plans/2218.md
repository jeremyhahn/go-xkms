# Row #2218: key-version-cas

## Objective

`XKMSService.rotateKey` writes the key's version record as a compare-and-swap
against the record it read before the rotation. The write succeeds only while
the stored record is still that one, so a stale or concurrent rotator fails
with a typed conflict error and does not overwrite the record. Orphan cleanup
(removing a backend key under the next version's name that the record does
not hold) never deletes a key version newer than the record it read. Every
shared backend gets this through the common `rotateKey` path, with no
per-backend code.

## Slices (lane row2218a)

1. Plan and SPEC row `key-version-cas` (planned).
2. Test: a second writer updates the stored record between rotateKey's read
   and its write; rotateKey returns `keyversion.ErrVersionConflict`
   (errors.Is) and the stored record is the second writer's (a compile
   failure before the fix: the error type is part of it).
3. Fix: `keyversion.Store.CompareAndPut(ctx, tenant, expected, rec)` and the
   typed `*VersionConflictError` (matches `ErrVersionConflict`); rotateKey
   uses it with the record it read. Store unit tests for the conditional put.
4. Test: orphan cleanup with a stored record newer than the one read keeps
   the backend key.
5. Fix: rotateKey checks the stored record before it deletes the orphan and
   refuses with the conflict error when it has moved on.
6. SPEC row marked shipped with the proving tests.

## Slices (lane row2218b: review findings)

7. Test: two processes (own stores, one record database and backend) race
   one rotation: one rotates after the other checked the record and before
   it removes the orphan, and after the other created the next key and
   before it records it; the recorded version's key is its rotator's.
8. Fix: `Store.Claim`/`Release` and a claim-fenced `CompareAndPut`: only the
   claim holder removes, creates and records the next version's key; a
   failed write leaves its key for the next holder; `Put` keeps a claim.
   `Store.Verify` and `Record.Clone` removed (rotateKey copies locally).
9. Test, then fix: `VersionConflictError` and `ErrVersionConflict` in the
   apierrors key-version tables (REST 409, gRPC FailedPrecondition).
10. Open for the coordinator: the SPEC row (protected in this lane) still
    names `Store.Verify`/`TestStoreVerify`; it should name Claim/Release,
    the new tests and issue #2218, with owner approval (Codex finding 4).
