# Plan: #2303 Platform SRK CLI (`xkey tpm srk enroll`, fido2 --backend tpm2)

## Objective

`xkey tpm srk enroll` enrols the Platform SRK with a user PIN read from
`--pin-file`, `--pin-stdin` or `XKEY_PIN` (never a flag value, default or
log, ruling 994), and `xkey fido2 --backend tpm2` uses that PIN as the
Platform SRK auth in a later process (rulings 993, 998).

## Slices

1. `tpm srk enroll` CLI and Platform SRK auth for fido2 tpm2 (done).
   Tests: enrol by PIN file and stdin, idempotent re-enrol, wrong PIN
   refused by fido2.
2. A named PIN source that fails stops fido2 before any TPM auth (done).
   Tests: `fido2_platform_srk_pin_test.go`.
3. Codex P1 x2 at 86dc0ffef (ruling 1008):
   - The TPM the `tpm` commands open has the persistent key store under
     `<dataDir>/tpm` (the store `localtpm` uses) as `TPMParams.Backend`, so
     enrolment records the SRK's enrolment PCR digest; the platform key
     store of `tpm srk enroll` uses the same store. Test: enrolment writes
     the record, PCR 11 is extended, a child key is still created.
   - Credential tests resolve the PIN through fido2's `--pin-file` and
     `--pin-stdin` and open a fresh TPM object and key store over the
     simulator (the separate-process equivalent); PIN tests change PCR 11
     first, so they fail if `loadFIDO2PlatformSRKAuth` stops setting the
     SRK password. Test: re-enrolment from a fresh open is idempotent and
     refuses another PIN.
   - `make skill-reference` in xkey keeps `skills/xkey-agent/reference/cli.md`
     current.
4. Ruling 1011: mutation evidence for the fresh-process PIN tests. With
   the `attrs.Password` assignment in `loadFIDO2PlatformSRKAuth` deleted,
   `go test -race -tags "codec_cbor codec_json codec_msgpack tpm_simulator"
   -run TestTPMSRK ./cmd/xkey/cmd/` fails `TestTPMSRKEnrollPINStdin` and
   `TestTPMSRKEnrollRecordsPolicyAndSurvivesPCRChange` (`--pin-file`) with
   `TPM_RC_POLICY_FAIL`; the tests resolve the PIN through fido2's
   `--pin-file`/`--pin-stdin` and open a fresh TPM and key store, so no
   test change was needed.
5. Ruling 1014: `resolveSRKEnrollPINs` resolves the user PIN and the SO PIN
   independently; each prompts only when its own source is empty and stdin
   is a terminal, so a user PIN from `--pin-file` or `XKEY_PIN` no longer
   skips the SO PIN prompt a TPM with owner auth needs. No terminal and no
   SO source still means an empty SO PIN. Tests:
   `tpm_srk_so_prompt_test.go`. The provisioned simulator tests keep the
   TPM key store in a per-test data dir, so no LAK blob outlives a run in
   the home data dir.

## Out of scope

- fido2's own key store for credential keys (still in memory).
- A `--data-dir` flag for `tpm` commands (`XKEY_DATA_DIR` / config apply).
- SPEC.md and workflow changes.
