# 2335: cross-tenant negative tests for same username and email

## Objective

Prove that two tenants holding an account with the same username and email
never resolve, bind, authenticate or activate across the tenant boundary,
and land PR #2370 green: its own tests, the Codex round-1 findings and the
red checks of its head.

## Slices

1. Tests (done): auth resolution, passkey binding/authentication and
   invite activation each stay inside the caller's tenant
   (pkg/auth, pkg/server tests).
2. Codex round 1, invitation redemption over a qrdb transport client:
   CreateUser refuses an invited (pending) account with ErrNotConfigured
   before persisting it when no user client with guarded activation is
   set (a dialed qrdb transport client has none). Test: a real
   qrdb QUIC frame transport wired through SetUserClients never receives
   user.Create. The REST, MCP and gRPC test mocks gain the guarded
   activation methods (the invite tests of those packages were red on
   the PR's head without them: the Coverage shard failure).
3. Codex round 1, concurrent TPM key-pair recovery
   (pkg/tpm2/session.go): serialize the pair mutation so a recovery that
   lost its fence cannot overwrite the private blob of a completed one.
   Test: pause one recovery before its private write while another
   completes; the stored pair loads.
4. Codex round 1, node browser tests: passkey-node.spec.ts provisions the
   operator through an administrator-issued invitation instead of
   anonymous registration (refused on the node), then tests login. The
   passkeyAccount helper takes the server origin and state directory
   (PasskeyServer; the node suite passes 18464 and .runtime-node), and
   config-node.yaml requests the admin client certificate. Typecheck only
   locally; the live suite runs in CI.
5. Codex round 2, node fixture login limiter: config-node.yaml sets
   auth.session.login_rate_per_min 6000 (as the webauthn-browser fixture),
   so the serial provisionOperator ceremonies do not hit the 10/min
   default. Test: internal/buildgates reads both fixtures.
6. Codex round 2, NodeCORS: a module with WithCORS and no WithRESTServer
   reports its policy to the node's outer CORS layer. Test: NodeCORS
   equals DaemonCORS of the WithCORS options. (A WithCORS subtest of the
   refusal harness mounts but answers 401, not 403, to an unbound
   certificate, so it was not added.)
7. Codex round 2, cross-process key-pair recovery: the in-process mutex
   is replaced by store-guarded writes (store.KeyBlobSwapper over the
   qrdb DAO CompareAndSwap) for the fence takeover, the private write and
   the publish; a backend without it fails closed. Test: a recovery that
   shares no lock takes a paused one over, which then fails.
