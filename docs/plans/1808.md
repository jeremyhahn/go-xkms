# Plan: row #1808 ssh-sessions

## Objective

Issue #1808 (SPEC row ssh-sessions, already `shipped` in docs/SPEC.md):
`session.DialClient` (pkg/ssh/session/dial.go) must close the TCP
connection when its context ends during the SSH handshake, and report the
cancellation as a TimeoutError; it never returns a client on a closed socket.

## Fold

This branch starts at the head of fold PR #2170 (865dbc9df, the port of
the #1756 fix from the Gitea history), merged with main. PR #2170's change
ships under this row's PR.

## Slices

1. DialClient cancellation (done in 865dbc9df): dial.go watches the
   context during `ssh.NewClientConn` and closes the conn when it ends.
   Test: `TestDialClient_CancelDuringHandshakeClosesConn` in
   pkg/ssh/session/dial_gaps_test.go, with a peer that accepts the TCP
   connection but never sends its banner; the cancelled dial returns a
   TimeoutError and the peer sees the connection closed. Companion tests
   `TestCloseAfterFailedHandshake_*` cover the close-error handling.
2. This plan (docs only).
3. Codex P1 on slice 2's review (dial_gaps_test.go:187): receiving the
   accepted connection did not prove DialContext had returned, so the
   test could pass through the dial's own cancellation path without the
   handshake watcher. Fixed in cfd5cfa89 (test only, no code change): the
   peer reads and checks the client's `SSH-2.0-` version line under a 5 s
   deadline before `cancel()`, still withholding the server banner.
   Check: with the watcher disabled by hand (AfterFunc bound to
   `context.Background()`, not committed) the test fails with "DialClient
   did not return within 2s of cancellation"; restored, it passes.
4. Codex P1 (security) on dial.go:238: when cancel wins after a
   successful handshake, closing the bare sshConn and discarding
   chans/reqs strands the x/crypto v0.58.0 mux goroutine blocked sending
   queued peer requests into its 16-entry channels. Test 14159e2c4
   (`TestDialClient_CancelAfterAuthWithQueuedRequestsLeavesNoGoroutine`):
   the peer queues 20 global requests and 20 channel opens, a test-only
   `afterHandshakeHook` cancels once the client mux is blocked on a send,
   and the goroutine count must return to baseline within 5 s. On the old
   dial.go it fails ("1 goroutines left behind"). Fix bcde2d217: close
   `ssh.NewClient(sshConn, chans, reqs)` so its handlers drain both
   channels; the test passes.
5. Codex P1 on that test (dial_gaps_test.go:313): under
   GODEBUG=fips140=only the default key exchange (X25519) is refused and
   the hook failed the test before the cleanup path ran. Fixed in
   472833186: the hook only records the handshake error, and the test
   passes DialClient's error to `fipstest.OutsideFIPSAfterRefusal`, which
   requires the refusal and reruns the test outside FIPS enforcement.
   `./pkg/ssh/...` passes both as-is and with GODEBUG=fips140=only.
6. Codex P1 (dial_gaps_test.go:348): both cancellation tests cancel
   before DialClient returns; none checked that cancelling the dial
   context after a successful return leaves the client usable (the
   AfterFunc watcher must be disarmed on success). Test 7d58aa53c
   (`TestDialClient_CancelAfterSuccessfulDialLeavesClientUsable`) dials,
   cancels the context, then sends three global requests that the peer
   must answer; under fips140=only it follows the same
   refusal-and-rerun convention. With the watcher left armed it fails
   ("global request 0 after cancelling the dial context: EOF"); dial.go
   already disarms it, so no fix commit was needed.

Gates: `go test -race -tags "codec_cbor codec_json codec_msgpack"
./pkg/ssh/...` and `make lint`.
