# Plan #2299: pool toolchain image once per hash, bounded apt-get

## Objective

A same-repo PR that changes the toolchain hash waited about 2 hours on
Devcontainer (PR #2183, run 44546824321): `scripts/ci-registry.sh resolve`
found no `<hash>-main` on GHCR, so every consumer job ran
`make docker-build-toolchain` on its own runner, and each apt-get hung on the
in-network apt cache (0-byte body, CLOSE-WAIT; Acquire::http::Timeout never
fires). Build the image once on the self-hosted pool, and bound apt-get.

## Changes

1. Same-repo PRs (`head.repo.full_name == github.repository`): the
   `ci-images` job runs on the self-hosted `bigdisk-docker` pool. When
   `<hash>-main` does not resolve on GHCR it builds each family once and
   pushes `<CI_IMAGE_REGISTRY>/go-xkms-ci-<family>:<hash>` (registry from
   `secrets.CI_IMAGE_REGISTRY` via the job env, masked, never logged or
   written to a file), and outputs a digest reference. Consumer jobs keep
   `scripts/ci-registry.sh use` with that digest; on a same-repo PR an empty
   reference fails instead of building locally. Main and fork PRs keep the
   GHCR path unchanged.
2. Every Dockerfile `apt-get` RUN call is `timeout 300 apt-get ...`; each
   "Take the toolchain image" step has `timeout-minutes: 30`.
