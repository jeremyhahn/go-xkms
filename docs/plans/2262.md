# Plan: backend-pin-strategy (#2262)

Owner decision 230, ruling 863. SPEC row `backend-pin-strategy`.

## Objective

xkmsd cannot start with a PIN-protected PKCS#11 backend: a literal PIN
is refused since #654, and `credential://` cannot resolve before the
backends start under manual unseal. The backend PIN (`backends.pkcs11.pin`,
`rng.pkcs11.pin`) is resolved through `pkg/pinselect` under one strategy:

- `auto` (default): `tpm2` when a TPM 2.0 is present, otherwise `sealed`
  (the i.MX 95 has no TPM, so auto selects `sealed`);
- `tpm2`: sealed to the TPM;
- `sealed`: sealed under the barrier, released at unseal; the PKCS#11
  backend starts after unseal;
- `manual`: never stored; supplied with the unseal request, held in
  memory only, zeroized at seal; the backend stops at seal.

PKCS#11 is never the store for its own PIN. The resolved strategy is
persisted (`<PINDir>/backend-strategy`) and reported in status.
Resolution fails closed and never downgrades silently. An optional
`backend_pin.minimum` refuses to start below it (order: sealed < tpm2 <
manual).

## Slices

1. pinselect + config (this lane, pn2262b):
   - `pinselect.ResolveBackendPIN`: auto/tpm2/sealed/manual, persisted
     record, mismatch refused, unavailable strategy fails closed, minimum
     enforced, PKCS#11 self-store refused.
   - `pinselect.BackendPIN` holder: sealed release after unseal, manual
     supply (copied, never persisted), zeroize at seal.
   - `config.BackendPINConfig` (`backend_pin.strategy`, `.minimum`) with
     validation.
   - Tests: `pkg/pinselect/backendpin_test.go`,
     `pkg/config` backend PIN validation tests.
2. server wiring (done, pn2262c): start-up resolve after
   `resolveConfigSecrets` (`Server.resolveBackendPIN`, fail closed),
   PKCS#11 backend start after unseal (`startPKCS11AfterUnseal`), manual
   PIN through `Server.UnsealBackendPIN`, backend stop and zeroize at seal
   (`SealBackendPIN`), strategy for status (`BackendPINStrategy`).
   Tests: `pkg/server/backend_pin_test.go`.
   Stub barrier (pn2262d): no barrier fails closed for sealed/auto (kept);
   the nofrost stub test selects manual, a New() test asserts the refusal.
3a. shutdown + status (done, rw2328a): `closeBackends` calls
   `SealBackendPIN` first (PIN zeroized at shutdown, provider closed once:
   test 8cf31e1ee, fix 24aceea70); `GetCredentialStrategy` and REST
   `GET /api/v1/credentials/strategy` carry `backend_pin_strategy` from
   `XKMSService.SetBackendPINStrategy`, wired to `Server.BackendPINStrategy`
   (test 4c82333a4, feat 58ac392a6). MCP returns the transport response.
   Open:
   - manual PIN on the unseal request: the unseal request is go-qrdb's
     sealed window (`qrdbnode.ServeSealedWindow`), which carries no backend
     PIN; needs a go-qrdb seam before `UnsealBackendPIN` has a caller;
   - gRPC (done, 3b rw2328c): new `GetCredentialStrategy` RPC with new
     `GetCredentialStrategyRequest`/`CredentialStrategyResponse` messages
     (no existing message changed), handler gated on credentials:strategy
     as REST, gRPC client maps `backend_pin_strategy` (no ErrNotSupported);
   - the pre-node PKCS#11 open (Raft key on the token) still runs before
     unseal: done (cr2328d, test 92c1b06ad, fix 69b7044f4): the strategy is
     resolved with a tpm2 floor before the open; anything else is refused
     (`ErrBackendPINNodeKeyBeforeUnseal`) before any open or record.
3c. Codex P1s on #2328 (cr2328c): an existing `{}`/`null` strategy record
   is a load error, never "not persisted"; the opener's PIN copy is wiped; the running barrier's
   `OnSealing` hook calls `SealBackendPIN`. Tests in
   `pkg/pinselect/backendpin_test.go`, `pkg/server/backend_pin_test.go`.
   Manual is refused at start-up (`ErrBackendPINManualUnavailable`,
   `TestResolveBackendPIN_ManualRefusedUntilUnsealSeam`) until a go-qrdb
   seam carries the backend PIN on the unseal request and the xkms service
   registers keystores late; the holder lifecycle is kept tested.
   The PKCS#11 self-store check applies to `sealed` only: tpm2 with
   `credentials.seal_strategy: tpm2` under `barrier.strategy: pkcs11`
   resolves to tpm2 (rl2328a,
   `TestResolveBackendPIN_TPM2UnderPKCS11BarrierIsNotSelfStore`; passed
   unchanged, no fix).
3d. Codex round 1 on b1c9a1df5 (af2328): `pinselect.BackendPINConfig.Store`
   (from `credentials.seal_strategy`: tpm2 -> tpm2, barrier -> sealed)
   refuses a strategy its storage does not provide, before persisting and
   on a persisted record (`BackendPINStoreError`); the release re-checks
   both. auto selects tpm2 on any TPM host, never sealed; tpm2 seals a PIN
   not stored in the TPM to it after unseal (sx2328a). An
   unset `rng.mode` is auto for the RNG PIN policy. Manual stays refused;
   the changelog says so. Tests: `TestResolveBackendPIN_StoreMismatchIs*`,
   `_AutoWithTPMSelectsTPM2`, `_SealedRequiresBarrierCredentialStorage`,
   `_RNGPINWithDefaultModeIsPolicyBound`.
3e. Codex round 3 on 91fdab63 (cr2328h): pinselect checks the minimum
   before the store, and the pre-node open marks a store refusal
   (`TestOpenPreNodePKCS11Backend_*`, pkcs11 tag). The preflight checks the
   effective strategy (auto or persisted) via `pinselect.CheckBackendPIN`,
   which persists nothing, so default/auto never wait on a credential
   reference (`TestBackendPINPolicyPreflight_DefaultAndAutoUseTheEffectiveStrategy`).
   The TPM custody migration stages the envelope under
   `xkms-internal.backend-pin-custody.<name>` (a reserved namespace operators
   cannot submit into) before deleting the plaintext;
   `recoverBackendPINCustody` completes an interrupted one at start-up,
   once per credential when the key backend and RNG PINs share one
   (`TestReplaceBackendPINCredential_InterruptedMigrationRecoverable`). The
   holder keeps the PIN in a `secure.Buffer` (secure-analyzer).
4. docs (done, rl2328a): `docs/backend-credentials/user.md` §"Backend PIN
   strategy". SPEC row flip left to the Tenant.
