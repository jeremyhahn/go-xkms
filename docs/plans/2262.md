# Plan: backend-pin-strategy (#2262)

Owner decision 230, ruling 863. SPEC row `backend-pin-strategy`.

## Objective

xkmsd cannot start with a PIN-protected PKCS#11 backend: a literal PIN
is refused since #654, and `credential://` cannot resolve before the
backends start under manual unseal. The backend PIN (`backends.pkcs11.pin`,
`rng.pkcs11.pin`) is resolved through `pkg/pinselect` under one strategy:

- `auto` (default): `tpm2` when a TPM 2.0 is present, otherwise `sealed`
  (the i.MX 95 has no TPM, so auto selects `sealed`);
- `tpm2`: sealed to the TPM;
- `sealed`: sealed under the barrier, released at unseal; the PKCS#11
  backend starts after unseal;
- `manual`: never stored; supplied with the unseal request, held in
  memory only, zeroized at seal; the backend stops at seal.

PKCS#11 is never the store for its own PIN. The resolved strategy is
persisted (`<PINDir>/backend-strategy`) and reported in status.
Resolution fails closed and never downgrades silently. An optional
`backend_pin.minimum` refuses to start below it (order: sealed < tpm2 <
manual).

## Slices

1. pinselect + config (this lane, pn2262b):
   - `pinselect.ResolveBackendPIN`: auto/tpm2/sealed/manual, persisted
     record, mismatch refused, unavailable strategy fails closed, minimum
     enforced, PKCS#11 self-store refused.
   - `pinselect.BackendPIN` holder: sealed release after unseal, manual
     supply (copied, never persisted), zeroize at seal.
   - `config.BackendPINConfig` (`backend_pin.strategy`, `.minimum`) with
     validation.
   - Tests: `pkg/pinselect/backendpin_test.go`,
     `pkg/config` backend PIN validation tests.
2. server wiring (done, pn2262c): start-up resolve after
   `resolveConfigSecrets` (`Server.resolveBackendPIN`, fail closed),
   PKCS#11 backend start after unseal (`startPKCS11AfterUnseal`), manual
   PIN through `Server.UnsealBackendPIN`, backend stop and zeroize at seal
   (`SealBackendPIN`), strategy for status (`BackendPINStrategy`).
   Tests: `pkg/server/backend_pin_test.go`.
   Stub barrier (pn2262d): no barrier fails closed for sealed/auto (kept);
   the nofrost stub test selects manual, a New() test asserts the refusal.
   Open: the transport unseal handler and the seal path must call
   `UnsealBackendPIN`/`SealBackendPIN` (the barrier unseal request is
   go-qrdb's sealed window), the status response must carry
   `BackendPINStrategy`, and the pre-node PKCS#11 open (Raft key on the
   token) still runs before unseal.
3. docs: `docs/backend-credentials/user.md`; SPEC row to shipped.

## Out of scope

- The tpm2 sealing primitive itself (consumed through the existing TPM
  provider); qrdb PIN strategy (`pin.strategy`) is unchanged.
- xkey, Makefile, workflows, scripts.
