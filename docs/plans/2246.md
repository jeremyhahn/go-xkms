# Plan: xkey command tests wait long enough on slow storage (#2246)

Red-main fix, ruling 742 item 4 (DS-9273). Main 81a1a5fb3 is red on
Nested Module Tests.

## Cause

In job 133717289375 the runner's storage syncs took 1.1-2.7 s. Three xkey
command tests use fixed 5 s and 10 s ceilings in their `Eventually` and
`time.After` waits, and those ceilings ran out before the work finished:

- `oidc_aws_cmds_test.go`: the callback-server wait, the mismatched
  callback return, and `awsAutoRefreshUntil`;
- `oidc_barrier_test.go`:
  `TestRunAutoRefresh_ReusesTheSameOpenBarrier_NotReopenedPerTick`;
- `oidc_login_flow_test.go`: the printed-URL wait and the login return.

## Change

One slice, test code only:

- new `xkey/cmd/xkey/cmd/testwait_test.go` with `slowStoreWait = 60 s`,
  a ceiling, never a sleep;
- the eight fixed ceilings in the three files use it. Poll intervals,
  conditions and assertions stay as they were: no retry, no skip.

Test commit: see the `test(xkey)` commit on this branch.

## Out of scope

Non-test code, the Makefile, workflows and the runner's storage.
