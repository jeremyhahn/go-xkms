# Plan 8475: make vuln passes without reaching GO-2026-6911

- Cause: make vuln reports GO-2026-6911 in github.com/mark3labs/mcp-go (SSRF and credential leak through a Location header; no fixed version, also at v1.5.0); pkg/mcptool/client.go Client.Connect reaches it through mcpclient.NewStreamableHttpClient, and the vuln target reads no exclusion file.
- Plan: save the govulncheck trace; replace NewStreamableHttpClient with a streamable HTTP transport of our own (no cross-origin redirect, no credentials to another origin) passed to mcp-go's transport-taking client constructor; a redirect test first (test commit), then the fix (fix commit); then make vuln, make test-mcp, make lint.

## Fix

pkg/mcptool/streamable.go: our own streamable HTTP transport (mcp-go transport.Interface + HTTPConnection), passed to mcpclient.NewClient. It posts only to the configured endpoint, refuses any 3xx (CheckRedirect returns ErrUseLastResponse; ErrRedirectRefused), never reads Location. Test: pkg/mcptool/client_redirect_test.go (301/302/303/307/308 to a second httptest server; on main both the request and "Bearer" reached it).
