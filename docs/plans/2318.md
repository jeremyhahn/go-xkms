# Plan: #2318 in-house pins at the latest tag or held with a written reason

## Objective

Every in-house module pin (`github.com/jeremyhahn/*`) in the four go-xkms
modules (root, `sdk/go`, `web/desktop`, `xkey`) sits at its latest published
tag, or carries a `// held:` comment on its `go.mod` line naming the reason it
cannot move.

## Slices

1. Bump the pins that move cleanly (go-codec v1.5.1-alpha, go-frost
   v0.3.1-alpha) in all four modules with tidy `go.sum`; hold go-luks2,
   go-qrdb, go-qrdb/sdk/go and go-truststrap with a written reason (each
   needs go-enclave >= v0.10.0-alpha while the go-enclave replace pins
   v0.8.0-alpha). Test: `test/scripts/release-alpha.test.sh` asserts every
   reciprocal pin in the tree sits at one version (a bump never moves a
   reciprocal edge).
2. Keep the branch current with main (merge commits) until it lands.

## Out of scope

- Moving the go-enclave replace pin (the held pins move with that seam).
- Reciprocal go-xkms/sdk/go and xkey edges: they move only via release-alpha.
