# Epic #1573 hsm-device-protocol: landing PR #2382

## Objective

Land PR #2382: the SPEC and ROADMAP row hsm-device-protocol records owner
ruling 1243 (DS-10419): the HSM device is an xkmsd node that serves the
existing service API over mTLS. The PR is documentation only.

## Slices, in order

1. SPEC (docs/SPEC.md l98) and ROADMAP entry, one changelog line
   (`.changelog/unreleased/changed-1573-hsm-device-protocol.md`).
2. Codex round 1 P1, scope: the `tls.client_auth` validation in
   `pkg/config/config.go`, its test file and its changelog entry exceed the
   documentation-only row. They are reverted on this branch with revert
   commits (history kept), so the PR carries only the slice 1 files.
3. Red `Lint Gates [toolchain image]`: no change on this branch. The job
   ran on a self-hosted bigdisk-docker runner whose environment sets no
   GOPROXY, so `go env GOPROXY` is Go's default
   `https://proxy.golang.org,direct` and `scripts/ci-go-integrity.sh` (ruling
   869) refuses it before any Go runs. Reproduced locally: GOPROXY unset
   fails with that message, a LAN-first `<lan>|https://proxy.golang.org`
   passes. The fix is the pool's runner environment (a LAN-first GOPROXY
   without `direct`, ruling 862), not the workflow: a workflow, job or step
   GOPROXY is refused by `TestCIPoolStepsKeepTheLANProxy`. Main fails the same
   way; after the pool fix, a run-level rerun of the job clears it.

## Out of scope

- Refusing an unknown `tls.client_auth` at config validation. It is a
  configuration-hardening change for its own brief and PR; the reverted
  commits (test, then fix) can be cherry-picked onto that branch as they are.
- Any HSM device code: the row records the protocol decision only.
