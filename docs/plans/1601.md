# Row 1601 transparency-log: plan

Objective (docs/SPEC.md:133): go-xkms implements go-qrdb's `HeadSignerProvider`
over the CA `crypto.Signer`; go-xkms ships no log, Merkle or proof code.

## Seam

The pinned `github.com/jeremyhahn/go-qrdb/sdk/go v0.58.5-alpha` exports the
seam: `sdk.HeadSignerProvider` (alias of `pkg/vlog.HeadSignerProvider`) and
`node.WithHeadSignerProvider`. No bump is needed.

## Slices

1. Done: `pkg/ca/tlog`: `HeadSignerProvider` over the CA `crypto.Signer`
   (ECDSA P-256 and Ed25519; RSA refused with `UnsupportedKeyError`); the CA
   public key is the checkpoint key and no key record is written. Tests in
   `pkg/ca/tlog/headsigner_test.go`.
2. Done: node wiring: `Server.headSignerProviderOptions` in
   `pkg/server/cluster_ca_keyprovider.go`, added to the node options in
   `pkg/server/qrdb_node.go`, bound to the TrustedCA after the CA is built
   (`pkg/server/server.go`, beside the cluster CA key provider). Test in
   `pkg/server/transparency_log_test.go`.
3. Next: append hooks: issuance, image signing and revocation append an
   entry to their log, with tests proving the emitted entries.

Out of scope: log, Merkle and proof code (go-qrdb owns them).

## Changes the dependency bump forces

The bump (996352ca3: go-qrdb v0.58.5-alpha, go-enclave v0.11.1-alpha; was
qrdb sdk v0.51.0-alpha, enclave v0.8.0-alpha) changes these exported surfaces.
Both are kept; neither is reverted.

- `sdk/go` `ShamirProtectedShare` (sdk/go/crypto.go:38) replaces
  `ShamirShare`. go-qrdb `sdk/go` v0.58.5 no longer exports `ShamirShare`
  (`go doc .../go-qrdb/sdk/go ShamirShare`: no symbol); it exports
  `ShamirProtectedShare = shamir.ProtectedShare`, whose value sits in
  go-enclave protected memory. The old alias cannot compile, and keeping the
  old name over the new type would hide a changed type. Commits 87013c20c,
  e57c65d92; test `sdk/go/crypto_shamir_test.go`.
- xkey `BarrierService.ChangePassword(currentPassword, newPassword)`
  (xkey/pkg/gui/services/barrier_service.go:591) and
  `BarrierService.PasswordBound` (barrier_service.go:649), used by
  `PINService.ChangeUserPIN` (pin_service.go:388, :425), with
  `ErrBarrierCredentialUnverified` (errors.go:411) and
  `BarrierCommittedError`. go-qrdb v0.58.5 `ChangePassword` takes the current
  credential and refuses a wrong one even on an unsealed barrier (see
  pkg/pkcs11/localseal/localseal.go:105-107, :155). The pre-bump PIN change
  called `ChangePassword(newPIN)` after committing the PIN, rewriting the
  barrier without the old password; that call no longer exists, and calling
  the new one after the PIN commit would leave PIN and barrier out of sync
  whenever setup gave the barrier its own password. `PasswordBound` is the
  minimal pre-commit check: it calls qrdb `VerifyCredentials` (no state
  change) and fails closed on any error, a mismatch included, because
  v0.58.5 reports strategy failures as the same `ErrCredentialMismatch`.
  The rollback covers a reseal that fails after the PIN commit. Commits
  7d6541ff2, fbc8f7f9d, 5fec89b56, c8e2b9067, 7574ecf4b, a180b2687,
  396de18be, ab2e8978a, 29e0b3886, a6b9c2921; tests
  `xkey/pkg/gui/services/barrier_service_test.go`, `pin_service_test.go`,
  `barrier_pin_change_strategy_test.go`.
