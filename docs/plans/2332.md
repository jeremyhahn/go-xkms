# #2332: qrdb node stop races the node start goroutine

## Objective

`make coverage` (-race) on main reports a data race in
`TestInitializeCA_QRDB_CorruptPersistedCertificateFailsClosed`: the read is
under `(*Server).stopQRDBNode` (reached from `closeQRDBStorage` in the test
cleanup), the write in a goroutine created under `newQRDBNode`
(`embeddednode.NewNode` -> go-qrdb `node.NewStandaloneNode`). Shutdown must be
synchronised with the node start.

## Slices

1. mf2332a (this lane, the only slice)
   - Test: `pkg/server/qrdb_node_stop_race_test.go`,
     `TestQRDBNodeStop_RacesNodeStartGoroutine`: start the qrdb storage the
     way the out-of-band CA reader does and close it at once, five times over
     one data directory, under -race.
   - Fix: the node lifecycle fields (`qrdbNode`, `qrdbClient`,
     `qrdbAuditSink`, `nodeSealClose`) are published in
     `initEmbeddedQRDBNode` and snapshot-and-cleared in `stopQRDBNode` under
     the Server's existing `s.mu`. The closes run outside the lock (a node
     goroutine may call a resolver that takes `s.mu` while Close drains it)
     and keep their order: node, audit sink, nodeSealClose.
   - Changelog: `.changelog/unreleased/fixed-2332-qrdb-stop-race.md`.

## Finding

The race does not reproduce locally (stress runs at -cpu 1,2,8, with and
without atomic coverage). The goroutine that writes is started inside go-qrdb
(`sdk/go/node`, v0.51.0-alpha); if the racing address is a go-qrdb Node field
read by `Node.Close`, the fix belongs in go-qrdb (its lifecycle gate) and the
pkg/server lock above only covers the xkms side.

## Out of scope

- go-qrdb internals and a go-qrdb bump.
- pkg/embeddednode beyond the call it already makes.
