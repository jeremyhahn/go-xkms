# Plan: #2284 xkey ssh connect/console send no key owner to a server unless given

## Objective

Against an xkmsd server, `xkey ssh connect`, `xkey ssh console` and server
profiles send no key owner unless `--key-owner` (or the profile) names one,
so the server resolves a user-scope key to the logged-in caller (rulings
937, 938). The local store path (no server, `--local`, `--identity`,
`--ssh-config-alias`, no key) keeps the `local` owner.

## Slices

1. CLI default (done, lane rl2284a): `defaultSSHKeyOwner` in
   `xkey/cmd/xkey/cmd/ssh_connect.go`, used by connect, console and
   profile add. Tests: `ssh_key_owner_test.go` (resolver defaults with and
   without a server, profiles).
2. Codex round 1 (lane af2360):
   - Server owner resolution: `pkg/ssh/tenancy` resolves an omitted
     user-scope owner to the authenticated caller's subject (`ownerOf`)
     before authorization and storage access, on every keys, known-hosts,
     authorized-keys, session and console call. Test:
     `TestKeys_OmittedUserOwnerIsCaller` (generate, get, signer, export,
     delete and pin add with no owner; no reach into another user's key;
     no fill-in without an identity).
   - Local host pins: a server-backed connect keeps a concrete owner
     (`sshHostPinOwner`, `local` when the key owner is omitted) for the
     local pin store it seeds from and syncs to. Test:
     `TestSSHConnect_ServerBackedOmitsKeyOwnerButPinsLocally` (remote
     Signer gets no owner; accepted key pinned under `local`; next connect
     seeds it; another owner's pin is never seeded).
3. Round-1 follow-up (sx2360a): known-host Verify/Callback resolve an
   omitted owner; a session dial whose host-key scope differs from the key
   scope uses the caller's own pins when no host-key owner is given. Tests:
   `TestSession_OmittedKeyOwnerIsCaller`, `TestConsole_OmittedKeyOwnerIsCaller`
   (server console keeps pins under the caller). Changelog entry
   `changed-2284-ssh-key-owner-default.md`.
4. Codex round 2 (sx2360b): those two tests now handshake with in-process
   SSH servers on 127.0.0.1 instead of an unreachable port. The caller's
   own pin (host key H1) admits the session dial and the console; a host
   key pinned only under another owner of the scope (H2) is refused as a
   host-key mismatch, never as an owner-binding refusal. Covers omitted
   and explicit key owner, omitted host-key owner, and user pins under a
   tenant key. Dropping any owner-resolution line in `sessionClient.Dial`
   or `client.Console` fails them. No code change: the finding was a test gap.
5. Codex round 3 (sx2360c): server-backed `xkey ssh console` called
   `client.Console`, which every remote transport refuses
   (`ConsoleUnsupportedError`). `openSSHConsole` now signs through the
   server's `Keys().Signer` and opens the PTY in-process against the local
   pin store under `sshHostPinOwner`, like connect. Test (CLI path):
   `TestSSHConsole_ServerBackedSignsThroughServerAndVerifiesLocalPins`
   (omitted owner: server sees `""`, host pinned under `local` opens; a
   host pinned only for `alice` is a host-key error; `--key-owner bob`
   reaches the server; never `ConsoleUnsupportedError`).
6. Codex round 4 (sx2360d): REST carries an omitted owner as an empty
   path segment. `TestSSHREST_OmittedOwnerThroughSDKTransport` drives the
   in-tree SDK REST client against the tenancy-backed handlers behind a
   bearer-to-identity middleware: `/keys/user//laptop/public` and `/sign`
   export and sign the caller's key; bob's key is refused (passed at once,
   no code change). CI fix: the server-backed CLI tests set TMPDIR to a
   short `os.MkdirTemp` dir (`TestServerBackedConnectSocketDirIsShort`),
   keeping the agent socket under the unix sun_path limit.

## Out of scope

- Server-side owner resolution in list calls (an empty owner there already
  means "every owner the caller may see").
- A remote Console on the REST/gRPC/MCP/QUIC SDK transports: remote keys
  drive a local session through `Keys().Signer` (sdk/go/client/ssh/client.go).
