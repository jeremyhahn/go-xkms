# Epic 2544: http-01 logs the key authorization's length, not its value

## Objective

CA m2544: every Devcontainer job hangs in `make coverage` on the self-hosted
runners. `challengeHandlerHTTPx` (`pkg/acme/challenges/http-01/http01.go`)
logs the whole key authorization on its Error path (write failed) and its
Debug path (served). `TestResponder_ShutdownContextExpired` serves a 32 MiB
key authorization whose write fails at shutdown, so the test prints one
33 MB line; the runner worker stops handling step output there and the job
never ends. The key authorization is a challenge response, so the log
carries its length (`key-authorization-length`), not its value.

## Slices

1. Test commit: `TestChallengeHandlerHTTPx_LogsKeyAuthLength` sets slog's
   default to a JSON handler over a buffer at Debug, serves a distinctive key
   authorization through `challengeHandlerHTTPx` to an `httptest` recorder
   (Debug path) and to `failingWriter` (Error path), and asserts the log has
   `key-authorization-length` with the byte count and never the value. It
   fails before the fix.
2. Fix commit: both log calls use `slog.Int("key-authorization-length",
   len(keyAuth))`; CHANGELOG Fixed line. `responder.go` does not log the
   value and is unchanged.

## Out of scope

- `TestResponder_ShutdownContextExpired`'s body size and assertions.
- Other packages' logging.
