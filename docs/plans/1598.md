# Plan: image-signing (SPEC row, issue #1598)

Objective (issue #1598): close the `image-signing` SPEC row
(docs/SPEC.md, `in progress`): `pkg/image` signs and verifies container
images with a KMS `crypto.Signer`, and `pkg/signing` gains gtp's manifest
RSA check as its verify half.

## Slices

1. This plan and audit; row text: `pkg/signing` is no longer sign-only.
2. Fold 1794-image: 11 pkg/image tests that repeat a kept path removed
   (dsse, oci, reference, registry, signer, timestamp, verifier);
   `TestSigner_SignImage_RegistryUnavailable` kept (only test of
   `ErrRegistryUnavailable` from `SignImage`).
3. Trust-roots store: the four verifier_truststore_test.go tests above.
4. Row text: the image-signing and signing rows of docs/SPEC.md cite
   `pkg/signing.Verify` and `xkms.VerifySignature` (sdk/go/crypto.go).
5. Transparency log append (`image-signed`), after the transparency-log
   row lands its append verb on go-qrdb `pkg/vlog`: `SignerConfig` takes
   the log appender; `SignImage` appends image digest, envelope digest and
   signer, and fails when the append fails. Tests: append recorded,
   append error refused. Not in this PR.

## Seams (other repositories, no code here)

- go-qrdb #722 (`pkg/vlog`) and the transparency-log row: slice 5.
- go-quicbaas: replace Tier 0 `ImageSignature` with `VerifyImage`;
  re-export the `pkg/signing` verify.
- go-trusted-platform: drop its `pkg/image` and manifest RSA check, call
  the `pkg/signing` verify through go-quicbaas.

## Out of scope

Any new signing format, key type or registry feature beyond the row.
