# Plan: image-signing (SPEC row, issue #1598)

Objective (issue #1598): close the `image-signing` SPEC row
(docs/SPEC.md, `in progress`): `pkg/image` signs and verifies container
images with a KMS `crypto.Signer`, and `pkg/signing` gains gtp's manifest
RSA check as its verify half.

## Slices

1. This plan, and the row text: `pkg/signing` is no longer sign-only.
   No code: every clause go-xkms can meet alone is met on main.
2. Transparency log append (`image-signed`), after the transparency-log
   row lands its append verb on go-qrdb `pkg/vlog`: `SignerConfig` takes
   the log appender; `SignImage` appends image digest, envelope digest and
   signer, and fails when the append fails. Tests: append recorded, append
   error refused.
3. Fold refs/fold/image-signing/lane/test/1794-image (35f4e3309c9a): merged; 11 tests removed, TestSigner_SignImage_RegistryUnavailable kept (only test of ErrRegistryUnavailable from SignImage), coverage 93.7% unchanged (93.7% before, 93.7% after).

## Seams (other repositories, no code here)

- go-qrdb #722 (`pkg/vlog`) and the transparency-log row: slice 2.
- go-quicbaas: replace Tier 0 `ImageSignature` with `VerifyImage`;
  re-export the `pkg/signing` verify.
- go-trusted-platform: drop its `pkg/image` and manifest RSA check, call
  the `pkg/signing` verify through go-quicbaas.
