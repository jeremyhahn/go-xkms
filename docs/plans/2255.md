# Plan: version-ldflags (#2255)

## Objective

`xkmsctl version` and `xkmsd -version` report the version, commit and build
date the Makefile stamps, not `dev`.

## Cause

Makefile LDFLAGS stamped `github.com/jeremyhahn/go-xkms/pkg/cli.Version`,
`GitCommit` and `BuildDate`. There is no `pkg/cli` package, and the linker
silently ignores an `-X` target that names no variable. The variables live in
package main: `cmd/xkmsctl/version.go` (`Version`, `GitCommit`, `BuildDate`)
and `cmd/xkmsd/main.go` (`version`, `commit`, `date`).

## Slices

1. test(buildgates): `internal/buildgates/version_ldflags_test.go`
   - `TestMakefileLDFlagsTargetsExist`: each `-X` target of the Makefile
     LDFLAGS names a package-level variable (go/parser); `main.X` must exist
     in both `cmd/xkmsctl` and `cmd/xkmsd`.
   - `TestBinariesReportStampedVersion`: builds both binaries with every
     target set to `v9.9.9` and asserts each version command prints it.
   Both fail on main.
2. fix(build): xkmsd's variables renamed to `Version`, `GitCommit`,
   `BuildDate` (same names as xkmsctl); LDFLAGS stamps `main.Version`,
   `main.GitCommit`, `main.BuildDate`. Both tests pass.
3. docs(plan): this file.
4. fix(release): Codex round 1. release.yml and Dockerfile.{cli,server,
   grpc,rest,quic,mcp} build the binaries directly with `-X main.version`,
   `main.commit`, `main.date`; they now stamp `main.Version`,
   `main.GitCommit`, `main.BuildDate` (xkmsctl never had the old names).
   - `TestReleaseLDFlagsStampVersionTargets`: every line of those files (and
     any Dockerfile*) that stamps package main stamps exactly the three
     targets, with the expected line count per file.
   - `TestBinariesReportStampedVersion`: distinct probe per target, the
     Makefile must stamp exactly the three, and each value is asserted in
     its own output field for both binaries.

## Out of scope

- A shared version package for both binaries (two `main` symbols suffice).
- The c-shared library build, which also receives LDFLAGS and declares no
  version variables (the `-X main.*` flags are ignored there as before).
- xkey (own module; its version lives in package `cmd`), which release.yml
  builds with the same LDFLAGS: the `main.*` targets reach nothing there.
- `make build` needs Docker (builder image); verified with `make build-full`.
