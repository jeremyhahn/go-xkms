# Plan 8765: Unix socket paths that fit sun_path (red main, DS-8765)

## Objective

Main is red on "Nested Module Tests" (xkey tests, native) on the
trusted-platform runner pool. TMPDIR and t.TempDir() sit under a long
`/home/runner/_work/...` prefix there, so Unix socket paths built under
them exceed AF_UNIX's sun_path (108 bytes on Linux, 104 on macOS) and
bind/dial fail with EINVAL.

## Slices (one session)

1. Test: `pkg/ssh/connect` session with an empty Request.WorkDir under a
   long TMPDIR still starts its agent (fails on main with
   `bind: invalid argument`).
2. Fix: `pkg/ssh/connect/connect.go` makes its default work dir under a
   short base ($XDG_RUNTIME_DIR when it is a 0700 directory owned by the
   user and fits, else /tmp) when the TMPDIR-based socket path would not
   fit. Mode 0700, cleanup and ownership unchanged.
3. xkey test fixtures: `privateTempDir` falls back to a 0700
   `os.MkdirTemp("/tmp", "xk-")` directory (removed in t.Cleanup) when
   t.TempDir() is too long; the remaining socket paths built directly
   from t.TempDir() in `xkey/cmd/xkey/cmd` tests go through it.

## Tests

- New pkg/ssh/connect long-TMPDIR test.
- The four failing xkey cmd tests pass with TMPDIR of 90+ bytes.

## Out of scope

- CI workflow or runner changes; xkey/pkg/ipc behaviour (already handles
  long homes).
