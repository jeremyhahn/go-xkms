# Plan: #2183 Codex round-4 P1 (4): WebAuthn first-credential claim recovery

## Objective

A crash between the first-credential claim and the credential save must not
leave an orphan claim that blocks every later first-credential registration
of the account (Tenant Agent ruling 952, Codex round 4 on PR #2183,
pkg/webauthn/credential_store.go:103).

go-qrdb offers per-entity atomic writes (SaveIfAbsent, CompareAndSwap,
DeleteIfMatch) but no multi-entity transaction, so the claim and the
credential cannot be written in one step. The fix is fenced orphan-claim
recovery:

- A claim is written pending, with a random token and a lease expiry.
- The winner saves the credential, then commits: CompareAndSwap from its own
  pending claim to committed. The CAS is the fence: a claimer whose claim was
  recovered loses the CAS, deletes the credential it saved, and is refused.
- A later claimer that finds a pending claim past its lease, while the
  account has no credential, takes it over with CompareAndSwap from the
  claim it read. A live claimer inside its lease is never taken over.
- A failed save releases with DeleteIfMatch of the claimer's own claim, so
  it cannot delete a claim another ceremony recovered.

## Round-5 P1: TPM import key pair (ruling 968)

Create-only ImportKey (SaveKeyPair overwrite=false) wrote the private blob,
then the public blob; a fault between them left an unloadable key that every
retry refused. The public blob is written last, so it marks a complete pair:
a create-only save that meets a private blob without a public blob replaces
the incomplete pair; a complete pair still refuses (ErrKeyAlreadyExists).

1. test: importexport_sim_test.go fails the public-blob write once, retries
   the import, loads the key, then a different import still refuses.
2. fix: pkg/tpm2/session.go SaveKeyPair incomplete-pair recovery.
