# 966: trim in-use CI cache volumes inside (Tenant Agent ruling 966 (4))

## Objective

`scripts/trim-ci-caches.sh` only removes cache volumes no container uses and
keeps every in-use one, so a busy host's gobuild volume grew to 57G, filled the
disk and failed PR #2289's CI. When the total is still over the bound after the
unused volumes are gone, trim inside the in-use volumes, whole cache entries,
oldest first.

## Slices

1. Test: `test/scripts/trim-ci-caches.test.sh` with a fake `docker` on PATH
   (canned `volume ls`, `ps`, `du` sizes; the in-volume trim script is run
   against a local directory). Cases:
   - an in-use gobuild volume over the bound gets a read-write trim run, no
     `docker volume rm`;
   - the trim empties whole `xx/` entry directories, oldest first, and stops
     once enough is freed;
   - a gobuild volume over the bound on its own gets `go clean -cache`;
   - an in-use golangci volume is cleaned whole (`golangci-lint cache clean`
     style);
   - an in-use gomod volume is reported, never trimmed per file;
   - `REAP_DRY_RUN=1` issues no rm and no trim run;
   - an unused volume over the bound is still removed whole.
   Added to `make test-scripts`; fails at b89e4bc87.
2. Fix: `scripts/trim-ci-caches.sh` second pass over in-use volumes, through a
   one-shot toolchain-image container (no network, no capabilities, the
   volume's uid) mounting the volume read-write. Never fails the job.
3. Changelog entry `fixed-966-trim-ci-cache-inuse.md`.

## Out of scope

- `.github/workflows/` (moving the trim before the heavy stages), go.mod/go.sum.
- Per-file age trims of the module cache (never).
