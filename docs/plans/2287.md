# Plan: console login refresh store writes as the service principal (#2287)

## Objective

The PIV and WebAuthn console logins wrote the refresh token store under the
anonymous request context and failed with 500. The refresh store now writes
as the service principal (Tenant Agent rulings 943, 946, 948).

## Slices, in order

1. test(auth): `pkg/server/login_wiring_test.go` drives PIV login 200,
   `/auth/me` 200 with the new access token and the WebAuthn finish reaching
   Mint, for `enable_rbac` off and on. The refresh step moves to #2292
   (ruling 948).
2. fix(auth): `pkg/auth/token/store.go` writes the refresh store under the
   service context; `pkg/apimodule/module_host.go` passes the module's
   service context into the REST host's `ServiceContext`. Tests:
   `store_servicectx_test.go`, `module_host_servicectx_test.go`,
   `host_servicectx_test.go`.
3. fix(rest): `handlers_auth.go` logs the Mint error (error string and
   user/tenant only, no token material) on the PIV and WebAuthn 500 paths.
4. Changelog `.changelog/unreleased/fixed-2287-login-refresh-store.md`.
5. Finish slice: main merged in; the red `Integration [integration image]`
   check was the hosted runner running out of disk (`No space left on
   device` in the runner's own diag log), not a code failure: it needs a
   run-level rerun, no code change.
