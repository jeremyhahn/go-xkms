# #2292: refresh re-check runs as the refresh token's own user

## Objective

On an embedded xkmsd node, refresh answered 401 after PIV or WebAuthn
login: the user re-check ran under the public route's identity-less context.

Ruling 953: the re-check runs as the validated refresh token's user, never
as the service principal, with no new grant and no access-check bypass.

## Slices

1. Plan. 2. test(auth) pkg/server/login_wiring_test.go: refresh after PIV
   login rotates (rbac off/on); a user disabled after login gets 401.
3. fix(auth): `QRDBUserResolver` binds the validated token's stored subject
   inside `ResolveUser` only; wired on pkg/server and pkg/apimodule.
4. Changelog fixed-2292-refresh-recheck-user.md.

## Status: unblocked without the go-qrdb seam (ruling 973)

The re-check reads the token's user through the embedded node's own user
service (`auth.NewNodeUserClient`, 05a76c661), wired on `Server.nodeUserSource`
and `apimodule.WithNodeUsers`; a remote-qrdb host keeps the qrdb client.

## Ruling 1029 (B): scope is system-tenant passkey login

PR #2296 is narrowed to passkey login in the tenant the relying party
serves (the system tenant on xkmsd). Codex P1s on head 0e2cacd39:

1. Invite store calls (create, lookup, redeem) run on a system context
   (`inviteStoreContext`); the user operations keep the invite's tenant.
   Test: pkg/server/webauthn_tenant_ceremony_test.go, full redemption over
   an RBAC-enforcing embedded node.
2. Invite enrolment for an account outside the RP's configured tenant is
   refused with `ErrInviteTenantNotServed` (REST 403), before the token is
   looked up. Test: pkg/xkms/servicer_invite_tenant_test.go (account stays
   pending, invite unredeemed); pkg/api/rest/handlers_invite_tenant_test.go.

Tenant-aware passkey login and token minting for non-system tenants is a
separate SPEC row the coordinator opens.
