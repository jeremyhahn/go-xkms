# #2292: refresh re-check runs as the refresh token's own user

## Objective

On an embedded xkmsd node, refresh answered 401 after PIV or WebAuthn
login: the user re-check ran under the public route's identity-less context.
Ruling 953: the re-check runs as the validated refresh token's user, never
as the service principal, with no new grant and no access-check bypass.

## Slices

1. Plan. 2. test(auth) login_wiring_test.go: refresh after PIV login
   rotates (rbac off/on); a user disabled after login gets 401.
3. fix(auth): `QRDBUserResolver` binds the token's stored subject inside
   `ResolveUser` only. 4. Changelog fixed-2292-refresh-recheck-user.md.

Unblocked without the go-qrdb seam (ruling 973): the re-check reads the
user through the embedded node's user service (`auth.NewNodeUserClient`),
wired on `Server.nodeUserSource` and `apimodule.WithNodeUsers`.

## PR #2296 Codex findings (DS-9556, review 5992347678)

apimodule host forwards the service-context binder; node user adapter and
invite routes bind the trusted tenant; the webauthn credential store clears
the tenant binding on every call (qrdb_userstore_tenant_test.go,
pkg/server/webauthn_tenant_ceremony_test.go). Tenant-aware login (ruling
1019) reverted under ruling 1029 (B): scope is system-tenant passkey login.

## Ruling 1029 (B) and 1041

1. Invite store calls run on a system context (`inviteStoreContext`); user ops keep the invite's tenant.
2. Invite enrolment outside the RP's tenant is refused with
   `ErrInviteTenantNotServed` (REST 403) after the token lookup.
3. `UserStore.TenantID()`; an unset tenant is `*UserStoreTenantUnsetError`.
4. The refresh store's KV calls bind `Node.ServiceContext`
   (`token.WithCallContext`, #2287); SDK re-exports `WithServiceModuleNodeUsers`.
