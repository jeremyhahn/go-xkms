# #2292: refresh re-check runs as the refresh token's own user

## Objective

On an embedded xkmsd node, POST /api/v1/auth/refresh answers 401 after a
successful PIV or WebAuthn login (enable_rbac on and off): the issuer's
user re-check (`QRDBUserResolver.lookup`) calls the qrdb user client under
the public route's identity-less context and qrdb refuses it as
unauthenticated.

Owner queue 240 = (b) (Tenant Agent ruling 953): the re-check runs as the
user the validated refresh token belongs to. The service principal grant
does not grow, the lookup does not take a path that skips the access check,
and the re-check never runs as the service principal.

## Slices

1. Plan (this file).
2. test(auth): pkg/server/login_wiring_test.go on the xkmsd wiring over an
   authenticating embedded node: refresh after PIV login rotates the refresh
   token (enable_rbac off and on; fails at 878d9560e), and a refresh for a
   user an administrator disabled after login answers 401.
3. fix(auth): `QRDBUserResolver` takes a `func(ctx, subject) (ctx, error)`
   binder (nil = caller context), applied only inside `ResolveUser`, which
   the issuer calls after the refresh token was found, unrotated, unrevoked,
   unexpired and its family intact. The subject is the validated token's
   stored subject, nothing from the request. Wired on the xkmsd server path
   (pkg/server) and the apimodule host path (pkg/apimodule), each with a test
   first.
4. Changelog: .changelog/unreleased/fixed-2292-refresh-recheck-user.md.

## Status: unblocked without the go-qrdb seam (ruling 973)

The self-read seam is no longer needed. The refresh re-check reads the
token's user through the embedded node's own user service
(`auth.NewNodeUserClient`, fix(auth) 05a76c661): the read is in-process
on the node, takes no request credentials and adds no grant. The subject
is still the validated token's stored subject. Wired on the xkmsd server
path (`Server.nodeUserSource`) and the apimodule host path
(`apimodule.WithNodeUsers`); a host that dials a remote qrdb keeps the
qrdb client. Tests: pkg/server/webauthn_node_wiring_test.go,
pkg/apimodule/module_host_node_users_test.go.

## PR #2296 Codex findings (DS-9556)

1. apimodule: the module host forwards WithServiceContext's binder into
   HostConfig.ServiceContext (refresh store). Test: hostConfig test.
2. auth/xkms: the node user adapter binds the caller's server-side tenant
   on username/email lookups; the invite routes bind the invite record's
   tenant after Lookup. Tests: non-system tenant lookups and invite read.
3. server: buildRESTConfig sets Config.Logger to xkmsd's logger.

## PR #2296 Codex findings (review 5992347678)

1. webauthn: the credential store clears the tenant binding on every call
   (system bookkeeping; RBAC refused the bound system principal). Test:
   qrdb_userstore_tenant_test.go over a KV store that refuses bound calls.
2. OPEN (owner/SPEC decision): an account enrolled through a non-system
   invite cannot sign in. Email, handle and discoverable login and token
   minting resolve in the relying party's configured (system) tenant, and an
   anonymous login carries no tenant. Choose how login names its tenant (or
   refuse non-system invite enrolment) before a lane builds it.
