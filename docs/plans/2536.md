# Plan 2536: Devcontainer image step timeouts (CA m2536 item 2)

## Objective

Main run 42965847875 sat in the Devcontainer image job's `make coverage`
step for two hours, until it was cancelled, because no step carries a bound.
Only the job's 240-minute bound applies. Each step that runs
`scripts/in-toolchain-image.sh` gets its own `timeout-minutes`, so a hang
fails fast and points at the step.

## Findings (by reading; GitHub kept no log of the cancelled job)

- Makefile:470 `UNIT_TEST_TIMEOUT ?= 75m`: a deadlocked Go test package
  panics only after 75 minutes. test-go, test-nofrost and test-pkcs11 run one
  after another under `make test` (-p=2), so one hang uses most of the 2 h.
- Makefile:729-735 test-web: `npm ci --silent` has no overall bound (only
  npm's per-request fetch-timeout), and runs four times on the network.
- All vitest scripts are `vitest run` (no watch mode): not a suspect.

## Slices

1. Test commit: `internal/buildgates/ci_step_timeout_test.go`. Every step of
   jobs.image that runs in-toolchain-image.sh has `timeout-minutes` > 0 and
   below the job's. The coverage step's bound is below the job's. Fails on
   main.
2. Fix commit: step `timeout-minutes` in ci.yml (jobs.image only). Coverage
   gets 60 (no green duration on record: the brief's default). The others are
   sized from their known durations (lint 7 min, build 5 min). Add a CHANGELOG
   line under Unreleased. If no slow package needs 75m, lower or bound
   UNIT_TEST_TIMEOUT and npm ci.

Other jobs' steps, runs-on, new jobs or actions, the coverage threshold.
