# Plan: #2226 Seal under PlatformPolicy honours the PCR selection

## Objective

A tpm2 `Seal` under `TPMPolicyPlatform` with a requested
`TPMAttributes.PCRSelection` must give an object bound to every requested
PCR. Before, the platform-policy digest covered only `Config.PlatformPCRs`,
so a PCR the caller asked for that was outside the platform set (PCR 11 for
go-trusted-platform #1897) was silently dropped.

## State at the start of this row

The binding is already on main. #2213 (852146763) added
`sealPCRSet` (pkg/tpm2/object_policy.go), which builds the platform-policy pin
over the union of the platform set and the requested selection and refuses a
selection in another bank. It also records that union in the pin and in the
sealed blob metadata, so unseal rebuilds the same PolicyPCR session.
`TestSeal_PlatformPolicy_BindsRequestedPCRSelection` covers PCR 15 on top
of the default platform set {7, 11}. The persisted pin format did not
change: the pin's `PCRSelect` mask holds the union.

## Slices

1. Regression test, consumer shape (sp2226a): platform set {7}, sealed
   selection SHA-256 {7, 11}.
   - `TestSeal_PlatformPolicy_RequestedPCR11BindsBeyondPlatformSet`: extending
     PCR 11 after the seal makes the unseal fail.
   - Without the extend, the unseal returns the secret.

No fix commit: the test passes at d2f589812, because the binding is already in.

## Out of scope

- The PolicyAuthValue (PIN) branch of a password-protected platform-policy
  object. It opens without the PCRs by design (the recovery path,
  `TestSealUnseal_PlatformPolicyWithPIN_ExtraPCRBranchOpensWithoutPIN`).
- A PCR selection in a bank other than the platform bank. `sealPCRSet`
  already refuses it.
