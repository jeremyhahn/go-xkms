## Codex findings on 3345d0d39 (lane row1820b)

Each a failing test commit, then its fix commit.

1. P1: an unreadable key password (`Bytes` nil on a retrieval failure)
   let construction succeed without one. Test a3952fefd
   `TestCA_New_UnreadableKeyPasswordFails` (`secret_wiring_test.go`);
   fix d5696b4ba: `carryKeyPassword` borrows through `WithBytes`,
   copies, propagates the error.
2. P1: a transport-issued LAK was owned by the system scope. Test
   127776de0 `TestIssueLAKCertificateRaw_RecordsTenant`
   (`tcg_lak_raw_test.go`), `TestIssueLAKCertificate_ForwardsCallerTenant`
   (`pkg/xkms/servicer_ca_tcg_test.go`); fix d8366bf9c:
   `IssueLAKCertificateRaw` takes the tenant, the servicer passes
   `callerTenant(ctx)`.
3. P1: an AIA-walk lookup error was taken for absence and stored over
   the existing certificate. Test 0410f4170
   `TestImportIssuingCAsInto_LookupErrorPropagatesWithoutWrite`
   (`aia_import_test.go`); fix 135ceed84: only `certstore.ErrCertNotFound`
   authorizes the insert.
4. P1 (lane-verify Codex, 02:55Z): every signer lookup built a fresh
   locked key password through `Identity.ToKeyAttributes` and never
   cleared it, so repeated signing exhausted the go-enclave locked-memory
   budget. Test 8dc68762c
   `TestCA_RepeatedSigningKeepsPasswordAllocationsBounded` (`ca_test.go`);
   fix 783986214: `getSigner` and `IssuerForIdentity` clear the temporary
   password (`clearKeyPassword`) once the signer is obtained.
