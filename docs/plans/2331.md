# Plan: #2331 CORS allowed-origin validation

## Objective

`rest.NewServer` and `apimodule.NewModule` refuse at start any CORS allowed
origin a browser could never send: a wildcard, or a malformed
`scheme://host[:port]`.

## Slices

1. Shared validator `rest.CORSOptions.Validate` / `validateCORSOrigin`, called
   by both constructors. Tests: `TestCORSOptionsValidate` (wildcard, missing
   scheme/host, path, query, fragment, user info, port range),
   `TestNewServer_RefusesWildcardCORS`, apimodule module CORS test. (done)
2. Codex round 1 P1: bracketed hosts must be IPv6 literals
   (`https://[not-an-ip]`, `https://[1.2.3.4]`, zones refused) and an explicit
   empty port (`https://app.example:`) is refused. Tests: regression cases in
   `TestCORSOptionsValidate`.
3. Red `Integration [integration image]` on the PR head: the branch reads
   no CORS origin in any integration config or test (the one config,
   `test/integration/webauthn-browser/config.yaml`, lists a valid origin).
   Locally, the integration packages compile; `test/integration/oidccredentials`
   TestMain fails the same way on main (barrier never initialized before
   the sealed-window unseal), so the red is main's, not this row's. No code
   change.

## Out of scope

- Full DNS label syntax checks for unbracketed host names.
- Per-route CORS policy changes.
