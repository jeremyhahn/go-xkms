# Row #2233 tenant-exact key lookups

## Objective

Under the docs/SPEC.md `multi-tenancy` row (~l.104, shipped; text and status
unchanged): a key lookup resolves only the caller's tenant's key, so two
tenants (the system tenant included) holding keys with the same CN or key ID
never resolve each other's key.

## Defect

Key lookups matched on key ID / CN alone over the backend's listing, so an
unscoped (system) view could resolve a tenant's key of the same name, and the
PIV slot-key lookups could pick a tenant's key for a platform slot.

## Rule

- Key lookups are tenant-exact: a listing is filtered by the key ID and the
  tenant together (`versionsIn`, `pkg/xkms/key_versions.go:153`).
- The unscoped view is the system tenant's for lookups: `viewTenant`
  (`pkg/xkms/backend_tenant.go:50`) names the tenant a backend view resolves
  in; `FindKeyAttributes` (`pkg/xkms/key_versions.go:179`, :187) and
  `findKeyAttrs` (`pkg/xkms/servicer_helpers.go:144`, :149) use it.
- A named tenant is admitted through `auth.AdmitTenant` before the lookup:
  `resolveKeyIn` (`pkg/xkms/key_versions.go:270`, :272).
- PIV slot keys are the system tenant's: `isSystemTenantKey`
  (`pkg/xkms/piv_keygen_backend.go:193`) guards the slot-key matches
  (`piv_keygen_backend.go:179,212,360`, `pkg/xkms/piv_manager.go:875`).
