# #2379 ci-images on the runner pool, selection by event (DS-10474)

On github.com the `ci-images` job in `.github/workflows/ci.yml` now takes
preflight's `runner_docker` output (`fromJSON(needs.preflight.outputs.runner_docker)`),
as the `image` job does, instead of always `ubuntu-latest`; on the forge it
keeps `release` for a push to main and `bigdisk` otherwise. The preflight step
`Balanced runner pool (ruling 1137)` gains a `REF: ${{ github.ref }}` env and,
right after the v1.52 fork check, an event gate on `"$EVENT:$REF"`: only a
push to `refs/heads/main` and a same-repository `pull_request` reach the
balancing; every other event or ref (schedule, workflow_dispatch, a push to
another branch) takes the GitHub-hosted default with a `::notice` and no
Actions API call, because the self-hosted image hook refuses schedule and
dispatch runs. No trigger, schedule, secret, variable, action or other runs-on
changes. Tests: `internal/buildgates/ci_image_digest_test.go` pins the new
`producerRunsOn` (with a CanFail row for the old hosted-only literal),
`TestCIRunnerSelectionPoolsOnlyPushToMainAndSameRepoPullRequests` in
`internal/buildgates/ci_sched_devcontainer_test.go` drives the gate, and
section F of `.github/workflows/testdata/runner-select-tests.py` (now a go-xkms
customization of the handbook v1.54 file) covers schedule, dispatch, another
branch and a same-repository pull_request_target. Out of scope: the handbook's
ci-template copy of the step and test file, which now drift from this one.

## code-review.yml v5.12.12 (DS-10498)

`.github/workflows/code-review.yml` is the handbook template v5.12.12, copied
verbatim over main's v5.12.3 (the CUSTOMIZE blocks already matched, so no line
differs from the template). Drafts get no review and no scope job: the `scope:`
job's `if:` holds `github.event.pull_request.draft != true` and
`github.event.pull_request.state == 'open'`, and a cancelled review job fails
the gate closed. Per the template note, the scope job takes the bigdisk pool for
same-repository heads on github.com; ci.yml v1.54 on main accepts that line.
Test: `TestCodeReviewTemplateV51212` in `internal/buildgates/code_review_test.go`
pins the header, the scope `if:` and the v5.12.12 cancelled-review note; it
fails on main's v5.12.3 file.
