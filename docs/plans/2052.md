# Plan: #2052 Linux FIDO2 hidraw report-ID byte

## Objective

Prove or disprove the claim that the Linux FIDO2 HID transport
(`pkg/fido2/hid_linux.go`) writes CTAP frames to hidraw without the report-ID
byte, with a test through a real hidraw node, and fix the transport only if
that test fails.

## Slices

1. Test: `pkg/fido2/hid_linux_uhid_test.go`,
   `TestLinuxHIDDevice_UHIDRoundTrip`. A kernel UHID device
   (`pkg/fido2/uhid`) backs a hidraw node that `LinuxHIDDevice` opens.
   Write path: CTAPHID INIT frames with CID 00112233 and FFFFFFFF; the raw
   UHID_OUTPUT payload must be 65 bytes, report ID 0x00 then the frame.
   Read path: a 64-byte input report starting with 0x00 must come back from
   `Read` unchanged. Skips when `/dev/uhid` cannot be opened.
2. Fix (only if slice 1 fails on main's code): frame reports in
   `hid_linux.go` as the kernel expects, with a `fixed` changelog entry.
   No exported name or signature changes.
3. Finish PR #2205: merge `origin/main` (merge commit). The red
   `Devcontainer image` check was a registry pull failure of main's
   published toolchain digest (`scripts/ci-registry.sh` pull_ref), not a
   code defect: CI re-runs it on the new head.
4. The same pull failure recurred on head 5cc46dc7c (main e5fbfd5ca is
   already merged; the branch changes no devcontainer input). No code fix
   applies: the check needs a run-level rerun once the registry serves
   the digest. `pkg/fido2/...` unit tests pass on this head.
- Main merge 1aaa7b58a (rulings 951, 1015): merged cleanly with no
  conflicts; build and `pkg/fido2/...` race tests pass with no fix.

5. Red `Integration [integration image]` on a23c43696: the
   `./test/integration/fido2` step of `make integration-test-fido2` failed
   before the UHID step. Its test build lacked the codec tags (the
   webauthn credential DAO needs `codec_json`), and the ceremony harness
   (`registration_ceremony_test.go`) registered a new email against the
   invite-only default. Fix: codec tags on the fido2 test steps, and the
   harness sets `AllowPublicRegistration`. The UHID step stays required
   (`XKMS_REQUIRE_UHID=1`); it needs `/dev/uhid` in the privileged CI
   devcontainer, which a lane container cannot show.

6. Red `Integration [integration image]` on aedc021bc: with the codec
   tags in, the CLI-exec tests of `./test/integration/fido2` failed. With
   no hidraw device, `RequireDevice` switched the in-process handler to
   the virtual authenticator, but the xkmsctl child processes never saw
   `FIDO2_USE_VIRTUAL=true`, so they enumerated `/sys/class/hidraw` and
   failed. Fix: `RequireDevice` sets the switch with `t.Setenv` whenever
   the suite runs on the virtual device. Test: the suite passes with no
   hidraw in the container; the UHID step still needs `/dev/uhid`.

7. Red Race Detector on d8b5a9b7f: the avr concurrency test hit its 50 ms
   wall-time deadline under -race (always deadline, never a crossed reply).
   Routing is correct (wire mutex, deadline after Lock, a late reply is
   dropped: new test), so the test gets a 10 s per-exchange deadline.

8. Red `Integration [integration image]` on e5373adc6 (exit 2). Local
   repro of `make integration-test-fido2`: the `./test/integration/fido2`
   step passes, then the UHID step fails (make exit 2) with no `/dev/uhid`.
   A container's /dev is copied at start and the host has no uhid node
   until the module loads; post-start.sh's in-container modprobe cannot
   load it. Fix: the step makes the misc node 10:239 when it is missing,
   whose open loads uhid on the host. The lane container has no sudo or
   uhid, so only CI's privileged devcontainer can show the step pass.

## Out of scope

- Other platforms' HID transports, the CTAPHID layer, `sdk/go`.
- Changes to `/dev/uhid` permissions or loading the uhid module on hosts.
