# Plan: #2052 Linux FIDO2 hidraw report-ID byte

## Objective

Prove or disprove the claim that the Linux FIDO2 HID transport
(`pkg/fido2/hid_linux.go`) writes CTAP frames to hidraw without the report-ID
byte, with a test through a real hidraw node, and fix the transport only if
that test fails.

## Slices

1. Test: `pkg/fido2/hid_linux_uhid_test.go`,
   `TestLinuxHIDDevice_UHIDRoundTrip`. A kernel UHID device
   (`pkg/fido2/uhid`) backs a hidraw node that `LinuxHIDDevice` opens.
   Write path: CTAPHID INIT frames with CID 00112233 and FFFFFFFF; the raw
   UHID_OUTPUT payload must be 65 bytes, report ID 0x00 then the frame.
   Read path: a 64-byte input report starting with 0x00 must come back from
   `Read` unchanged. Skips when `/dev/uhid` cannot be opened.
2. Fix (only if slice 1 fails on main's code): frame reports in
   `hid_linux.go` as the kernel expects, with a `fixed` changelog entry.
   No exported name or signature changes.

## Out of scope

- Other platforms' HID transports, the CTAPHID layer, `sdk/go`.
- Changes to `/dev/uhid` permissions or loading the uhid module on hosts.
