# 8268: `make lint-gates` exists and runs in place

## Objective

The CI job `lint-gates` (`.github/workflows/ci.yml`) probes the Makefile for a
`lint-gates` target and, finding none, is green without running a gate
(InfoSec O-5). Add the target, so that the job runs the repository's own
gates beside `make lint`: on a hosted runner in the toolchain image with no
network, and natively under `XKMS_NATIVE_BUILD=1` on the bigdisk pool, which
has no Docker daemon.

## Slices

1. Test: `internal/buildgates/lint_gates_target_test.go`.
   - The Makefile matches the CI probe's expression, and `lint-gates` is
     `.PHONY` with a `## lint-gates:` help line.
   - `make -n lint-gates XKMS_NATIVE_BUILD=1` prints no command that starts
     Docker, calls sudo or installs a package or tool.
   - `lint` does not list `lint-gates`; `lint-gates` lists no `lint`, `vet`,
     `deps-check` or test target other than `test-buildgates`, and no gate
     that `lint` lists.
2. Fix: the `Makefile`.
   - `lint-gates: fmt-check check-insecure-tls check-public-literals
     check-test-helpers proto-check test-buildgates`.
   - `check` lists `lint-gates`; `lint` keeps `actionlint`.
   - Changelog entry.

## Out of scope

- `.github/`, `scripts/`, `go.mod`, `go.sum`: unchanged.
- `actionlint` stays a prerequisite of `lint` and out of `lint-gates`. The
  plan was to move it; `.github/scripts/make-gates-test.sh`, which CI's lint
  job runs and this change may not edit, has the case "make lint fails when
  actionlint reports findings", which fails once `lint` no longer lists it.
  Its recipe also runs `make install-actionlint` when the pin is absent.
  Moving it needs that script changed in the same PR.
- `check-wailsjs` stays out of `lint-gates`: its prerequisite
  `generate-wailsjs` fetches and builds the Wails CLI with `go run ...@version`,
  which needs the module proxy.
- Any gate that fails for a reason of its own is not fixed here.
