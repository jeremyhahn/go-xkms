# Plan: #1725 TPM NV certificate owner auth and ECC EK cert index

## Objective

writeCertToNVRAM defined certificate NV indexes under the owner hierarchy
with an empty password (TPM_RC_BAD_AUTH on an owned TPM), and the ECC EK
certificate went to the RSA index 0x01C00002 instead of 0x01C0000A (TCG EK
Credential Profile 2.2.1.4). ErrNVCertTooLarge is re-exported in sdk/go.

## Slices

1. Port (done, one commit onto main d55b1b73c): NV certificate writes take
   the owner hierarchy auth; certificate reads use the index's own auth;
   the EK cert index is resolved from the configured EK key type.
   Tests: TestEKCertIndex_FollowsEKKeyType,
   TestAnswerCredentialChallenge_ECCEKUsesTheResolvedCertIndex,
   pkg/tpm2/nvram_owner_auth_simulator_test.go,
   ek_cert_roundtrip_simulator_test.go, sdk/go/tpm_errors_test.go.
2. Verify on the GitHub history (lane bp1725): the new tests fail on the
   base (HEAD~1 copies via go test -overlay) and pass on the fix; build,
   vet, race tests and golangci-lint clean on pkg/tpm2 and its dependents,
   sdk/go and xkey. A failing check gets a failing-test commit, then the
   minimal fix.
