# Plan 981: one image tag per bootstrap build target (Tenant Agent ruling 981)

## Objective

Red main: #2183's Integration job failed after two hours in
`make integration-test-bootstrap` with "image go-xkms-bootstrap:<tag> already
exists", because the bootstrap compose services `xkms-server` and
`zone-generator` both build and both export to `go-xkms-bootstrap:<tag>`.
Give each build target its own image name and run the bootstrap suite first in
`make integration-test`, so a build failure costs minutes, not hours.

## Slices (in order)

1. test(buildgates): `internal/buildgates/compose_image_tags_test.go`
   - every compose file under `test/integration/`: no two services with a
     `build:` section share one `image:` value;
   - the Makefile `integration-test:` rule lists `integration-test-bootstrap`
     directly after `clean-test-containers`.
   Both fail at e5fbfd5ca.
2. fix(integration): `go-xkms-bootstrap-server` and `go-xkms-bootstrap-zonegen`
   in `test/integration/bootstrap/docker-compose.yml` (both stay on
   XKMS_IMAGE_REPOS `go-xkms-*`, so check-run-images and teardown find them).
3. fix(make): `integration-test` runs `integration-test-bootstrap` first.
4. Changelog entry `.changelog/unreleased/fixed-981-bootstrap-image-tags.md`.
5. Codex P1 (PR #2300): test(buildgates) `integration-test-bootstrap` lists
   `stage-gomodauth` as a prerequisite (fails before the fix); fix(make) adds
   it, so the gitignored `build/docker/devcontainer/gomodauth.env` exists
   before the bootstrap compose build when no earlier suite staged it.

## Out of scope

- `.github/workflows/`, `docs/SPEC.md`, ci-template scripts.
- Running the Docker integration suites (lanes have no Docker; CI runs them).
