# Plan: SPEC row tpm-policies (#2184)

## Objective

Ship SPEC row `tpm-policies` (docs/SPEC.md): named, TPM-authorized policies
(PolicyAuthorize with NV-counter revocation) shared by keys and sealed objects,
`UpdatePolicy` from a signed CoRIM, `verify` reporting the approved branch on
every transport and in xkey and xkmsctl, the `.tpmpolicy` binding record and
its static `PolicyBindingResolver` exported through `sdk/go`. One row = one
branch `row/2184-tpm-policies` = one PR (CA ruling 573).

## Slices, in order

Each slice folds open PRs with `git merge --no-ff <head>`; the folded PR's own
tests come with it and must pass here.

1. Plan, then PR #2119 (web console Seal view). Tests: `web/app/test/view3_seal.test.ts`.
2. Core row PR #2124 (policy verbs, parity cells, clause map) and fold ref
   `refs/fold/tpm-policies/lane-wip/stpmpb/20261112T082725Z` (transport parity
   tests for update/verify branch and reference values). Tests: the Go unit
   tests of the touched packages and `make integration-test-<feature>`.
3. Web console PRs #2120-#2123, #2129-#2134, #2136, #2137, #2139-#2165, a batch
   per slice, oldest first. Tests: each PR's `web/app/test/*.test.ts`; shared
   files (`App.svelte`, `nav.ts`, `router.svelte.ts`, `docs/web-console/user.md`)
   resolved by keeping both sides' entries.
4. Close the gap between the merged work and the row's acceptance (SDK
   re-export of the static resolver, per-node record keys), each with a test
   that fails before and passes after.
5. Mark the row shipped in docs/SPEC.md; PR body lists the folded work.
