# Row #2314: SPKI pinning consolidated on go-truststrap spkipin

## Objective

go-truststrap `pkg/spkipin` owns SPKI-pinned TLS (docs/00 L1/L2, docs/18
V41). go-xkms drops its two copies, `pkg/crypto/spki` and the SPKI code in
`pkg/trust/fetcher/spki.go`, and every caller moves onto spkipin. Pins keep
their format (lowercase hex SHA-256 of the SPKI DER), so stored pins and
fixtures stay valid.

1. tp2314a (only slice)
   - test commit: `internal/buildgates` TestSPKIPinningOnlyViaSpkipin (no
     `pkg/crypto/spki`, no `pkg/trust/fetcher/spki.go`, no import of the old

3. af2385 (Codex round 1): sdk/go `tls_spki_test.go` covers the SDK

## Local helpers kept (spkipin v0.6.0-alpha lacks them)

- `PinTLSConfig` (pin an existing tls.Config, keep client certs/RootCAs).
- `FetchServerPin` (dial and read a pin): test-local code in the logins
  integration test only.
- `NormalizePin` (colon/whitespace normalization): stays in pkg/trust/fetcher.
- sdk/go requires the tagged root module (v0.64.0-alpha, no replace), so
  its `NewSPKIPinnedTLSConfig`/`VerifySPKIPinnedConnection` build on
  spkipin directly instead of the new bootstrap helpers.

A go-truststrap release adding these lets a later row delete the helpers.

- Editing go-truststrap (docs/00 L8).
