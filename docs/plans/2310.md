# 2310: webauthn registration finish returns internal_error (ruling 742)

## Objective

Main is red: `make integration-test-webauthn-browser` fails every rp-ceremony
spec with `registration finish failed: {"error":"internal_error"}` on an
xkmsd with `auth.enabled: true` and an embedded qrdb node. Begin succeeds.

## Cause (what this slice proved)

- The finish path makes three qrdb calls begin does not: `Users.GetUser`
  (by ID), `Users.UpdateUser` (display name) and the refresh-token KV `Put`
  of the token mint. All ran on the anonymous request context of a public
  route.
- The refresh-token store (`token.QRDBRefreshStore`) was built on the bare
  node client: a real auth-enforcing node refuses its KV write on an
  anonymous context (test below, subtest "anonymous context is refused").
- `handleServiceError` logged unmapped errors only at Debug, so CI never
  showed which call failed.

## Fix (slice 1, this lane)

1. test: `pkg/api/rest/host_token_principal_node_test.go` mints the ceremony
   token pair on an anonymous context against a real auth-enforcing node
   (`barriertest.NewPrincipalNode`); fails on main, passes with the binder.
2. fix: `token.WithCallContext`; `TokenIssuerParams.CallContext`,
   `HostConfig.ServiceContext`; xkmsd passes `Node.ServiceContext`
   (`refreshStoreCallContext`), apimodule passes its `WithServiceContext`
   binder. `handleServiceError` logs the unmapped error at Error.

## Open (not in this slice)

- The user-store calls stay on the request context. Binding them to the
  service principal is refused (`qrdb-service:xkms cannot read on users`):
  its grant has no users read/update, and ruling 742 forbids widening it.
  If CI still fails after this slice, the new Error log names the call.
  When it is `get user` or `qrdb update display name`, a narrow enrolment
  identity is missing and needs an owner decision. (Save rewrites an
  unchanged display name, so it could also be skipped when unchanged.)
- An HTTP-level begin+finish test on a bare principal node is not possible:
  the bare node refuses the anonymous begin too, which xkmsd's begin is not
  in CI. The first test commit tried this and was replaced.
- `make integration-test-webauthn-browser` needs Docker: CI runs it.
