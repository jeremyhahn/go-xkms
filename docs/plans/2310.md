# 2310: webauthn registration finish returns internal_error (ruling 742)

Folded into PR #2296 (ruling 1035: #2296 is the single main-red fix).

## Objective

Main is red: `make integration-test-webauthn-browser` fails every rp-ceremony
spec with `registration finish failed: {"error":"internal_error"}` on an
xkmsd with `auth.enabled: true` and an embedded qrdb node. Begin succeeds.

## Cause

- The finish path makes three qrdb calls begin does not: `Users.GetUser`
  (by ID), `Users.UpdateUser` (display name) and the refresh-token KV `Put`
  of the token mint. On main all ran on the anonymous request context of a
  public route.
- The refresh-token store (`token.QRDBRefreshStore`) was built on the bare
  node client: a real auth-enforcing node refuses its KV write on an
  anonymous context.
- `handleServiceError` logged unmapped errors only at Debug, so CI never
  showed which call failed.

## Fix (as folded into #2296)

1. test: `pkg/api/rest/host_token_principal_node_test.go` mints the ceremony
   token pair on an anonymous context against a real auth-enforcing node
   (`barriertest.NewPrincipalNode`).
2. fix (c72ec0ec8): already on #2296 from go-xkms#2287, so the cherry-pick
   carries no diff: `token.WithCallContext` bound to the node's
   `ServiceContext` through `TokenIssuerParams.ServiceContext`, pkg/server
   and apimodule; `handleServiceError` logs the unmapped error at Error
   (error chain only, no secrets; r1035(3)).
3. test: `pkg/apimodule/module_host_node_users_finish_test.go` runs begin,
   mock attestation and finish over an auth-enforcing node with no identity.

## Outcome of the open user-store question (ruling 1038 (3))

- Finish's user lookup by ID and display-name update already reach the user
  store through the node user service (`NodeUsers` /
  `auth.NewNodeUserClient`, which has `GetUser` and `UpdateUser`), the route
  #2296 gives begin. The new finish test passed on first run, so no fix
  commit and no new node user service method were needed.
- The service principal's grant is unchanged
  (`pkg/embeddednode/serviceprincipal/**` untouched); no public path gets a
  general system identity for user calls.
- The refresh-token write stays on the node `ServiceContext` binder of
  #2287: the node user service has no KV method, and moving the write would
  need a qrdb SDK seam. Left for the reviewer/owner if it counts as too broad.
- `make integration-test-webauthn-browser` needs Docker: CI runs it.
