# Plan 2309: build with -trimpath (DS-9612)

## Cause

Without `-trimpath`, cmd/go hashes the package directory into each action
ID. Every lane clone and every lane-verify directory therefore builds fresh
build-cache keys, and the shared `go-xkms-lane-gocache` volume grows by about
134 GB/h with entries no other directory can reuse.

## Fix

`-trimpath` drops the directory from the action ID, so identical sources in
different clones share cache entries.

## Slices (one lane, in order)

1. Test: `internal/buildgates/go_trimpath_test.go`
   - the Makefile exports GOFLAGS with `-trimpath` before its first rule,
     so every go build/test target (and `env -i` sub-makes, which re-read
     the Makefile) inherits it;
   - the `coverage` target-specific GOFLAGS keeps `$(GOFLAGS)`, so
     `-trimpath` survives its `-p=2`;
   - every `GOFLAGS:` env value in `.github/workflows/ci.yml` contains
     `-trimpath`.
   Committed while it fails.
2. Fix: `export GOFLAGS := $(strip $(filter-out -trimpath,$(GOFLAGS)) -trimpath)`
   near the top of the Makefile (idempotent across recursive makes), and
   `GOFLAGS: -mod=readonly -trimpath` on each ci.yml GOFLAGS line, keeping
   the ruling 869 comments.
3. Changelog entry `.changelog/unreleased/fixed-2309-go-trimpath.md`.
4. Tests that found files through runtime.Caller break under -trimpath (the
   file name becomes the module path): `cmd/xkmsctl` flag-bindings and
   `pkg/api/rest` nav-matrix tests use the package directory instead, and the
   integration `getProjectRoot` helpers (api, api/commands, fido2) walk up
   from the working directory to `go.mod`.
5. Lint keeps untrimmed paths: the `lint` recipe exports GOFLAGS with
   `-trimpath` filtered out, since golangci-lint's cgocall cannot parse cgo
   files under it; builds and tests keep it.
6. Full matrix on build-file PRs (ruling 1041(4)): test
   `TestCIFullTierOnBuildFiles` first; then ci.yml `FULL_TIER_PATTERN`
   (a Makefile, any go.mod/go.sum, ci.yml) sets preflight's `full_paths`,
   which selects integration, nested-module-test, build-raft, race and
   tpm2-simulator without `ci:full`, and CI Gate's FULL_TIER reads it.
   `ci_gate_test.go` expectations follow the new expression.

Codex round 3 slice: `pkg/xkms.Version()` read `VERSION` via runtime.Caller,
which -trimpath makes module-relative ("unknown" in Health); the Makefile
LDFLAGS now set `pkg/xkms.buildVersion` from `$(VERSION)` and the file lookup
is gone (`version_linker_test.go`, buildgates `xkms_version_ldflags_test.go`).

Codex round 2 P2 (Makefile:21): Docker-backed build-server, lib and
build-xkey did not see GOFLAGS; `TestDockerBuildsForwardGOFLAGS` first, then
`BUILDER_MODULE_ENV` carries `-e GOFLAGS` (forwards the exported value).

Codex at 88e43cbef: P1 (in-toolchain-image.sh:224) a lock not taken only
warned and the shared caches mounted unlocked; the shell test's mktemp/mkfifo
failure case with a concurrent trim first, then the stage runs on private
caches. P2 (Makefile:21) compose exec in run_in_devcontainer/run_with_server
dropped GOFLAGS; `TestDevcontainerHelpersForwardGOFLAGS` first, then each exec
forwards `XKMS_CALLER_GOFLAGS`, appended by `$(devcontainer_goflags)`.
