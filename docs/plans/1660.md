# Row #1660 attestation-verifier: plan

Objective: the attestation appraisal verbs reach every client through the
transports and sdk/go, and (ruling 1073 (a)) xkey appraises evidence
through the sdk/go Client (`sdk/go/transport` `AttestationAppraisalService`).

## Slices, in order

1. Done: REST and embedded routes, sdk/go exposure, permission scopes
   (docs/plans/attestation-verifier-rest.md).
2. Done: SPEC text names the transports and the sdk Client (rw2101a).
3. Ruling 1073 (a), BLOCKED (rw2101b): xkey `device attest` and `tpm ek`
   appraise through the sdk Client.
   - Test: a fake `AttestationAppraisalService` records the evidence and
     returns a verdict; the command reports it; a refusal is a non-zero exit
     with the typed error.
   - Fix: call the Client from `runDeviceAttest`
     (xkey/cmd/xkey/cmd/device_attest.go) and from the EK path
     (xkey/cmd/xkey/cmd/tpm_ek.go, `VerifyTPMAttestation`), keeping the
     local chain verification.
   - SPEC: the xkey clause of row attestation-verifier names the remote call.

## Blocker on slice 3

`AttestationAppraisalService` (pkg/api/transport/types_attestation_appraisal.go)
has one appraisal verb, `AppraiseAttestationQuote`. Its request
(`appraisal.AppraiseQuoteRequest`, pkg/attestation/appraisal/verifier.go:175)
needs a TPMS_ATTEST quote, the AK signature, the nonce, PCR values and the
AK certificate. Neither xkey command has that evidence:

- `device attest` gets an Android key-attestation certificate chain
  (KeyDescription extension) from the paired phone.
- `tpm ek` holds an EK certificate only; it makes no quote.

Sending either through `AppraiseAttestationQuote` would be refused by the
server or would give a meaningless verdict. Both ways to unblock are outside
this lane's file map:

- (a) a new appraisal verb for Android key attestation and EK certificate
  chains in pkg/xkms, the transports and sdk/go (pkg/ is "leave unchanged");
  or
- (b) xkey makes a TPM quote (AK + nonce + PCRs) and appraises it, which is
  a new command, not a change to these two.

Asked of the coordinator: choose (a) or (b), or a SPEC text that keeps xkey
in-process for these two commands.

## Out of scope

gRPC/Unix/QUIC/USB/MCP for any new verb until (a) is chosen; go.mod and
go.sum of every module; Makefile; workflows.
