# Row enrolment-imx95-e2e (#2258): enrolment against the i.MX 95 board

Objective: prove device enrolment end to end from a lab node against the
xkmsd that runs on the board (main f422814e9; software and pkcs8 backends;
passphrase barrier; mTLS admin), through to an issued certificate.

Script: `test/e2e/enrolment-imx95.sh` (BOARD=host:port of the API listener;
optional ACME_DIR, ACME_CLIENT, WORK, STRICT=1). It prints `OK step N`,
`STOP step N: <call> -> <answer>`, `NOT REACHED step N` or `BOUNDARY ca`
(SignCSR without credentials refused, as required) and ends at the last
working step with exit 0; it exits 1 when the board is unreachable, when a
call that must be refused succeeds (`FAIL`), or with STRICT=1 at the first
STOP. test/e2e/enrolment_imx95_test.go runs it against a fake board. The client account carries the
board CA saved in step 0 as `trusted_roots`; no CA is a step-2 failure.

Out of scope: any change on the board, init, credentials. Known defects
#2252-#2257 are filed and not fixed here.

## Done in this PR

- Slices 2-3 withdrawn (Codex round 3): no default ACME listener and no
  start-up listener certificate; they need their own SPEC row and change.
  cmd/xkmsd/acme_shipped_config_test.go pins ACME off by default.
- Slice 4 (en2258d, ruling 902): `account add` is local only again; the
  script gives the client the board CA. Slice 6: partial-progress exit.
- Slice 5 (sh2260a, ruling 908): the account client refuses a key store it
  cannot sign through (tpm2, pkcs11, anything but software/file) with
  ErrUnsupportedAccountKeyStore, at `account add` and before the first
  order's client exists, so no software key stands in for a hardware one
  and nothing is sent. No account key is written to disk, so per-name key
  collisions cannot occur. The SPEC row moves to a separate docs PR.
- Codex (lane verify): finalize binds the possession CSR's application
  evidence (273) to the evidence the verified alias carries
  (ErrPossessionEvidenceMismatch).

Board redeploy needed before step 1 can work (owner/CA action):
- Add an `acme:` section to the board's xkmsd configuration (own listener
  reachable from the lab node, `external_url`, `caa_identities`, a TLS pair
  issued from the board CA). The shipped default stays ACME off.
- Build the client with `-tags "codec_cbor codec_json codec_msgpack"`.
