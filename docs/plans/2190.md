# Plan: SPEC row release-signing-key (#2190)

Row: `release-signing-key` (docs/SPEC.md:120), row issue #2190, branch
`row/2190-release-signing-key`, one PR.

## Objective

The tenant release signing key, held in go-xkms, is the default signer of the
tenant's images and CoRIM reference values; a tenant may name another key per
repository (owner ruling 134), resolved by go-xkms's signing-key service and
exposed through `sdk/go` for go-quicbaas.

## Done on this branch

1. CoRIM signer: `refvalue.Sign` and `XKMSService.SignReleaseCoRIM`
   (`pkg/xkms/release_signing.go`), re-exported by `sdk/go`.
2. CoRIM sign on the servers: REST `POST /api/v1/attestation/signing-keys/sign`
   (QUIC serves the same router), gRPC + Unix `SignReleaseCoRIM` RPC, MCP
   `attestation.signing_key.sign`; permission `attestation_signing_keys:sign`.
   Written here, not folded (row/1697 is not on GitHub).
3. Client transports: `pbconv.SigningKeyClient`, every client transport
   (USB refuses), `transport.Client` embeds `ReleaseSigningService`.
4. CLI `xkmsctl key signing-key`: `sign <repository> <corim-file> [--signer]
   [--out]`, `set <repository> <key-id> [--key-backend]`, `get`, `list`,
   `delete`, `resolve`; tests in `cmd/xkmsctl/key_signing_key_test.go`.
5. Image default signer: `XKMSService.RepositorySigner` and
   `image.NewRepositorySigner`, re-exported as `sdk/go`
   `NewRepositoryImageSigner` / `ImageRepositorySigners`.
