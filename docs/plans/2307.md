# Plan 2307: build the integration images once per job

## Objective

`make integration-test` hit its 150-minute bound with every finished suite
green: about 88 minutes went to per-suite image builds and cold compiles. Under
`make integration-test` each image is built once (in `integration-images`) and
every suite reuses it and one warm GOCACHE. A sub-suite run on its own
(`make integration-test-pkcs8` and the rest) keeps building as before.

## Slices, in order

1. Shared suite image: `test/integration/Dockerfile.suite` (golang base, union
   of the suites' apt packages, SoftHSM 2.7.0 stage, `go mod download` with the
   gomodauth secret, `COPY . .`), described by
   `test/integration/compose.suite.yml` and built in `integration-images`.
   Check: `make -n integration-images` shows the build.
2. Suites switch to it: the `test` services of pkcs8, pkcs11, pkcs11/barrier,
   tpm2, awskms, gcpkms, azurekv, vault, quantum, frost, storage and bootstrap
   use `go-xkms-integration-suite:${XKMS_IMAGE_TAG}` and carry their old CMD
   as `command:`; the per-suite Dockerfiles go away. `SUITE_BUILD ?= --build`
   gates every `run --build`, `up --build`, `compose build` and API
   `$(API_COMPOSE) build` line; `integration-test: SUITE_BUILD :=` empties it,
   and `integration-images` builds the challenges, bootstrap and api compose
   images once. Check: `make -n integration-test` shows every build once and
   only in integration-images; `make -n integration-test-pkcs8` still builds;
   each changed compose file parses.
3. Shared GOCACHE: one external volume `go-xkms-gocache-<tag>` mounted at
   `/root/.cache/go-build` in each suite container, created by
   `integration-gocache` (a prerequisite of each suite) and removed by
   clean-run-images and clean-test-containers. Check: `make -n` of a suite and
   of the cleanup targets.

Tests: no Go test changes. Each suite keeps its go test tags, packages,
-timeout, env and service dependencies. CI's Integration job is the end to
end check (lanes have no Docker).

## Out of scope

timeout-minutes values, runs-on, triggers, secrets, actions, schedule,
sharding the job, go.mod/go.sum, the suites that already run in the
devcontainer, and stacks outside `integration-test` (cluster, acmeadmin,
acme-tpm, dns01/http01).
