# Epic #2094 workload identity: PR #2128 review fix

Earlier slices: docs/plans/workload-identity-tenant-create.md (ACME admin
path) and docs/plans/workload-identity-core-create.md (core path).

## Objective

The core create path (`XKMSService.CreateTenantDetail`,
pkg/xkms/servicer_tenant.go) refuses a non-trust-domain or cluster-trust-domain
tenant ID with a bare `fmt.Errorf` wrap of the spiffe sentinel. No tenant
error mapper knows those sentinels, so REST answers 500 and gRPC and MCP
answer Internal for a caller's bad input. The refusal must be a client error
on every transport.

## Slices

1. Test commit: drive a refused ID ("Acme", and the cluster trust domain)
   through `CreateTenantDetail` and map the error through REST
   `handleTenantError` (400), gRPC `mapTenantError` (InvalidArgument) and MCP
   `mapTenantError` (invalid params). The core test also asserts
   `errors.Is(err, xkms.ErrInvalidTenantID)` beside the spiffe cause.
2. Fix commit: sentinel `xkms.ErrInvalidTenantID`; the core path wraps both
   the sentinel and the spiffe cause; the three mappers classify it.
