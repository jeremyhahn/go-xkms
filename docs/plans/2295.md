# Plan: env -i sub-makes keep the caller's Go caches (#2295)

## Objective

No target under `make test` writes `$HOME/go/pkg/mod` when the caller sets
GOMODCACHE. Today `test/scripts/gomodauth.test.sh` runs make under `env -i`
with only PATH and HOME, so the sub-make's Go commands fall back to
`$HOME/go/pkg/mod`; and the Makefile's `PKG_DIRS := $(shell go list ./pkg/...)`
runs (and downloads every module) on every parse.

## Slices, in order

1. test(scripts): `test/scripts/go-caches-env.test.sh` sets HOME to an empty
   temp dir H and GOMODCACHE to an empty temp dir D, then
   - parses the Makefile under the `env -i` form (`make -n help`) and
   - runs `test/scripts/gomodauth.test.sh`,
   and asserts `H/go/pkg/mod` does not exist after each. Wired into
   `make test-scripts`. Fails at e5fbfd5ca.
2. fix(scripts): every `env -i` in test/scripts that runs make or go
   (gomodauth.test.sh, ci-registry.test.sh, the fake docker of
   in-toolchain-image.test.sh) passes GOMODCACHE, GOPATH, GOFLAGS, GOPROXY,
   GOSUMDB and GOCACHE, each only when the caller set it.
3. fix(make): `PKG_DIRS` becomes a deferred `=` so no parse runs `go list`.
4. Changelog entry `.changelog/unreleased/fixed-2295-gomodcache-env-i.md`.

## Out of scope

- lane-run and factory changes (claude-agents).
- .github/workflows/, docs/SPEC.md, go.mod, go.sum.
- `GOMODCACHE_HOST := $(shell go env GOMODCACHE)` stays: `go env` writes
  nothing.
