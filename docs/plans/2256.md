# Plan 2256: deploy docs name one unit, one config, the right CA bundle

Defect row from the i.MX 95 deploy (ruling 814), issue #2256.

## Objective

An operator following deploy/README.md and docs/init-ceremony/user.md ends up
with a running xkmsd: the config they copy exists, the unit they install reads
it, and the CA bundle they distribute is the one `xkmsd run` advertises.

## Cause

- deploy/README.md copied the missing `configs/config.yaml`.
- Two units ran xkmsd: deploy/systemd/xkms.service and configs/xkmsd.service.
- user.md step 3 named a bare `ca-bundle.pem`, not persistCABundle's file.

## Slices

1. test(buildgates): internal/buildgates/docs_paths_test.go
   - TestOneXkmsdSystemdUnit: exactly one `.service` under deploy/ and
     configs/ whose ExecStart runs xkmsd.
   - TestDeployConfigPathsExist: every `/etc/xkms/*.yaml` and
     `configs/*.yaml` the README and the unit name exists in configs/.
   - TestInitCeremonyStep3NamesWrittenBundle: step 3 names
     `<step 2 --data-dir>/<name persistCABundle joins>`.
2. fix(docs): keep configs/xkmsd.service, remove deploy/systemd/xkms.service,
   README copies configs/xkmsd.yaml and uses the `xkmsd` unit name, step 3
   names /var/lib/xkms/ca-bundle.pem. docs(plan): this file.
3. Review round 1: unit dependencies, README systemctl names, OpenRC config
   and /etc/xkms/environment resolve; fix xkey.service ordering, root README,
   OpenRC defaults, EnvironmentFile and HSM daemon ordering in the unit.
4. Review round 2: TestXkmsdUnitWorkingDirectoryWritable (relative
   xkms-data paths need WorkingDirectory=/var/lib/xkms) and
   TestInitCeremonySetsDatastorePathBeforeInit (step 1 sets datastore.path,
   since init keeps a configured one; no change after init).
5. Review round 3 (deploy_runtime_test.go): README installs xkmsd.yaml
   root:xkms 0640 after the user exists; OpenRC sets directory=/var/lib/xkms.
6. Codex round 5 (TestInitCeremonyPinFromServerHost): init-ceremony step 6
   takes the pinned certificate on the server host, from the daemon on
   loopback (127.0.0.1:8443) or the configured tls.cert_file, never over the
   network from another machine, where an interceptor would choose the pin.

## Out of scope

- DeviceAllow and Type=notify of the removed unit (xkmsd sends no sd_notify).
