# Plan: #2325 xkey SRK/FIDO2 follow-ups from the #2305 review (ruling 1047)

## Objective

Close the five review follow-ups on the Platform SRK / FIDO2 tpm2 path, each
with a test that fails before its fix.

## Slices (one session, three commits)

1. `test(xkey)`: failing tests and the compile-time assertion.
   - pkg/tpm2: `var _ platformKeyStoreSetter = (*TPM2)(nil)` with no build
     tag, so a hidden or renamed setter breaks the build.
   - sharedTPM (tpm_simulator tests): a wrapper over a TPM without
     SetPlatformKeyStore calls its fatalf hook instead of skipping.
   - fido2: resolveFIDO2PlatformSRKPIN returns a sealed `*secure.Secret`;
     loadFIDO2PlatformSRKAuth destroys it after use.
   - fido2: a VerifyAuth failure maps to ErrFIDO2TPMPlatformSRKAuthRejected
     and `ExitCode(err)` returns ExitCodePlatformSRKAuthRejected (78,
     EX_CONFIG); an attach failure keeps exit code 1; main's run returns
     ExitCode(err); the xkey unit lists the code in RestartPreventExitStatus.
   - pin_input: a PIN file with group/other mode bits is refused
     (ErrPINInputFilePermissions); the first-line parser returns a copy and
     wipes the whole read buffer.
2. `fix(xkey)`: the fixes for all five.
3. `docs(xkey)`: deploy/systemd/xkey.service RestartPreventExitStatus=78,
   xkey/docs/fido2/user.md exit-code note, one changelog entry.

## Out of scope

- A secure-memory VerifyAuth signature (it takes a string; the string copy
  is the TPM SDK's contract, not changed here).
- Exit codes for other commands.
