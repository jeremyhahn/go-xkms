# Plan: #2275 http-01 logs the key authorization length, not the value

## Objective

`challengeHandlerHTTPx` (pkg/acme/challenges/http-01/http01.go) logged the
whole key authorization on a failed write (slog.Error) and on a served
request (slog.Debug). A 32 MiB key authorization made a 32 MiB log line and
hung the Devcontainer image job. Log `key-authorization-length` instead.

## Slices

1. test(http-01): two tests in http01_test.go swap slog.Default for a
   buffered text handler at Debug level:
   - failed write: log has no key authorization value and has
     `key-authorization-length=<len>`;
   - successful serve (httptest.NewRecorder): same assertions on the
     Debug line.
   Both fail on 9a4449afb.
2. fix(http-01): replace `slog.String("key-authorization", keyAuth)` with
   `slog.Int("key-authorization-length", len(keyAuth))` at both sites, plus
   the changelog entry .changelog/unreleased/fixed-2275-http01-log-length.md.

## Out of scope

- responder.go and its tests, workflows, docs/SPEC.md.
- Hashing the value (the issue allows length or digest; length is enough).
